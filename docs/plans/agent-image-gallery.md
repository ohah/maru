### 1.2 검증 방법 — 실패는 **베이스라인과 비교해서** 센다 ⚠️

IG1-c 에서 **두 번 틀렸고**, 원인이 둘 다 «세는 방법» 이었다.

1. 새 test 블록이 첫 write 전에 훅 커서를 되감지 않아 poll 이 «읽을 것 없음» 으로 지나갔다 —
   블록이 **검증하는 척만** 하고 있었다.
2. 그 상태에서 돌린 뮤테이션이 "잡혔다" 로 보였는데, 실은 뮤테이션 **전에도** 실패하고 있었다.

이 워크트리는 `poll_owner`(`SocketPathTooLong`)와 소스 컨트롤 `.git/worktrees/work` 가 **원래 실패한다**.
그래서 "FAIL 이 있나" 로는 아무것도 알 수 없다. 이렇게 센다.

```sh
zig build test > /tmp/t.log 2>&1
grep -cE '\.\.\.FAIL|^FAIL \(' /tmp/t.log                      # 전체 실패
grep -E '\.\.\.FAIL|^FAIL \(' /tmp/t.log | grep -vc SocketPathTooLong   # 그중 새것 후보
# 베이스라인(변경을 stash 한 상태)에서 같은 수를 재서 **차이**를 본다
```

**`grep "FAIL"` 로 세면 안 된다.** 통과한 테스트 이름에 `CHANNEL_FAILURE`·`OPEN_FAILURE` 같은 대문자
`FAIL` 이 들어 있어 **성공을 실패로 센다** — 실제로 그렇게 1건을 3건으로 잘못 읽고 회귀를 찾아 헤맸다.
러너가 실패를 찍는 모양은 `…FAIL (Error)`(같은 줄) 또는 줄 첫머리 `FAIL (Error)` 둘뿐이다.

뮤테이션도 같다 — "실패했다" 가 아니라 **"실패 수가 늘었다"** 를 본다.

현재 베이스라인(2026-08-29, 이 워크트리): 비-`SocketPathTooLong` **2건** — `소스 컨트롤: 활성 터미널이
다른 저장소로 옮겨 가면…` 하나가 **두 test 바이너리에 각각** 들어 있다(워크트리에서 `.git` 이 디렉터리가
아니라 파일이다). 전체 건수는 바이너리 구성에 따라 흔들리므로 **비-`SocketPathTooLong` 수만** 비교한다.

**`macos-app-host-abi-lib` 는 test 를 컴파일하지 않는다.** 제품 코드를 고칠 때는 그 타깃이 빠른 게이트로
쓸 만하지만, **test 를 더하거나 고쳤으면 그것으로 «컴파일 통과» 를 말할 수 없다** — 이 세션에서 두 번
그렇게 넘어갔고, 두 번째는 `ArrayList.writer(allocator)`(Zig 0.16 unmanaged 에 없는 API)가 통과한 것처럼
보였다. test 를 건드렸으면 게이트는 `zig build test` 하나다.

**그리고 종료 코드를 먼저 본다.** 컴파일이 깨지면 FAIL 줄이 **0** 이라 위 grep 이 «전부 통과» 로 읽힌다 —
실제로 `i64` 캐스트 누락으로 한 번 그렇게 읽을 뻔했다. `zig build test; echo $?` 가 0 이 아니면
`grep -n 'error:'` 로 컴파일 에러부터 확인한다.

## 2. IG0 — `View` 분기 선행 정리

계약 §10이 요구하는 것. `dock_panel.View`에 값을 더하기 **전에** 한다.

### 2.1 실측이 초안을 반박했다 (2026-08-29)

초안은 *"`.agent_sessions` 비교 29곳이 `==`/`!=`라 새 뷰가 조용히 잘못 동작한다"*였다. **실제로 재보니 틀렸다.**

더미 4번째 enum 값을 넣고 컴파일한 뒤 29곳을 전수 분류했다.

| 분류 | 개수 | 새 뷰에 안전한가 |
| --- | --- | --- |
| 가드(`== .agent_sessions` 일 때만 실행 / `!= …` 이면 조기 반환) | **28** | **안전** — 에이전트 전용 코드가 안 돌 뿐이다 |
| 이분 분기 후보 | 1 | **안전**(오탐) — `if (…) captureAnchor() else null`이라 새 뷰는 `null`을 받는다 |

`main.zig`의 도크 셀 조립도 안전하다 — `view != .explorer` 안에서 뷰마다 **각각** 분기하고 모르는 뷰는 뷰 바만 그리고 반환한다. `setDockView`도 이탈/진입 훅이 뷰별로 갈려 있어 새 뷰는 훅이 없을 뿐이다.

**그래서 29곳을 건드리지 않는다.** 기계적 변환은 노이즈만 남기고 잡는 결함이 0이다.

### 2.2 컴파일 게이트가 `zig build`가 아니다 ⚠️

같은 실험에서 더 중요한 것이 나왔다.

| 명령 | 잡은 곳 |
| --- | --- |
| `zig build` | **0** — CLI(`maru`)만 짓고 macOS 앱 호스트를 안 건드린다 |
| `zig build macos-app-host-abi-lib` | **2** |

```
src/platform/macos/app_session/dock.zig   switch (self.dock.view)
src/session/dock_layout.zig               defaultRightPtForView
```

**IG1을 `zig build`로만 확인하면 통과하고 제품이 깨진다.** 완료 조건에 이 타깃을 명시한다.

### 2.3 실제로 고칠 것 — 손-미러 하나

`dockViewSlotIndex`(`dock.zig`)가 `View.slot()`을 **손으로 다시 적어** 두고 있었다. 바로 위 `dockViewForSlot`은 `View.forSlot`에 위임하는데 **역방향만 복사본**이었다 — 그 비대칭이 드리프트의 자리다.

```zig
pub fn dockViewSlotIndex(self: *const AppSession) usize {
    return self.dock.view.slot();   // switch 복사본 제거
}
```

`defaultRightPtForView`(`dock_layout.zig`)는 그대로 둔다. exhaustive인 것이 **정상**이다 — 새 뷰의 기본 폭을 정하도록 컴파일러가 강제하는 게 맞고, IG1이 그 case를 더한다.

**완료 조건**: `zig build macos-app-host-abi-lib`와 `zig build test` 통과. 동작 변화 0(같은 값을 돌려주는 위임이다). 리팩터가 실제로 드리프트를 막는지 확인하려면 더미 4번째 값을 넣어 **에러가 `defaultRightPtForView` 한 곳만** 나오는지 보고 되돌린다.

## 3. IG1 — 뼈대(첫 세로 슬라이스)

### 3.1 인덱스 코어 — `src/session/agent_image_index.zig`

**플랫폼 비의존 순수 모듈**이다. `std`만 쓰고 파일을 열지 않는다 — 바이트 슬라이스를 받아 레코드 위치를 돌려준다. macOS 전용 심볼이 새지 않았는지 [개발 명령](../development-commands.md)의 Linux 타깃 컴파일 확인으로 못박는다(로컬 macOS에서는 통과하고 CI Linux에서만 깨지는 부류를 막는다).

- 바이트 마커 스캔(§3.2). 청크 경계에 걸친 마커를 위해 꼬리를 이월한다.
- 레코드 분류: Claude `image`/`toolUseResult.file.base64`, Codex `input_image`, **Codex `compacted` 제외**(§3.3).
- 산출: `{ line_offset, data_offset, data_len, mime, provider, kind }`.
- 한 줄 16 MiB 상한. 넘으면 그 줄을 버리고 `partial`에 센다.
- 내용 해시 dedup(§4.3).

### 3.2 최소 pane↔파일 매핑 (§P4)

**IG1은 이것 없이 아무것도 못 보여준다.** 범위가 활성 pane이므로 "이 pane이 지금 어느 파일을 쓰는가"를 모르면 읽을 대상이 없다.

그래서 IG1이 **현재 세션 하나**를 잇는 최소 배선을 포함한다 — 기존 훅 drain 경로에서 그 pane의 최신 `transcript_path` 하나를 받아 든다. **목록 누적·env 폴백은 IG6**이다. 이 단계에서는 `/clear` 하면 갤러리가 비는 것을 알려진 한계로 둔다.

### 3.3 도크 뷰 껍데기

- `dock_panel.View`에 `image_gallery` 추가, `forSlot`/`slot`에 3번 슬롯, `dock_view_bar.slot_count` 3→4.
- 아이콘 하나를 SVG→coverage 파이프라인에 추가(PUA 0xF0000~ 등록 집합).
- workspace 영속은 기존 `View.parse` 경로가 그대로 처리한다(`workspace.zig`의 clamp가 이미 있다).
- 격자는 **자리표시자 사각형**만 그린다. 디코드는 IG3이다.

**완료 조건**: `zig build macos-app-host-abi-lib`(§2.2 — `zig build`로는 안 잡힌다) 통과. 도크에서 4번째 아이콘을 눌러 갤러리로 전환되고, 실제 인덱스 개수만큼 자리표시자가 뜨며, 창을 닫았다 열어도 그 뷰가 복원된다. 인덱스 단위 테스트는 합성 fixture로 하되 **구조는 실측을 따른다**(§P2).

## 4. IG2 — 이어읽기(델타 스캔)

`src/platform/macos/agent_image_scan_backend.zig`.

- **디렉터리 열거가 없다.** 대상은 활성 pane의 `transcript_path` 목록이다(계약 §2.1·§4.1). 그 목록을 만드는 지점을 한 함수로 모아 나중에 범위를 넓힐 수 있게 한다.
- 파일별 `(device, inode, size, mtime, last_offset)` 상태. `stat` 하나로 세 갈래(§4.2).
- 델타는 `file.readPositional(io, &.{&buf}, offset)`으로 읽는다.
- `last_offset`은 **마지막 개행까지만** 전진.
- 디코드 직전 `(device, inode)` 재확인, 어긋나면 항목 제거(§4.5).

**완료 조건**: 픽스처 JSONL을 append하면서 refresh를 반복할 때, **읽은 바이트 수 카운터**가 델타 크기와 일치하는지 단언한다. 파일을 잘라내거나 교체하면 0부터 다시 읽는지도 단언한다. `/tmp` 픽스처는 pid 기반 이름을 쓰지 않는다(기존 오염 사례 회피).

## 5. IG3 — 디코드 워커와 텍스처

### 5.1 clamp는 순수 함수로 분리한다 ⚠️

계약 §5.3의 clamp를 **텍스처를 만들지 않는 순수 계산 함수**로 뺀다.

```zig
/// 원본 크기를 GPU 텍스처 상한 이하로 줄이는 서브샘플 계수와 결과 크기를 계산한다.
/// 텍스처를 만들지 않는다 — 상한 초과 디스크립터는 Metal 이 nil 이 아니라 abort 이므로
/// 이 계산이 틀리면 앱이 죽는다. 그래서 계산과 생성을 분리해 계산만 CI 에서 검증한다.
pub fn clampToTextureLimit(w: u32, h: u32, limit: u32) struct { w: u32, h: u32, subsample: u8 }
```

**CI 테스트가 실제로 16385짜리 텍스처를 만들면 CI가 죽는다.** 그러므로 단위 테스트는 이 함수의 경계값(16383/16384/16385, 1440×14771, 극단 비율)만 확인하고 `MTLTextureDescriptor`를 만들지 않는다.

### 5.2 나머지

- ImageIO 브리지는 얇은 Swift/ObjC 한 겹. `CGImageSourceCreateWithData` + `kCGImageSourceSubsampleFactor`.
- 워커에서 디코드하고 픽셀을 owned로 넘긴다. 렌더 tick에서 디코드하지 않는다(20 ms > 16.7 ms 예산).
- 썸네일 160 px, LRU 상한(장당 0.06 MB 기준).
- `GpuImage`를 갤러리 전용 builder로 채운다. `buildGpuImages`(kitty 전용)를 고치지 않는다.

**완료 조건**: CI — clamp 경계값, LRU 축출 순서, 격자 배치 수학(dest rect), 워커가 렌더 경로를 잡지 않음. 수동 — 실제 앱에서 썸네일이 보이는 것 1회.

## 6. IG4 — 크게 보기와 팬·줌

`dest_*`와 `src_u/v` 조작만으로 구현한다. 원본을 다시 디코드하되 **반드시 §5.1의 clamp를 통과시킨다** — 여기가 실제 위험 지점이다(격자는 160 px라 안전하다).

**완료 조건**: CI — 팬·줌 좌표 변환의 경계(축소 한계·확대 한계·경계 밖 팬 방지). 수동 — 큰 이미지 1장을 실제로 열어 확인.

## 7. IG5 — 문맥 복원과 세션 점프

- 계약 §2.2. 이미지 줄 오프셋 기준 ±N줄을 파싱해 두 종류로 나눈다(사용자 텍스트 / 직전 `tool_use`).
- 원본 경로 표시(양쪽 provider가 기록한다). **파일 존재를 확인하지 않는다** — 대개 이미 지워졌고(로컬 붙여넣기는 tmp라 앱 재시작 시 삭제, SSH 수신본은 7일), 이름만 보여준다.
- 세션 점프는 `activateSurfaceById`(ABI v78) 재사용.

**완료 조건**: CI — 두 종류 분류와 창 경계(파일 처음/끝). 수동 — 점프가 실제로 그 pane을 활성화하는 것.

## 8. IG6 — 세션 목록 누적과 폴백

- 훅 `transcript_path` 소비는 **기존 drain 경로에 얹는다.** ndjson은 한 번만 소비되므로(maru가 읽고 지운다) 갤러리가 파일을 직접 읽으면 기존 agent-turn 기능과 경합한다.
- pane별로 관측된 `transcript_path`를 **목록으로 누적**한다(계약 §2.1). `/clear`가 새 파일을 만들어도 이전 것이 남는다.
- 훅이 꺼져 있으면 pane↔파일 매핑을 `agentSessionIdentity` env 폴백이 대신한다.
- IG1의 "현재 세션 하나"를 **목록 누적**으로 승격하는 것이 이 슬라이스의 본체다. 여기서 `/clear` 한계가 닫힌다.

**완료 조건**: 훅 on/off 두 경로가 같은 결과에 도달하는지(늦고 빠름의 차이만). 훅 off 경로는 설정을 바꿔야 하므로 **수동 1회**로 명시한다.

## 9. 계획 검토 기록 — 적대적 4회

| 회차 | 공격 관점 | 발견한 결함 | 반영 |
| --- | --- | --- | --- |
| **P1** | 슬라이스 순서가 죽은 코드를 쌓는다 | 초안은 인덱스·이어읽기·문맥을 **순수 모듈 3 PR**로 먼저 내고 뷰를 나중에 붙였다. 그러면 소비자 없는 코드가 세 번 머지되고, **첫 사용자 가시 결과가 5번째 PR에야** 나온다 | IG1을 **세로 슬라이스**로 재편 — 인덱스 코어 + 도크 뷰 + 자리표시자를 한 PR에. 나머지는 그 위에 얹는다 |
| **P2** | 개인정보 규칙이 테스트를 무력화한다 | 계약 §6이 "fixture는 synthetic만"인데, 파서는 **실제 provider 포맷**을 맞춰야 한다. 내가 상상한 합성 포맷은 통과하는데 제품이 깨질 수 있다 | **구조는 실측, 값은 합성.** 계약 §3.2에 실측한 레코드 모양을 박아 두고 fixture가 그 구조를 따른다. `agent_hook_event.zig`의 "실측 payload 모양을 그대로 읽는다" 테스트가 선례다 |
| **P4** | 슬라이스 의존성이 역전돼 있다 | 범위를 활성 pane으로 좁히자(계약 §2.1) **IG1이 IG6에 의존**하게 됐다 — 어느 파일을 읽을지 모르면 뼈대가 아무것도 못 그린다. 초안대로면 IG1이 머지돼도 빈 화면이다 | **최소 매핑을 IG1로 끌어올린다**(§3.2). IG6은 "라이브 갱신"이 아니라 **목록 누적 + env 폴백**으로 역할을 다시 정의했다 |
| **P3** | 완료 조건이 "동작한다"로 뭉개진다 | GPU 픽셀은 이 환경에서 헤드리스 캡처가 막혀 있어(`zig build macos-app`이 `web:build` 실패) "수동 검증"이 실질적 무검증이 된다. 특히 **clamp 테스트가 실제 텍스처를 만들면 상한 초과에서 CI가 abort로 죽는다** | 슬라이스마다 **CI 몫과 수동 몫을 표로 분리**(§1). clamp를 **텍스처를 만들지 않는 순수 함수**로 빼서 경계값만 CI에서 확인(§5.1) |

P3이 가장 값이 컸다 — 초안대로였다면 "clamp가 잘 도는지" 테스트가 CI를 죽였을 것이다. P4는 범위 결정(활성 pane)이 들어온 뒤 다시 돌려 찾았다. **결정이 바뀌면 슬라이스 의존성을 다시 봐야 한다**는 뜻이다.
