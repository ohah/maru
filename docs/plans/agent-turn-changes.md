# 에이전트 턴 변경분 — 단계 계획

[에이전트 턴 변경분](../agent-turn-changes.md)이 정한 넷(훅 경계·AI 소행 확정·셸 사각지대 표시·스냅샷 영속)을
**무엇을 어느 순서로 만들고 각 단계를 무엇으로 검증하는가**만 정한다. 계약의 단일 출처는 그 문서이고, 그
아래 층(턴 경계의 의미·스냅샷 메커니즘·링 정책·화면 소유)은 [에디터 Surface 도구](../editor-surface-tooling.md)
§6.1과 [도크 소스 컨트롤 뷰](../editor-surface-dock.md) §3.5.4가 소유한다.

## 0. 전제 — 이미 도는 것

[scm-dock 2판 계획](scm-dock.md) **P5(2026-08-18 완료)** 로 아래가 제품에서 돈다. 이 계획은 그 위에만 얹는다.

- `session/turn_snapshot.zig` 링 8개(tree OID·`surface_id`·캡처 시각·`agent_kind`)
- `platform/macos/git_backend.zig` 스냅샷(`read-tree HEAD` → `add -A` → `write-tree`, 임시 index는 저장소 밖)
- `session/git_command.zig` `turn_name_status`(`git diff --name-status <treeA> <treeB>`)
- 에이전트 탭 턴 타임라인 + 파일 클릭 시 네이티브 diff 뷰

> ⚠️ **2026-08-23**: 위 넷 중 **가운데 둘(`git_backend` write-tree 스냅샷·`turn_name_status`)은 이 계획이
> 걷어낸다**(계약 §4.4). 남는 전제는 링 구조와 타임라인 UI다. 링 항목의 «tree OID» 자리는 캡처본 참조로
> 바뀐다.

## 1. 단계

각 단계는 독립 PR이고 문서 갱신을 포함한다. **AT1과 AT5는 서로 독립**이라 순서를 바꿔도 된다.

### AT0 — 링 소유를 «세션 id»로 옮긴다 (선행, 2026-08-24)

계약 [§6.1](../editor-surface-tooling.md)이 링 소유를 저장소에서 **provider 세션 id**로 옮겼다. AT1~AT6보다
**먼저** 와야 한다 — 영속화·`--resume`이 전부 이 키 위에 서고, 지금 구조로는 워크트리를 오갈 때마다 히스토리가
통째로 사라진다.

- **자료구조**: `AppSession.turn_ring`(+`turn_ring_repo`) 한 쌍 → `turn_rings: <세션 id> → Ring`.
  Term은 아무것도 소유하지 않는다(자기 신원을 조회할 뿐 — 신원 캐시는 이미 `term.agent_transcript`에 있다).
- **신원 소스는 훅 payload 하나다.** 모든 훅 이벤트가 `session_id`를 싣고, 특히 턴 경계인 `Stop`이 실어 오므로
  **스냅샷을 찍는 그 순간 신원이 손에 있다**(실측 2026-08-23).
- **관측 모드에서는 스냅샷을 찍지 않는다.** 신원이 없어 어차피 링에 못 넣는데 찍으면 git 프로세스만 공짜로
  띄운다(§6 비용 규율). 그 모드에서 목록이 비는 것은 계약이 정한 정상 동작이다.
- **세션 순번을 걷어낸다** — `Ring.sessionCount`/`sessionOrdinal`/`scm_dock.agentLabel`과 그 테스트. 한 링이
  한 세션이라 번호가 가리킬 대상이 없다(2026-08-23 도입, 같은 날 폐기).
- **저장소 축은 세션 안에 남는다**: 그 세션이 `cd`로 저장소를 옮기면 **그 세션의 링만** 비운다.
- **맵 상한**을 둔다. 세션이 끝나도 링이 남으므로 최근 N개 세션에서 끊는다(링 자체의 8개 상한과 다른 축).
  Term 소유였을 때는 `destroyTerm`이 공짜로 하던 정리라, **이 단계에서 새로 생기는 유일한 비용**이다.
  밀려난 세션은 **신원만 자취로 남긴다**(`RingMap.wasEvicted`) — 기록은 되살릴 수 없지만 화면이
  「밀려났다」와 「원래 없었다」를 갈라 말할 수 있어야 한다(아래 §3).
- **요약 요청의 귀속**(`pumpTurnSummaries`): 결과가 어느 링으로 갈지 요청 시점에 **세션 id를 기억**한다.
  그 세션이 맵에서 밀려났으면 버린다.

검증:

- 순수 층: 맵 상한 축출(오래된 세션부터), 밀려난 신원의 자취가 남고 다시 들어오면 지워지는지, 같은 세션
  id로 두 Term이 붙어도 링이 하나인지, 저장소 전환이 그 세션만 비우는지.
- 배관: 훅 `Stop`의 `session_id`로 링이 선택되는지, 관측 모드에서 **스냅샷 호출 자체가 없는지**
  (`test_turn_snapshot_calls`가 이미 그 계약을 세는 카운터다).
- 화면: 활성 Term의 신원으로 조회하고, 신원이 없으면 `scm_no_turns`가 서는지.
- 회귀: 세션 순번이 화면·모델·테스트에서 완전히 사라졌는지(문자열 `#`가 그 자리에 남지 않는다).

**이 단계는 영속화를 포함하지 않는다.** 맵은 여전히 메모리라 앱을 끄면 사라진다 — 키가 세션 id가 되었으므로
영속화가 **가능해질 뿐**이고, 실제 저장은 캡처 전환(§4.4) 뒤에 온다(참조 없는 tree는 `gc` 대상이라 tree OID를
저장해 봐야 나중에 객체가 없다).

### AT1 — 훅을 턴 경계 트리거로

- **선행: [훅 통합 계획](agent-hooks.md) AH1~AH3.** 전달 채널·설치·모드 판정은 그쪽이 소유한다.
- 이 단계가 하는 일은 이벤트를 **턴 경계로 해석**하는 것뿐이다: `SessionStart`→턴 0 스냅샷,
  `Stop`(단 `stop_hook_active` 무시)→턴 종료 스냅샷. 스냅샷 생성 코드는 건드리지 않는다(§6.1 메커니즘,
  수확 지점은 `app_session/git.zig`의 `takeSnapshotResult`).
- 턴 식별자(`prompt_id`/`turn_id`)를 링 항목에 싣는다 — AT3 귀속이 이 키에 의존한다(계약 §3.1).
- 관측 경로(`isTurnEnd`)는 관측 모드에서 그대로 남는다. 두 경로가 같은 링으로 수렴하되 **한 Term에서
  동시에 돌지는 않는다**(모드가 하나다).
- 검증: 이벤트→경계 해석 단위 테스트, `stop_hook_active` 무시, 턴 식별자 왕복, 모드별로 한 소스만
  링을 채우는지.

### AT2 — 턴 제목

- `Stop`의 `last_assistant_message`를 그 턴 라벨로 싣는다(양 provider 공통, 실측 확인).
- 링 항목에 제목 슬롯을 더한다. **`turn_snapshot.zig`는 순수 층**이라 문자열 소유 규칙을 지킨다(고정 버퍼 +
  길이, 할당 없음).
- 검증: 제목 절단·비ASCII·빈 문자열·개행 포함 케이스 단위 테스트.

### AT3 — 세션 캡처 엔진 (AI 소행)

> **2026-08-23 재정의.** 초판은 «provider 기록에서 경로 집합만 뽑고 내용은 tree 비교에서 온다»였다.
> 계약 §4.4가 그 전제를 바꿨다 — 내용도 **우리가 직접 읽는다**. tree 스냅샷은 이 경로에서 걷어낸다.

- 순수 층: 경로별 **그림자 사본**(before/after) 보관 정책 — 파일당 상한, 초과 시 해시만, 턴 링과의 수명 결합.
- 캡처 트리거는 훅 이벤트다(계약 §4.4 표): `PreToolUse`의 `Read`·`Edit`·`Write`, Codex는 `patchPaths()`.
  **`Read`에서도 뜨는 것이 회수율의 핵심**이라 빼지 않는다.
- after는 도구 구간이 끝날 때 같은 경로를 다시 읽어 만든다.
- 셸 도구 호출 수도 함께 센다(AT4의 고지 줄용).
- **관측 모드 폴백은 그대로 필요하다** — 훅이 없는 세션에는 캡처 트리거가 없다. 세션 파일 파싱
  (Claude `toolUseResult{filePath}` / Codex rollout `patch_apply_end.changes`)은 그 경우의 경로 소스로 남긴다.
  이때는 내용이 없으므로 «변경됨(비교 불가)»까지만 간다.
- 검증: 상한 초과 파일이 해시로 접히는지, 링에서 밀려난 턴의 사본이 해제되는지, 같은 파일을 여러 도구가
  연달아 만질 때 before가 **첫 캡처**로 고정되는지, synthetic fixture로 폴백 경로.

### AT3b — Bash 브래킷 + FSEvents (셸 편집)

- `Pre(Bash)` ~ **그 도구의 `Post(Bash)`** 로 구간을 열고 닫는다. **«다음 `Pre`가 끝»을 쓰지 않는다** —
  병렬 도구 호출에서 깨진다(계약 A21). `PostToolUse` matcher를 `Bash`/`exec`로 좁혀 되돌리는 일이
  이 단계에 포함된다(설치 스크립트·Codex trust 해시 갱신 동반 — 계약 §7).
- 그 구간의 FSEvents 경로만 다시 읽는다. macOS 어댑터는 `MaruAppHost.swift`(FP7)에 이미 있다 —
  `kFSEventStreamCreateFlagFileEvents` + latency 0.0으로 연다.
- 계약 §4.4의 네 규율을 그대로 구현한다: 임시 파일·구간 끝 부재 경로 필터, 종류는 재-stat/hash가 권위,
  구간 끝 ~0.2초 유예, **다른 세션 구간과 겹치면 확정하지 않음**.
- 검증: `sed -i`·리다이렉트·`mv`·`rm` 포착(§2.7 PoC를 fixture로), 임시 파일 제외, 두 세션 구간 겹침 시
  «확정 안 함»으로 떨어지는지, `UserDropped` 시 그 구간을 불완전으로 표시하는지.

### AT4 — 배지·고지 합류

- tree 비교 목록 ∪ AT3 경로 집합 → `✎ AI 편집` / `· 턴 중 변경` / `↩ 순변경 없음` 3분류.
- 셸 명령 수가 1 이상이면 고지 줄을 붙인다. 0이면 줄이 없다.
- git 저장소가 아니면 tree 비교가 없으므로 `✎` 목록만 렌더하고 머리에 불완전함을 명시한다.
- 검증: 3분류 분기 단위 테스트, git 아닌 디렉터리에서 목록이 서는지, 필터 토글이 기본 off인지.

### ~~AT5 — 스냅샷 ref 고정~~ (폐기, 2026-08-23)

**계약 §4.4가 이 단계를 통째로 없앴다.** git tree를 안 만들므로 `git gc`로부터 지킬 객체가 없고,
`refs/maru/turn/<owner-key>/<n>` 이름 공간도, 그 `<owner-key>` 선정 문제(A12)도 함께 사라진다.

영속이 필요하면 대상이 **우리 캡처본**이므로 우리 캐시에 쓰면 된다 — git ref 규율이 아니라 캐시 수명
규율이다. 그 자체는 이 계획 범위 밖으로 남긴다(현행도 링은 메모리·창 로컬이다).

**AT3·AT3b가 곧 이 단계다.** 캡처가 git을 안 쓰므로 git 아닌 워크스페이스에서 **기능이 그대로 선다** —
«보류할 별도 단계»가 아니라 기본 경로가 됐다.

## 2. 이 계획이 함께 고치는 현행 결함

| 결함 | 지금 | 고치는 단계 |
| --- | --- | --- |
| 화면 관측이 전이를 놓치면 두 턴이 하나로 합쳐지고 복구 불가 | `isTurnEnd`가 유일 트리거 | AT1 |
| 턴 목록에 사용자 편집이 섞여도 구분이 없다 | 근거 표기 없음 | AT3·AT4 |
| 앱 재시작 후 링이 빈다 | 메모리·창 로컬 | ~~AT5~~ — 캡처 방식에서는 `gc` 문제가 없다. 영속은 별건으로 남긴다 |
| 같은 폴더의 다른 세션 변경이 내 턴에 섞인다 | tree가 작업트리 전체라 원리적으로 섞인다 | AT3·AT3b |
| **워크트리를 오가면 턴 히스토리가 사라진다** | 링이 저장소당 하나라 저장소가 바뀌면 버린다 | **AT0** |
| 셸 편집 비중이 큰데 그 사실이 화면에 안 보인다 | 고지 없음 | AT4 |

## 3. 알려진 한계 (구현 전에 적어 둔다)

- **셸 편집의 소행은 «대체로» 안다.** provider payload로는 끝내 모르지만(계약 §2.3), AT3b의 FSEvents
  브래킷이 경로를 준다. 남는 구멍은 **다른 세션과 구간이 겹칠 때**이고 그때는 확정하지 않는다(계약 §4.4).
- **Codex `PostToolUse` payload가 미검증**이다. 그래서 AT3의 Codex 경로는 **rollout 파일 파싱을 1차**로 두고
  훅 payload에 의존하지 않는다. 검증이 채워지면 훅 경로를 보조로 얹는다.
- 링 8개 상한은 §6.1의 결정이라 이 계획이 바꾸지 않는다.
- **맵 상한 8은 «동시 세션 8개»가 아니라 «최근 세션 신원 8개»다.** `/clear`가 provider 세션을 새로 시작해
  **새 id를 발급하므로**, 터미널 하나에서만 일해도 여덟 번 지우면 가장 오래된 기록이 밀린다. 밀리는 것은
  AT0의 결정이지만 **조용히 밀리지는 않는다** — 밀려난 신원의 자취를 남겨 에이전트 탭이 「밀려났다」를
  「원래 없었다」로 말하지 않게 한다(2026-08-24 적대적 검증). **기록 자체는 되살릴 수 없다**: 자취는 이유를
  말할 뿐이고, 되살리려면 영속화(계약 §4.4)가 와야 한다.
- 목록 자체의 디스크 영속(재시작 후 타임라인 복원)은 이 계획 밖이다.
- 훅 설치는 사용자 소유 설정 파일을 고친다. `sidebar.agent-hooks`와 같은 계열의 **config 게이트**가
  필요하며, 기본값은 AT1 리뷰에서 사용자와 정한다.
- **AT1은 배관을 새로 만드는 단계다.** 초판 계획은 "기존 매핑 훅에 얹으면 된다"고 봤으나 코드 대조에서 그
  채널이 이 용도에 맞지 않음이 드러났다(계약 A11). 그래서 AT1의 실제 비용은 "훅 항목 추가"가 아니라
  **append 로그 + tail 소비기 + 설치/제거 규율** 셋이다. 이 단계를 작게 잡으면 안 된다.
- ~~`<owner-key>` 선정~~ — AT5 폐기와 함께 사라졌다(계약 §4.4).
- **그림자 사본의 메모리 상한을 먼저 정해야 한다.** 이 저장소 기준 중앙값 12.7 KB·p90 89.6 KB·최대 4.8 MB
  (계약 §2.6). 링 8턴이 그것을 곱하므로 상한과 초과 시 동작(해시만)을 AT3 리뷰에서 못 박는다.
- **FSEvents 지연 ~0.2초**(계약 §2.7)는 구간 끝 유예로 덮되, 그 유예가 다음 도구 시작을 막지 않아야 한다 —
  구간은 겹쳐 열릴 수 있고 그 사실 자체가 «확정 안 함» 판정의 입력이다.
