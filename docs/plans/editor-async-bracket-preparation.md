# 비동기 완료의 괄호 잎 준비

상태: 구현·Debug 집중/제품 회귀 완료. ReleaseFast·실제 입력 대조는 진행 중이다.

## 재현과 범위

접힘 준비 PR #4672는 `2428a125b1e13c21bbd5518ba2f38ebc9734661d`로 머지됐다.
이후에도 비동기 완료 설치는 괄호 목록을 버려 뷰마다 프레임 예산으로 전체 잎을 다시 수집한다.
실제 두 뷰 설치의 재수집 0 회귀는 수정 전 `expected 0, found 1`로 실패했다.
이전 단계 조사에서 문법 준비 뒤 괄호 준비가 프레임 진행에 결합되어 있었지만,
그 이전 자료를 현재 코드의 CPU 비용이나 이번 변경의 개선율로 쓰지 않는다.

기존 `BracketIndex.step` 순회를 취소 확인이 있는 공통 구현으로 나눈다. 기존 프레임은
컴파일 시 항상 false인 중단 판정과 기존 예산을 사용한다. worker는 `prepareCancellable`로
현재 입력의 완료 목록만 준비한다. 다른 parser/세대나 미완료 순회는 새로 시작한다.
취소·OOM의 부분 목록·cursor·text/tree 사본은 정리한다. native tree 복사 실패의 기존
강제 unwrap도 오류 반환으로 바꾼다. C allocator 실패 전수 강제 검증은 하지 않는다.

Job이 잎 값 배열을 소유하고 기존 worker 퇴역 경로에서 해제한다. 완료 이후 불변이며 보유
참조가 있을 때만 빌린다. 뷰 설치는 기존 문서/요청/문법 판 검증 뒤 `replaceMatched`로
독립 배열에 옮기며 기존 용량·수신 판을 재사용한다. 순회 자원·색/짝 판정·탐색 인덱스·
설정·선택은 복사하지 않는다. 각 뷰는 기존 경로로 자기 옵션의 판정과 점프/강조를 만든다.
Markdown의 색 비활성·점프/강조 활성도 유지한다.

## 실패와 비용

선택적 worker 준비/뷰 복사 OOM은 정상 파싱을 유지하고 기존 프레임 수집으로 복귀한다.
취소는 기존 결과 거절 경로로 가며 worker가 회수한다. 본문·Undo·IME·새 알림 정책은 없다.
기존 `reproject_after_frame`과 legacy/선택적 캐시 부재의 다음 프레임 요청은 유지한다.

worker의 전체 수집·일시적 text/tree 사본·완료 잎 배열 비용과 뷰 복사가 추가된다.
worker는 뷰 설정을 받지 않아 색/강조가 꺼져도 준비 비용이 들 수 있다. 뷰의 기존 drop은 유지한다.
취소는 협력적이며 native 함수나 개별 잎의 긴 텍스트 분류를 강제 선점하지 않는다.
worker가 구문 완료를 공개하기 전 준비하므로 구문 표시 자체가 늦어질 수 있다. 최종 색만
보지 않고 첫 표시·구문 준비 표시·다음 게시 전 구문 표시 횟수·RSS를 함께 대조한다.

## 검증

- native `test-editor-bracket-preparation` 6개(import 포함): 언어별 기존 전체 수집,
  독립 복사와 원본 종료, 빈 값, 취소 전/도중, 모든 Zig 할당 실패, 다른 parser와 미완료 순회.
- worker 25개: 실제 준비 장벽 취소/OOM과 정상 파싱 보존·기존 수집 복구·자원 회수.
- view 7개: 두 뷰 재수집 0, 개별 풀, 이전 판 숨김, 복사 OOM 뒤 정상 복구.
- 기존 전체 syntax·색/점프·스냅샷·재배치·공유 편집·연속 프레임·제품 입력 회귀를 대조한다.

기존 BRCONT edit 검사는 worker 설치 직후 목록 ready를 색/탐색 완료로 혼동해 종료했다.
실제 현재 판의 `bracketSource`를 기다리도록 바꾸고 기존 토큰/깊이/dirty/idle 비교는 유지한다.

## 실제 대조

측정 사본의 `--stream --bracket-control`과 `summary_study.py --cache bracket`는 같은 실행 파일에서
worker 괄호 잎 준비만 끄고 켠다. 심볼·접힘 준비와 기본 frame rate는 양쪽에서 유지한다.
한 줄/여러 줄 함수, 단일/공유 뷰, 50/100ms 고정 ASCII 게시를 구분하며 물리 IME와 혼동하지 않는다.
실제 worker 분기와 뷰 재수집, 입력·본문·Metal 표시·설정 해시를 검증한다.

측정 사본의 presented handler가 각 입력을 포함하는 첫 구문 준비 프레임의 실제 표시 시각·
세대·문서 접두부 수를 기록한다. 다음 키 게시 전 표시 횟수와 마지막 게시→구문 표시→최종 색을
분리한다. 사후 메인 타이머 시각을 표시 시각으로 쓰지 않으며 누락을 0ms로 계산하지 않는다.
