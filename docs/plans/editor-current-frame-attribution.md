# 최신 메인의 편집·프레임 비용 재귀속

상태: 선행 PR #4598이 main `4ac6691a2`에 머지됐다. 검토한 head와 실제 main의
전체 트리가 일치하며 실제 main의 native·제품 집중 회귀와 문서/config 48개 빌드 단계가
통과했다. 새 성능/정확성 실행과 다섯 가설 검증을 완료했다. 전체 게이트는 후속이다. 이전 표본을 최신 메인의 수치로 바꾸어 쓰지 않는다.

## 확인할 문제

공유 파싱·변경 범위·sticky 요약·괄호 목록 재사용과 범위 이동이 각각 합류했다.
과거 관측의 남은 시간을 단순히 빼거나 더해서 현재 병목으로 해석할 수 없다.
현재 제품에서 입력·프레임·Provider·저장소의 중첩 구간과 실제 호출 수를 다시 확인한다.

## 측정 경계

기존 `tools/editor-provider-measure/`의 제품 사본과 요약·검증 도구부터 적용한다.
제품의 src·빌드·ABI·설정·저장 포맷에는 계측이나 정책을 추가하지 않는다.
현재 API와 도구의 구간·호출 수 계약이 맞지 않으면 명시적으로 수정·버전 구분한다.
기존 자료의 계약을 느슨하게 바꾸어 새 자료를 통과시키지 않는다.

고정 Zig 3,000·15,000·50,000 선언과 실제 build.zig·Swift 호스트의 다섯 입력을 사용한다.
일반·공유 입력을 각각 성능 3회와 별도 전수 대조 1회로 실행하며 매 실행 20개 입력을
첫 입력부터 모두 보존한다. 기대 모집단은 성능 30프로세스/600입력과 정확성
10프로세스/200입력이다. 측정 전 준비 빌드 실행은 이 모집단과 구분한다.

원본·계측 소스와 입력·도구·실행 파일·로그의 해시, 제품 결과 대조와 실제 C 호출 수를
확인한다. 상위/하위 포함 관계를 보존하며 중첩 구간을 더하지 않는다. 현재의 공유 재사용을
별도 실행 모델로 판정하고 오류·미완료 경로를 일반화하지 않는다.

## 채택과 검증

실측의 다음 대상 선택까지가 범위다. worker 이동·문서 저장소 재설계·새 UX 결정은 하지 않는다.
다섯 독립 가설에서 모집단·시간/호출 수·정확성·근거 파일·CLI를 손상하고 거절을 확인한다.
각 가설 전후 정상 대조와 마지막 원본 대조를 유지한다. 해당 입력의 실패나 도구 불일치를
단순 재시도로 숨기지 않는다. GUI/HID·실제 입력기·RSS·모든 언어의 최악 지연으로 일반화하지 않는다.

## 현재 계측 형식

프레임 schema 1의 `bracketRefresh`는 기존 직접 재수집 호출만 포함한다. 현재 제품의
복사 성공과 재수집 복귀를 함께 재는 구간은 schema 2의 `bracketUpdate`다.
`frame_schema`·구간 이름·`frame_bracket_operation=copy-or-refresh`를 함께 확인한다.
잘못된 버전·혼합 기록·괄호 구간이 상위 시간을 넘는 기록은 거절한다. Provider의
범위 재사용 schema 3과 프레임 schema는 서로 다른 축이다.

처음 준비는 옛 직접 refresh 위치가 없어 명시적으로 멈췄다. 그 부분 사본은
`current-frame-attribution-1`로 보존하며 성능 근거로 쓰지 않는다. 수정한 준비 사본은
`current-frame-attribution-2`다. 실제 메인 source hash와 계측 소스·실행 파일을 확인하고
별도 실행 파일과 도구 사본을 보존했다.

새/옛 프레임 판정 단위 13개와 저장소 판정 10개가 통과했다. 옛 고정 입력/원시 기록
800개는 schema 1로 대조했다. 옛 전체 자료에는 실행 파일이 없어 전체 provenance 검사는
거절됐으며, 그 검사를 통과로 기록하지 않는다. 새 실측에서는 전체 근거를 별도로 검증한다.

두 번째 사본은 성능/대조 실행을 끝냈지만 집계가 Provider의 포함 시간 불일치를 거절했다.
옛 도구가 `editProvider` 공통 호출 대신 helper 내부의 native fallback만 감싸 복사 경로를
빠뜨린 것이 원인이다. 해당 자료는 결과로 채택하지 않는다. 공통 호출을 감싸도록 고치고
schema 2에 `FRAME_CALLS`를 추가해 Provider·괄호 갱신의 뷰별 호출 수를 확인한다.
호출 누락·옛 형식과의 혼합도 거절한다. 수정한 새 사본은 `current-frame-attribution-3`이며
이전 자료의 타이머나 메타데이터를 사후 수정해 채택하지 않는다.

## 채택한 결과

세 번째 사본의 성능 600입력과 정확성 200입력이 전체 자료 검증을 통과했다.
[전체 결과](../../tools/editor-provider-measure/current-results.md)에 p50/p95/최대·첫 입력과
Provider·프레임·저장소 구간 및 호출 수를 기록했다. 다섯 가설의 49개 손상 거절과 정상 대조,
원본 자료 대조를 확인했고, 독립 원시 계산으로 모든 구간 통계와 첫 입력을 대조했다.
생산자·실행 파일은 측정 후 바꾸지 않았다. 추가 프레임 표 분석기와 최종 reader/검증 도구의
사본·해시는 최초 사본과 구분해 보존했다. 실제 파일의 구문 색 세부 작업이 다음 계측 후보이며
현재 수치를 worker 이동이나 저장소 변경의 승인으로 삼지 않는다.

추가 줄 추가·붙여넣기·Undo 회귀 15프로세스·85입력의 구간·호출 수 대조도 통과했다.
주 성능/정확성 모집단과 분리했으며 로그 해시를 별도로 보존한다.
