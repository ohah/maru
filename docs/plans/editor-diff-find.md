# 비교 뷰 좌우 독립 찾기

상태: 구현. 2026-09-30 `zig build test-editor`, 최신 main 리베이스 후 `mise run check`, 제품 Metal 캡처와 실제 한국어 IME 열 전환을 확인했다.

대상은 네이티브 read-only 2열 비교 뷰다. 단일 편집기·터미널·웹의 기존 찾기는 유지한다.
검색 엔진은 기존 literal/PCRE2를 그대로 쓴다. 새 의존성과 공유 문서 구조는 도입하지 않는다.

## 상태와 입력

- 열마다 검색어·대소문자·단어 단위·정규식·오류·현재 매치·전체 매치를 독립적으로 유지한다.
- 두 상자는 함께 열릴 수 있지만 실제 키/확정 입력과 NSTextInputClient 조합은 한 입력 포커스에만 전달한다.
- 반대 열의 결과·현재 강조는 포커스를 옮겨도 남는다. 입력 중인 조합 문자열을 반대 열 검색어로 옮기지 않는다.
- 비교 뷰는 read-only다. 두 상자는 찾기만 제공하고 바꾸기 UI나 디스크 수정 권한을 새로 만들지 않는다.
- 빈 열도 자신의 상자를 열고 0건을 표시한다. 빈 열이라고 터미널 검색으로 폴백하지 않는다.
- ⌘F는 포커스된 열만 열거나 다시 포커스한다. 반대 열을 클릭하고 ⌘F를 누르면 그 열의 상자도 열린다. 사용자 승인한 VS Code 정책이다.

## 결과와 렌더

- 왼쪽 결과·현재 매치·막대 마커는 왼쪽 텍스트에서만 계산하고 왼쪽에만 그린다. 오른쪽도 같다.
- 두 결과 목록과 렌더 scratch 수명을 구분한다. 오른쪽 강조를 만들면서 왼쪽 quad/run이 참조하는 저장소를 덮지 않는다.
- 현재 매치 이동은 포커스된 열에서만 선택을 옮긴다. 두 열의 세로 스크롤이 함께 움직이는 기존 diff 계약은 유지한다.
- 두 상자는 실제 비교 열 rect 안에 배치한다. 그리는 좌표·버튼 hit-test·IME candidate caret는 같은 기하를 쓴다.
- 좁은 열은 기존 find 배치를 축소하되 접두·말줄임/커서·배경 패딩이 들어갈 때만 상자를 보여 준다. 입력 공간을 확보한 뒤 정규식 버튼·카운터를 표시하며 반대 열을 덮지 않는다. 보이지 않는 입력은 포커스를 잡지 않는다.

## 수명

- 비교 재계산으로 정렬된 행 배열이 바뀌면 두 결과를 새 배열로 재계산한다. 낡은 행 번호로 이동하지 않는다.
- Term 전환·닫기·다른 배타 overlay 열기는 두 상자의 결과/입력 owner 수명을 함께 정산한다.
- Esc/Tab은 활성 상자만 닫는다. ⌘G는 활성 열의 보존 검색어로 이동하며, ⌥⌘D는 반대 열의 상자를 열거나 포커스한다.

## 검증

- 서로 다른 검색어와 옵션으로 동시에 검색하고 양쪽 카운터·강조·막대 결과가 독립인지 확인한다.
- 한쪽의 invalid regex/0건이 반대 열의 정상 결과를 지우지 않는지 확인한다.
- 열 전환·다른 Term·닫기·diff 재계산·빈 열·좁은 열에서 상태/좌표/수명이 맞는지 확인한다.
- 조합→열 전환→확정과 클릭/⌘F/⌥⌘D/Enter/Shift+Enter/Esc 입력을 실제 AppKit/IME와 헤드리스로 구분해 검증한다.
- 단일 편집기·터미널·웹 찾기의 기존 회귀 판정은 유지한다.

### 2026-09-30 제품 확인

1200×720 기본 어두운 테마에서 왼쪽 `left` 1/2, 오른쪽 `right` 1/3을 동시에 확인했다.
실제 두벌식 키 입력은 AppKit의 `setMarkedText`에 `ㅎ → 하 → 한`을 전달했다.
왼쪽 조합 중 오른쪽 검색창을 클릭하면 왼쪽 `left한`은 확정되어 남고, 오른쪽만
`right한`의 조합 표시를 가진다. 헤드리스 `DCOL10`은 같은 입력 소유자 계약을 판정한다.
화면 자동화의 클릭 좌표는 실제 창 위치를 읽어 계산한다. 창 외곽의 패널 여백은 입력 hit rect와 다르다.

본문 클릭→⌘F→오른쪽 조합→Enter에서도 양쪽 검색어가 보존되고 조합이 확정되는 것을 확인했다.

### 적대적 검증: tick 전 입력(2026-09-30)

실제 `focusTerm` 직후 tick을 호출하지 않고 키/IME 입력을 보냈다. 수정 전에는 지난 비교
검색어 `aa`가 `aax`로 바뀌었고, 새 Term의 첫 ⌘F는 상자를 여는 대신 지난 상자를 닫았다.
원인은 비교 찾기 소유자의 정산이 tick/렌더에만 있었던 것이다. 키·포인터·앱 액션과
IME marked/직접 commit을 라우팅하기 전에 같은 `syncDiffFind`로 출처를 정산한다.
`DCOL12`~`DCOL14`는 그 간격에서 지난 검색어/조합이 수정되지 않고 새 찾기가 첫 입력에
열리는지 판정한다. 수정 전 두 키 판정의 실패를 확인하고 수정 후 세 판정의 통과를 확인했다.

### 적대적 검증: 좁은 열(2026-09-30)

32px 폭과 32px 높이의 rich 패널은 기존 판정에서 접두·배경 여백이 열 경계를 넘었다.
열 rect만 검사하지 않고 실제 draw·hit·caret 공통 배치를 검사해 부족한 공간에서는 상자를 숨긴다.
중간 폭에서도 접두와 입력 자리를 확보한 뒤 보조 표시를 배치한다. 120~256px의 137개 폭에서
실제 text op의 픽셀 구간이 겹치지 않고 패딩된 배경·caret이 자기 열 안에 있는지 판정한다.
`DCOL15`는 숨긴 상자가 키/IME 포커스를 잡지 않고, 폭을 늘린 뒤 ⌘F로 보존 검색어를
다시 포커스할 수 있는지 판정한다. 일반 찾기의 기존 배치는 유지한다.

IME 트랜잭션 시작도 키/marked 경로에 앞서 같은 정산을 한다. `DCOL16`은 Term 전환 직후
`imeBegin`이 새 Surface를 입력 대상으로 고정하는지 판정한다. 수정 전에는 대상 id가 `null`로 남았다.
