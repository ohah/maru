# 비교 뷰 좌우 독립 찾기

상태: 구현, 헤드리스·제품 Metal 검증 진행. 실제 한국어 IME는 화면 잠금 해제 후 별도 확인한다.

대상은 네이티브 read-only 2열 비교 뷰다. 단일 편집기·터미널·웹의 기존 찾기는 유지한다.
검색 엔진은 기존 literal/PCRE2를 그대로 쓴다. 새 의존성과 공유 문서 구조는 도입하지 않는다.

## 상태와 입력

- 열마다 검색어·대소문자·단어 단위·정규식·오류·현재 매치·전체 매치를 독립적으로 유지한다.
- 두 상자는 함께 열릴 수 있지만 실제 키/확정 입력과 NSTextInputClient 조합은 한 입력 포커스에만 전달한다.
- 반대 열의 결과·현재 강조는 포커스를 옮겨도 남는다. 입력 중인 조합 문자열을 반대 열 검색어로 옮기지 않는다.
- 비교 뷰는 read-only다. 두 상자는 찾기만 제공하고 바꾸기 UI나 디스크 수정 권한을 새로 만들지 않는다.
- 빈 열도 자신의 상자를 열고 0건을 표시한다. 빈 열이라고 터미널 검색으로 폴백하지 않는다.
- ⌘F는 포커스된 열만 열거나 다시 포커스한다. 반대 열을 클릭하고 ⌘F를 누르면 그 열의 상자도 열린다. 사용자 승인한 VS Code 정책이다.

## 결과와 렌더

- 왼쪽 결과·현재 매치·막대 마커는 왼쪽 텍스트에서만 계산하고 왼쪽에만 그린다. 오른쪽도 같다.
- 두 결과 목록과 렌더 scratch 수명을 구분한다. 오른쪽 강조를 만들면서 왼쪽 quad/run이 참조하는 저장소를 덮지 않는다.
- 현재 매치 이동은 포커스된 열에서만 선택을 옮긴다. 두 열의 세로 스크롤이 함께 움직이는 기존 diff 계약은 유지한다.
- 두 상자는 실제 비교 열 rect 안에 배치한다. 그리는 좌표·버튼 hit-test·IME candidate caret는 같은 기하를 쓴다.
- 좁은 열은 기존 find의 축소 규칙을 사용하고 반대 열을 덮지 않는다. 보이지 않는 입력을 열린 모달로 남기지 않는다.

## 수명

- 비교 재계산으로 정렬된 행 배열이 바뀌면 두 결과를 새 배열로 재계산한다. 낡은 행 번호로 이동하지 않는다.
- Term 전환·닫기·다른 배타 overlay 열기는 두 상자의 결과/입력 owner 수명을 함께 정산한다.
- Esc/Tab은 활성 상자만 닫는다. ⌘G는 활성 열의 보존 검색어로 이동하며, ⌥⌘D는 반대 열의 상자를 열거나 포커스한다.

## 검증

- 서로 다른 검색어와 옵션으로 동시에 검색하고 양쪽 카운터·강조·막대 결과가 독립인지 확인한다.
- 한쪽의 invalid regex/0건이 반대 열의 정상 결과를 지우지 않는지 확인한다.
- 열 전환·다른 Term·닫기·diff 재계산·빈 열·좁은 열에서 상태/좌표/수명이 맞는지 확인한다.
- 조합→열 전환→확정과 클릭/⌘F/⌥⌘D/Enter/Shift+Enter/Esc 입력을 실제 AppKit/IME와 헤드리스로 구분해 검증한다.
- 단일 편집기·터미널·웹 찾기의 기존 회귀 판정은 유지한다.
