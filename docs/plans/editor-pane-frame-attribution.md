# pane 프레임 준비 비용 귀속

상태: 17구간의 사본 계측·성능 30회/600입력·정확성 10회/200입력과 다섯 독립 실패 가설 검증 완료. 전체 로컬 문서/경계 게이트 완료. main 합류·PR CI 미완료. 제품 최적화는 별도다.

공유 입력의 완료 트리 재사용 측정 뒤에도 큰 문서의 `appendPaneFrame`에는 기존 세부 구간에
귀속하지 못한 비용이 남았다. 기존 구간은 중첩되어 단순히 중앙값을 빼서 잔여 비중을 만들지 않는다.
제품 소스는 변경하지 않고 외부 사본에서 같은 입력의 함수 호출과 구간을 추가 관측한다.

`tools/editor-pane-measure/run.py`는 기존 Provider 계측의 원문·실행 파일·입력 대조를 유지한다.
pane 프레임 내부의 기하 clamp·미리보기·가로 seek·진단·선택·같은 단어·inlay·caret·충돌 위젯/
밴드·본문 장식과 sticky/들여쓰기/괄호 클라이언트를 기록한다. 같은 함수가 편집 때 실행된 시간은
깊이 guard로 제외한다. `guides`와 `brackets`는 `paneDecorations` 안에 중첩되므로 더하지 않는다.

첫 입력을 보존한 5파일의 일반/공유 성능 실행과 별도 매 입력 독립 대조를 요구한다.
실행 순서·원본/계측 소스·바이너리·원문·호출 수·각 입력의 시간 포함 관계를 검증하고,
누락·중복·순서·음수/중첩 시간·다른 증거·잘못된 oracle의 독립 손상 기록도 거절한다.
함수 경과시간을 물리 HID·화면 present·RSS 증거로 넓히지 않는다.

이 측정은 새로운 캐시·worker·진단/강조 UX·저장소 교체를 승인하지 않는다.
결과로 원인을 좁힌 뒤 기존 계약 안의 개선인지 판단하고, 새 정책이면 사용자와 논의한다.

## 결과와 다음 경계

[전체 결과](../../tools/editor-pane-measure/results.md)에 입력의 실제 바이트·줄바꿈 수와 p50/p95/최댓값을 기록한다. 큰 합성 Zig 공유 입력의 고정 머리줄 p50은 18.785ms, 포함된 심볼 요약의 C 변경 범위 비교는 17.169ms, 조상 조회는 0.037ms였다. 요약의 C 비교를 매 입력 뷰마다 한 번씩 반복했다. 다음 경계는 같은 Provider의 기계산 범위를 심볼 요약에 전달할 수 있는 정확한 세대/편집 조건이다. 이 단계는 원인을 더 좁힐 관측 근거이며 고정 머리줄 정책이나 캐시 구조 변경의 승인이 아니다.

독립 검증은 표본/실행 순서, 시간/호출/중첩, 상위 제품·oracle, 원본/계측/schema/실행 파일, CLI 합성을 공격한다. 각 묶음 앞뒤 원본과 마지막 실제 원본 대조를 유지하며 도구 세 파일의 해시를 결과에 묶는다.

계측 원본 schema 1(14구간·원본 14개)은 보존하고, schema 2(고정 머리줄 하위 구간 추가·원본 15개)를 구분한다. 버전과 구간/파일 집합이 서로 어긋난 자료는 거절한다.

## 후속 제품 변경을 판단할 조건

현재 Provider는 `noteChanged`가 계산한 비소비형 byte 범위를 다음 세대용으로 보관하며 접힘 캐시가 사용한다.
심볼 요약에도 전달하려면 요약이 보관한 이전 트리 판·현재 Provider 판·정확히 반영한 편집 수가 일치해야 한다.
제공 뷰의 범위를 복사하지 않고 대상 Provider 자신의 범위만 검토한다.
늦은 조회·여러 편집·전체 교체·grammar 변경·트리 부재·보관 한도 초과·증명 부재는 기존 비교를 유지한다.
실제 편집 범위는 구조 변경 범위와 별도로 계속 방문해야 한다. 마지막 선언 삭제처럼 구조 범위가 비어도
파일 전체 심볼 존재 여부가 바뀌는 경우를 놓치면 sticky의 접힘 출처 선택이 달라진다.

전체 심볼 대조군과 종류/이름/범위/존재 여부, 알려진 범위와 직접 비교의 대조, 각 실패 할당 뒤 재시도,
일반/공유 뷰·Undo/Redo·다중 편집·IME 콜백·Save As/grammar 갱신을 확인한 뒤 제품에 적용한다.
현재 계측은 실제 C 호출 수를 요구하므로, 비교가 제거된 후보는 실행 모델/형식을 명시해 별도로 검증한다.
기존 자료의 호출 수 계약을 느슨하게 바꾸어 후보를 통과시키지 않는다.

원시 측정이 생긴 폴더는 `--resume --run-only`만 허용한다. 재준비·재빌드와 `--refresh`는 새 폴더에서 수행해, 새 실행 파일의 근거로 옛 시간 기록을 설명하지 않도록 한다. 해당 거절과 유효한 읽기/0회 실행은 실제 준비된 자료로 검증했다.

선행 #4576의 프로젝트 검색 개수 가드 수정 위로 재정리했다. 계측 원본 15파일과 현재 사본의 차이는 `build.zig`의 별도 검색 테스트 개수 가드뿐이다. 제품 Zig 소스는 동일하고, 측정한 EW2 target의 5개 실행 가드는 바뀌지 않았다. 원래 계측 소스·해시·실행 파일은 이전 snapshot 그대로 보존한다.

실제 main `f795a8497` 위로 재정리했으며 직전 head와 제품/계측 소스가 동일하다. 선행 #4576은 필수 CI를 통과해 머지됐다.
