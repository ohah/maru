# pane 색 계산과 그리기 목록 변환 비용 귀속

상태: 확장 9구간 계측·성능 30회/600입력·별도 정확성 10회/200입력과 다섯 독립 실패 가설 검증 완료. 전체 로컬 경계/문서 게이트 통과. PR CI·main 합류는 미완료다.

[변경 범위 재사용](editor-sticky-change-reuse.md) 뒤에도 프레임 준비에는 비용이 남는다.
다른 구간의 중앙값을 빼서 잔여를 계산하지 않고, 같은 입력의 실제 호출을 추가 관측한다.

제품은 변경하지 않는다. 외부 사본의 `appendPaneFrame` 안에서 구문 색·최대 열·미니맵·히트 행 저장과
chrome 토큰 생성·배경 quad·텍스트 draw list 변환을 분리한다. pane 밖의 같은 함수 호출은 제외한다.
첫 7구간 측정 뒤에도 남은 준비 비용을 추정으로 채우지 않고, pane 안의 `advanceSyntax`와
`buildPaneOps`를 추가한 9구간을 별도 사본에서 측정한다. 초기 LOWERING schema 1과 확장 schema 2의
구간 집합은 구분하고, 초기 자료를 덮어쓰거나 두 실행의 분포를 합치지 않는다.
기존 FRAME/PROVIDER/PANE의 구간과 호출 수 계약, 원본/계측 소스·실행 파일·표본·실제 실행 순서,
별도 매 입력 전체 sticky oracle을 유지한다. 새 LOWERING 레코드를 기존 schema 3과 구분해 검증한다.

5파일 × 일반/공유의 성능 3반복과 별도 정확성 1반복을 수행한다. 첫 입력을 남기고 p50/p95/최대를
함께 보고한다. 표본·시간/호출/중첩·상위 제품/정확성·원본/schema/실행 파일·CLI의 다섯 독립 실패
가설을 공격하고 각 묶음 앞뒤 원본과 최종 실제 자료 대조를 유지한다.

새 캐시·worker·제품 출력 형식·UX·영속 포맷·의존성을 추가하지 않는다. 결과는 후속 개선을 선택할
근거이며, 함수 경과시간을 GUI/HID·present·RSS나 다른 입력의 연속 개선량으로 해석하지 않는다.

[전체 분포와 재현 명령](../../tools/editor-lowering-measure/results.md)에 p50/p95/최대·원본/계측 소스·검증 범위를 기록한다. 초기 7구간과 확장 9구간을 독립 검증하며 각각 43개·45개 손상을 거절했다. 다음 경계는 pane 안 구문 준비와 색 계산의 내부 비용/재실행 조건이다.
