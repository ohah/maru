# 프로젝트 바꾸기 — 배치 UI 연결안

상태: 열린 문서 전체 미리보기·worker·actor 적용·파일별 저장 결과를 제품 UI에 연결했다.
2026-10-11 사용자 승인: 열린 문서 전용 범위를 명시해 먼저 연결한다.
편집·저장 계약은 [배치 계획](editor-project-replace-batch.md)의 승인 정책을 유지한다.

## 현재 제품과 연결 범위

검색 결과는 열린 모델과 닫힌 디스크 파일을 함께 표시한다. 현재 단일 파일 미리보기는
둘 다 처리하지만, 배치 worker와 actor는 열린 모델만 처리한다. 닫힌 파일을 건너뛰면서
버튼을 ‘전체 바꾸기’로 표시하면 사용자가 기대한 검색 결과 전체와 실제 적용 범위가 달라진다.
디스크 source를 지금 열린 모델로 임의 치환하는 것도 기존 신원 계약에 어긋난다.

## 승인된 열린 문서 첫 UI

- 기존 검색과 단일 파일 미리보기는 유지한다.
- 별도 진입 동작은 **‘열린 문서 전체 미리보기’**로 표시한다.
- 완료한 검색의 model source 일치 전체를 대상으로 한다. 접힌 행·스크롤 밖 결과도 포함하며
  표시 행 인덱스 대신 문서 신원과 원문 범위를 동결한다.
- 미리보기 머리에 대상 문서 수·일치 수와 **‘열림 N · 닫힘 M 제외’**을 표시한다.
  대상 model이 없으면 시작할 수 없다. 닫힌 파일을 오류 없이 처리한 것으로 집계하지 않는다.
- 미리보기는 파일 머리와 변경 전/후 행을 함께 표시한다. 아직 본문을 변경하지 않는다.
- 사용자는 **‘열린 문서 N개 적용·저장’**을 명시적으로 눌러 기존 승인된 자동 저장을 실행한다.
  기존 미저장 편집도 함께 저장된다는 안내를 미리보기에 표시한다.
- 입력·옵션·root·문서 변경·IME 시작·닫기·취소는 준비 결과를 폐기한다. 결과를 자동 적용하지 않는다.
- 적용 중 명세와 Plan은 UI 상태 밖으로 이동해 자기 편집 알림으로 폐기되지 않게 한다.
- 결과는 파일마다 변경 없음/저장됨/적용됨·저장 실패를 표시한다. 저장 실패도 본문과 Undo를 유지한다.
  과거 배치 결과와 현재 문서 상태를 구분하며 적용 버튼을 다시 활성화하지 않는다.
- 파일별 적용을 위해 탭을 활성화하지 않는다. 기존 단일 미리보기 적용을 반복 호출하지 않는다.

새 파일/일치 checkbox 선택은 이 첫 UI에 추가하지 않는다. 임의 선택 UX는 별도 논의 대상으로 둔다.
‘프로젝트 결과 전체 바꾸기’는 닫힌 파일 준비·로드·물리 신원/별칭·점유 검증을 구현한 뒤 연결한다.

## 대안: 닫힌 파일 지원을 먼저 완성

열린 문서 전용 동작을 제품에 추가하지 않고, 배치 디스크 준비·비활성 로드를 먼저 구현한다.
그 뒤 열린 모델과 디스크를 모두 대상으로 하는 전체 미리보기/적용 UI를 연결한다.
프로젝트 전체 바꾸기라는 사용자 기대에 바로 맞지만, 기존 파일 항목 한도와 준비 실패 시 새 문서 수명,
symlink/hardlink 별칭·선택 밖 점유, 늦게 열린 문서, root/파일 교체를 먼저 해결해야 한다.

## 검증 문턱

1. 실제 완료 검색에서 두 모델을 수집하고 worker가 준비한 원래 Ticket으로 actor에 전달한다.
2. 접힘/스크롤/root 중복과 열린 모델·디스크 혼합 결과에서 명시한 범위·개수·표시가 맞는지 확인한다.
3. 마지막 충돌/OOM/읽기 전용/IME/닫기/취소는 모든 본문·선택·기존 이력을 보존한다.
4. 자기 commit 알림 뒤에도 모든 저장 결과가 남고, 첫 저장 실패 뒤 다음 저장을 시도한다.
5. no-op과 단일 유효 편집, 연결 Undo, focus/공유 뷰, 결과 게시 실패를 실제 경로로 확인한다.
6. 오른쪽 도크·하단 도크·좁은 세로 화면·1×/2× 제품 Metal 캡처를 PR 본문에 첨부한다.
7. 파일 수/총 입력 bytes/피크 RSS/취소 응답/최장 actor tick을 기록한다. 물리 IME와 VoiceOver는
   별도 경계로 보고하며 AppKit-local 입력을 물리 OS 입력 증거로 표현하지 않는다.

## 구현과 수명

`search/batch/ui.zig::start`는 완료 검색의 모든 model group과 범위를 수집한다.
접힘/보이는 행에 의존하지 않는다. root 상대 경로를 절대 논리 경로로 정규화하고,
명세에서 동일 경로/동일 source를 합친다. 닫힌 파일 수도 절대 논리 경로로 중복 제거한다.
`batch.captureSnapshot`은 적용과 같은 문서/경로/점유/읽기 전용/조합 검사를 재사용한다.
모든 snapshot의 수집과 worker 시작이 성공한 뒤에만 UI State를 게시한다.

`poll`은 준비 시작 Ticket의 질의/옵션/root/model 세대를 그대로 확인한다.
실제 root inode 재검사는 시작과 최종 actor 적용에서 수행하며 매 프레임 I/O를 추가하지 않는다.
`apply`는 State를 검색 UI 밖으로 옮긴 뒤 actor를 호출하므로 자기 편집/저장 알림이 Plan과
결과 슬롯을 해제하지 않는다. 완료한 결과는 ‘이전 배치 결과’이며 후속 검색·Undo로 덮어쓰지 않는다.
적용 버튼은 비활성으로 유지하고 Back/새 명시적 검색으로 결과 화면을 닫는다.
파일 행은 owner/slot/generation이 같은 살아 있는 문서만 명시적으로 연다.
닫힌 문서를 경로로 다시 열거나 새 문서에 저장/치환을 재실행하지 않는다.
현재 활성 문서의 결과 행을 재선택해도 IME 입력 트랜잭션/확정 대기 중에는 입력 필드 포커스를 유지한다.
이 재선택이 기존 focus 함수의 same-target 빠른 경로를 지나 확정 대기 중 필드를 blur하던 결함을 재현해 수정했다.

컴포넌트는 불변 라벨·활성 여부·보이는 행만 받는다. 새 동작은 작은 아이콘을 더 늘리지 않고
치환 입력 아래 한 줄 버튼으로 둔다. 좁은 오른쪽 도크에서는 문구를 짧게 표시하고,
파일별 완료 상태도 ‘저장됨/적용됨·저장 실패/변경 없음’으로 표시한다.
180 논리 px 미만에서는 적용 버튼/닫힌 파일 제외 수/저장 성공·실패 수를 축약해 숫자가 잘리지 않게 한다.
접근성 버튼 라벨은 전체 문구를 유지하고 완료 행의 상태를 파일명보다 먼저 표시한다.
중복 scope/result 안내 행을 제거해 아래 결과 영역을 보존한다. 파일 라벨은 동결된 경로들의
공통 부모 아래 상대 경로라 같은 이름의 다른 디렉터리 파일을 구분하고, 후속 root 변경으로 과거 경로를 바꾸지 않는다.
미저장 편집 저장 안내는 실제 변경한 문서에 적용되며 no-op 문서 저장 생략 정책은 유지한다.

## 실행 검증

- `zig build test-editor-project-replace-batch-ui` (Debug/ReleaseFast): 실제 완료 검색→수집→worker→
  UI action→전체 모델 적용/저장, 닫힌 파일 제외·접힌 결과, 자기 알림 뒤 결과 보존/연결 Undo,
  입력·IME·취소·닫기, CAS 실패 뒤 다음 저장, no-op/단일 유효 편집/disk 전용 요청,
  결과 문서 닫기와 단회 적용, 모든 수집/worker 준비 OOM·화면 게시 OOM을 검사한다.
- `zig build test-editor-project-search-dock`: 배치 버튼의 위치·폭·1×/2×·낡은 세대·비활성/숨김 동작을 포함한다.
- `python3 tools/test-editor-replace-batch-ui-adversarial.py`: 접힌 대상 누락·닫힌 파일 안내 유실·
  저장 집계 유실·과거 결과 폐기·결과 행의 IME 보호 제거 결함을 실제 UI controller 판정으로 검출한다.
- `python3 tools/editor-project-search-app/run.py --replace-batch --disk-files 2 --count 20`:
  실제 AppKit 클릭·제품 Metal의 오른쪽/하단 미리보기·적용·저장 결과와 제품 연결 Undo/재저장을 확인한다.
  추가 Undo/Save는 fixture가 제품 API로 호출하며 물리 키 입력 증거로 표현하지 않는다.
  `--batch-open-files 32`로 열린 문서 수를 늘리고 수집/준비/동기 적용 시간, 원문/출력 bytes,
  Plan 행 수와 전체 앱 RSS를 기록한다. `--window-size 640x480 --render-scale 2000`도 같은 binary로 검사한다.

## 남은 범위

닫힌 파일 배치·파일/일치 임의 선택·저장만 재시도하는 전용 UI는 후속이다.
저장 실패 문서는 결과에서 살아 있는 정본을 열어 기존 Save 동작을 사용할 수 있다.
물리 symlink/hardlink 별칭과 다른 창의 공유 뷰는 기존 API의 별도 검증 경계다.
측정치는 fixture/환경의 표본이며 모든 파일시스템의 전원 손실·물리 IME·VoiceOver나 RSS 상한 보장이 아니다.
