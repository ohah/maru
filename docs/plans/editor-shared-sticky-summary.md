# 공유 분할의 고정 머리줄 심볼 요약 복사

상태: 재현·비용 귀속과 로컬 구현·집중/제품 검증·전후 실측·717개 빌드 단계의 전체 게이트를
완료했다. PR #4593의 모든 필수 CI가 통과해 실제 main `6dee25c06`로 머지됐다.
머지 트리는 검증 head와 전체가 동일하고, 실제 main의 native 4개·제품 5개·기존 공유
스냅샷 16개·문서/config 검사 등 54개 빌드 단계도 통과했다. 해당 main의 별도 CI
40202350250는 아직 대기 중이다. 선행 PR #4591의 실제 머지 main `5fbfd92f3`에
리베이스했다. 찾기 IME 합류로 전체 트리는 달라졌지만 이번 커밋의 range-diff와 제품
세 파일은 동일하며, 원래 부모를 기준으로 한 예상 통합 트리와 실제 트리가 일치한다.
통합 상태에서 Debug 집중/전체 게이트 714개 빌드 단계와 ReleaseFast 집중 25개 테스트·
45개 빌드 단계를 다시 통과했다. 최종 문서 동기화 뒤 문서/config 검사도 통과했다.

## 확인한 문제

공유 분할에서 native 트리는 복사하지만 `Provider.copyReady`는 고정 머리줄의
`sticky_summary`를 전달하지 않는다. 새 뷰의 첫 고정 머리줄 조회가 심볼 존재 여부를
확인하려고 전체 트리를 다시 센다. 별도 계측 사본의 대형 Zig 첫 표본에서 준비 구간의
고정 머리줄은 약 131ms, 그 안의 `Summary.hasSymbols`는 약 130.8ms였다.
원본 뷰의 재구축 노드 증가는 0개, 새 뷰는 1,250,001개였다. 이는 해당 표본의 비용
귀속이며 제품 변경 전후 개선량이나 GUI 입력 지연을 뜻하지 않는다.

## 구현 범위

`copyReady`가 같은 언어의 실제 현재 트리를 성공적으로 복제한 자리에서만 요약 복사를
시도한다. 원본 요약의 트리가 존재하고 현재 provider와 세대가 같으며 미반영 편집과
편집 범위가 없을 때만 집계 값을 넘긴다. 수신 요약은 수신의 현재 트리에 대한 별도
native 참조를 소유한다. 원본의 과거 트리 포인터·작업 배열·누적 작업 계수는 공유하지 않는다.

요약 복사의 참조 확보 실패는 이미 성공한 provider 복사를 취소하지 않는다. 수신 요약을
비워 두어 첫 조회에서 기존 전체 집계를 사용한다. 원본 요약이 없거나 오래됐거나 편집 중이면
같은 경로를 사용한다. 심볼 개수가 0인 유효한 요약도 복사하며, 실제 심볼 출처와 sticky
표시 정책은 유지한다. 새 worker·전역 캐시·영속 데이터·UX·의존성을 도입하지 않는다.

## 검증과 완료 조건

- 유효한 요약에서 수신의 재구축 노드가 증가하지 않고 전체 심볼·고정 머리줄 대조가 일치한다.
- 원본 종료 뒤 수신 조회·편집·Undo/Redo가 정상이며 양쪽 native 참조의 수명이 독립적이다.
- 오래된 세대·미반영 편집·트리 부재·요약 부재·심볼 0개·다른 언어와 복사 실패를 확인한다.
- 세대·편집 수·편집 범위·독립 소유·선택적 실패 처리를 겨냥한 서로 다른 결함 5개를 실행에서
  검출하고 정상 전후 대조를 통과한다. 단순 실행 반복을 독립 결함 검증으로 세지 않는다.
- 동일 입력과 계측으로 분할 준비와 첫 입력을 전후 교차 측정하고 모든 정확성 대조를 수행한다.
- 기존 고정 머리줄·공유 스냅샷·변경 범위·접힘·문서/config·경계 게이트 및 필수 CI를 통과한다.

현재 원시 계측은 저장소 밖 `split-ready-attribution-8`에 소스·실행 파일·입력 해시와 함께
보존한다. PR에는 완료한 검증과 전후 측정만 기록하며 미완료 항목을 통과로 표현하지 않는다.

## 실행한 검증과 한계

집중 native 4개와 기존 심볼/변경 범위/native 스냅샷 21개는 Debug·ReleaseFast에서
통과했다. 제품 5개와 기존 계보/공유 스냅샷 16개도 Debug·ReleaseFast에서 통과했다. 제품 대조는
분할·원본 종료·입력·Undo와 랩/스크롤 변경에서 전체 심볼 순회의 머리줄 번호·본문·색상을
비교한다. 새 뷰의 첫 조회에 전체 집계 노드가 늘지 않는 것도 단언한다.

`python3 tools/editor-shared-sticky-summary/review.py --output <새-외부-경로> --deps "$PWD/zig-pkg"`는
세대·편집 수·편집 범위 검사 제거, native 트리 참조 공유, 요약 부재 시 전체 분할 거절을
주입한다. 다섯 결함이 컴파일 후 실행에서 검출됐고 정상 대조 6건이 통과했다.
첫 도구 실행의 소유권 결함은 이중 해제로 종료됐다. 테스트가 그 결함을 발견하면 공유한
요약 참조를 정리 대상에서 빼고 원래 소유권 위반을 보고하도록 고친 뒤 다시 전부 실행했다.

요약의 native 참조 확보 실패 분기는 기존 provider 복사를 보존하지만, C allocator의 실패를
전수 강제한 증거는 없다. 요약 부재에도 provider 복사를 보존하는 대조와 그 정책을 훼손한
결함 검증을 C 할당 실패 재현으로 표현하지 않는다. 첫 제품 실행은 fixture의 화면 기하를
설정하지 않아 그리지 못했으며 기존 판정자와 같은 초기화를 추가한 뒤 대조를 통과했다.
이 테스트 fixture 수정은 제품 동작 변경이 아니다.

[전후 실측과 후속 반복](../../tools/editor-shared-sticky-summary/results.md)을 보존한다.
5개 파일의 성능 30개 실행·600편집과 정확성 10개·200편집에서 준비 시간 감소와 전체
결과 일치를 확인했다. 후속 입력이 조금 늘어난 두 파일은 추가 성능 40개·800편집으로
반복했다. 대형 Zig 준비 중앙값은 첫 대조 202.431→72.449ms, 추가 반복 203.233→70.929ms다.
추가 반복의 대형 Zig 입력 p95 약 0.42ms 증가도 보존하며 모든 입력의 개선을 주장하지 않는다.
원인 귀속·전후 측정·실제 제품 검증은 각자의 사본/실행 파일 해시로 구분한다.
