# 고정 머리줄 심볼 요약의 변경 범위 재사용

상태: 기계와 집중 native 대조 6개(import 포함), 기존 심볼/접힘 및 제품 고정 머리줄·공유 편집 대조 완료. 독립 결함 5개를 실행 중 검출했다. 실제 전후 교차 측정·별도 전수 대조 완료. 전체 편집기·경계·문서/config 게이트 통과. PR CI·main 합류 미완료.

[pane 비용 귀속](editor-pane-frame-attribution.md)의 17구간 측정에서 큰 합성 Zig 공유 입력의
고정 머리줄 p50은 18.785ms이며, 포함된 심볼 요약 C 변경 범위 비교는 17.169ms였다.
Provider의 앞선 비교와 별도로 뷰마다 다시 실행했다. 다른 실행/구간의 중앙값을 더하거나
이 값으로 개선량을 미리 주장하지 않는다.

Provider·parser·Summary 소유와 sticky 출처/표시 정책을 유지한다. 이미 대상 Provider 자신이
계산한 비소비형 범위를 Summary가 보관한 이전 세대와 현재 세대가 정확히 한 단계이고,
같은 편집 하나를 반영했을 때만 동기 조회 동안 빌린다. 제공 뷰의 범위를 복사하지 않는다.
공통 `syntax/changes.zig`는 byte 범위와 세대/편집 조건만 소유한다. 기존 접힘 캐시는 같은 판정을 쓴다.

Summary의 실제 편집 범위는 별도로 계속 방문한다. 구조 범위가 비어도 마지막 선언 삭제/재삽입으로
파일 전체 심볼 존재 여부가 바뀔 수 있기 때문이다. 늦은 조회·여러 편집·전체 재설정·언어 변경·
트리 부재·보관 초과·증명 부재는 기존 자체 비교/전체 집계를 유지한다.
요약 자체가 실패하면 이전 집계·트리·세대·미반영 편집을 유지해 재시도한다.
요약이 성공한 뒤 조상 출력의 할당만 실패하면 완료한 최신 요약을 유지하고 출력은 비운다.

전체 심볼/조상 대조, 차용/자체 비교 계수, 늦은 요약과 다른 트리 이력, 모든 실패 할당 뒤 재시도,
일반/공유·Undo/Redo·다중 편집·IME·Save As/grammar와 기존 접힘 캐시 회귀를 대조한다.
같은 입력/계측 도구로 실제 선행 제품과 비교하고, 실제 C 호출 제거와 성공한 차용을 구분한다.
호출 수 계약을 느슨하게 바꾸어 후보를 통과시키지 않는다.

새 전역 캐시·worker·문서 단위 mutable Provider·UX·영속 포맷·의존성을 도입하지 않는다.
함수 계측을 GUI/HID·present·RSS의 증거로 넓히지 않는다.

`tools/editor-sticky-changes/review.py`는 차용 비활성화·이전 세대 무시·편집 수 무시·실제 편집 범위 누락·할당 전 세대 조기 게시를 각각 주입한다. 다섯 결함 모두 컴파일 이후 실행 단언에서 검출됐고 원본 앞뒤 대조도 통과했다. 제품 네 소스와 build 가드를 검증 사본의 해시로 묶었다. Zig allocator 실패를 전수 순회하며, C allocator의 모든 실패까지 강제한 증거는 아니다.

[전후 실측과 전체 분포](../../tools/editor-sticky-changes/results.md): 큰 합성 Zig 공유 입력의 함수 p50 72.291 → 54.707ms. 모든 표본 p50/p95 감소와 real-build 공유 최대 증가를 함께 보존한다. 별도 400입력·600뷰 sticky 대조를 완료했다. schema 3의 실제 C 호출/차용을 구분하고 schema 1/2도 유지한다.

선행 #4577의 실제 main `547e5e97e` 위로 재정리했다. 변경된 제품/측정 파일 15개의 해시가 재정리 전과 동일하다. 원시 측정은 원래 실행 파일·소스와 묶어 보존하며 새로 빌드한 파일의 시간으로 바꾸지 않는다.
