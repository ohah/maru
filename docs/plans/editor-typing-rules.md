# 언어별 들여쓰기·자동 닫기 규칙 구현 계획

상태: TR1(들여쓰기 단위)·TR2(괄호 Enter·닫는 괄호 내어쓰기)·TR3(언어 규칙 표) 완료, TR4 대기. 계약은 [문서 모델](../native-editor-document-model.md) §3.7(타이핑 보조)·§3.9a(줄 조작과 들여쓰기)가 소유하고, 이 문서는 결정·실측·설계·조각·검증을 소유한다.

## 왜

[잔여 점검](editor-remaining-work.md)의 「언어별 들여쓰기·자동 닫기 문맥 규칙」이다. 지금 편집기는 VS Code 와 이렇게 갈린다(2026-10-13 제품 경로 재현 — 임시 판정자, 커밋하지 않음).

| 입력(`|` = caret) | 지금 | VS Code |
| --- | --- | --- |
| TS `function f() {|}` 에서 Enter | `{` ⏎ `|}` — 가운데 줄이 없다 | `{` ⏎ `→|` ⏎ `}` |
| TS `if (x) {|` 에서 Enter | 들여쓰기 그대로 | 한 단계 더 |
| TS 들여쓴 줄 뒤 Enter 후 `}` | `    }` — 안 내어쓴다 | `}` |
| Python `def f():|` 에서 Enter | 들여쓰기 그대로 | 한 단계 더 |
| C `/**|` 에서 Enter | 빈 줄 | ` * ` 로 잇는다 |
| TS 주석 `// a |` 에서 `'` | `''` 로 닫는다 | 안 닫는다(주석 안) |
| 공백 들여쓰기 파일에서 `Tab` | 탭 문자 | 공백(그 파일의 폭) |

## 결정 (2026-10-13 사용자)

- **들여쓰기 단위는 파일에서 감지한다**(VS Code `editor.detectIndentation` 기본과 같다). 안내선(시각 매핑 §5.1c)이 이미 쓰는 `indent_guides.guessWith` 그 결과를 쓴다 — 탭 파일이면 탭, 공백 파일이면 그 폭. 들여쓴 줄이 없으면 언어 기본(Go·Makefile 은 탭, 그 밖은 공백 `editor.tab-width` 칸).
- **규칙은 Zig 표로 적는다 — 정규식 엔진을 타이핑 경로에 붙이지 않는다.** 근거는 아래 「적대적 검증(결정)」.
- **범위는 넷 다**(사용자 「진행」 — 권장안): 들여쓰기 단위 → 괄호 Enter·닫는 괄호 내어쓰기 → 언어 규칙 표 → 구문 트리 문맥.

## 실측 — VS Code 내장 언어 설정 (2026-10-13, `microsoft/vscode` main 의 `extensions/*/language-configuration.json` 15개)

- 고유 정규식 49개(78번 등장 — 같은 규칙이 언어마다 복사돼 있다: 줄 주석 이어쓰기 한 쌍이 7개 언어, 블록 주석 규칙이 3개 언어).
- 규칙의 종류: 괄호 사이 Enter(들여쓰고 닫는 괄호는 아래로) · 여는 괄호 뒤 한 단계 · 닫는 괄호로 시작하는 줄은 한 단계 덜 · 블록 주석(`/**` → ` * `, ` * ` 줄 이어쓰기, `*/` 뒤 한 칸 빼기) · 줄 주석 가운데 Enter 면 `// ` 이어쓰기 · `case X:`·`default:` 뒤 한 단계 · 중괄호 없는 `if/else/for/while` 다음 한 줄만 · Python 제어문 `:` · Ruby `do`·`def`…`end` · HTML 태그 사이 · YAML `key:`.
- **원래 의미(JS `RegExp`)로 돌린 경계 입력의 오답** — 정규식이 문자열·주석을 모르는 탓이다:

| 입력 뒤 Enter | VS Code 규칙 | 맞나 |
| --- | --- | --- |
| TS `const s = "{";` | 들여쓰기 | ✗ 문자열 안 |
| TS `// {` | 들여쓰기 | ✗ 주석 |
| TS `const re = /\{/;` | 들여쓰기 | ✗ 정규식 리터럴 |
| Python `if x:  # note` | 없음 | ✗ 줄 끝 주석 |
| Python `match x:` | 없음 | ✗ 목록에 없음 |
| Ruby `s = "a do b"` | 들여쓰기 | ✗ 문자열 안 |
| YAML `key: &anchor` | 앵커 처리 안 됨 | ✗ 규칙 원문의 `&amp;`(HTML 이스케이프 오타) |

- 자동 닫기의 문맥 제외(`autoClosingPairs.notIn: string|comment`)는 VS Code 도 정규식이 아니라 토크나이저 스코프로 판정한다 — 우리는 tree-sitter 트리로 같은 판정을 한다(TR4).

## 적대적 검증(결정) — Zig 표 대 PCRE2 로 VS Code 규칙 옮기기

처음 근거 넷을 공격했다.
- 「PCRE2 와 JS 정규식이 다르다」 — **철회.** 49개가 쓰는 구문(전후방 탐색 14·역참조 2·`\b` 10·`\s` 37)은 PCRE2 가 다 지원한다.
- 「VS Code 는 짐작, 우리는 정확」 — **반만 맞다.** 들여쓰기 규칙엔 맞고, 자동 닫기 문맥 제외엔 VS Code 도 스코프를 쓴다.
- 「Zig 표 몇 줄」 — **과소평가.** 규칙 종류가 위 목록만큼이다. C 계열 한 벌을 열 개 문법이 나눠 써도 수백 줄이다.
- **설계 구멍 — 트리 신선도.** 구문 트리는 예산제로 갱신돼 Enter 순간 낡았을 수 있다. 줄 텍스트만 보는 규칙이 1급 경로이고 트리는 보정이다.

그래도 Zig 표를 고른다: VS Code 규칙을 옮기면 위 표의 오답이 그대로 들어온다(그 자리가 전부 「문자열·주석 안인가」 — 우리는 줄 스캐너가 문자열·줄 주석을 건너뛰고 트리가 보정한다). 규칙 원문을 복사하지 않아 라이선스 기록·갱신 추적이 늘지 않는다. **PCRE2 쪽이 이기는 축은 사용자 정의 규칙**인데 그것은 plugin/확장 경계 결정이라 미룬다 — 그때 바뀌어도 소비처(「이 줄 뒤 Enter 는 무엇을 하나」를 묻는 함수 하나)는 그대로다.

## 설계

### 들여쓰기 단위 (TR1)

- `indent_guides.Guess` 가 단위다 — `tabs` 면 탭 하나, 아니면 공백 `spaces` 칸. Term 마다 한 번 추정해 굳힌다(`editor_guides.guess` — 안내선과 **같은 칸**, 처음 묻는 쪽이 채운다). 편집으로는 다시 추정하지 않는다(VS Code 도 열 때 한 번). 탭 폭 설정·문법이 바뀌면 지금처럼 버린다.
- 언어 기본(동률·들여쓴 줄 없음): Go 와 **Makefile**(`Makefile`·`GNUmakefile`·`*.mk` — 레시피가 탭이어야 한다; VS Code `[makefile]` 의 `insertSpaces: false`)은 탭, 그 밖은 공백. 안내선과 같은 함수를 쓴다.
- **`Tab`(한 줄 안)**: 탭 파일이면 탭 문자, 공백 파일이면 **다음 탭 스톱까지** 공백(VS Code `insertSpaces` — 열 5 에서 폭 4 면 공백 3).
- **`Tab`/`⇧Tab`(여러 줄)**: 한 단계를 넣고 뺀다. 내어쓰기는 지금처럼 「있는 만큼만」 — 탭 하나, 없으면 공백을 최대 단위 폭만큼.
- **`Backspace` 가 들여쓰기 안에서 탭 스톱까지 지운다**(VS Code `editor.useTabStops` 기본 켬): caret 앞이 그 줄의 공백·탭뿐이고 선택이 없으면 앞 스톱 열에 처음 닿는 자리까지 지운다(탭이 섞여도 — VS Code `deleteLeft` 와 같다; `␣␣⇥|` 는 세 글자). 같은 들여쓰기의 커서 여럿은 앞 커서의 끝에서 멈춘다. 자동 닫기 쌍 지우기(§3.7)가 먼저다.
- **언어 서버 문서 포맷의 `FormattingOptions`** 도 이 단위를 보낸다(도구 §8.2e ③) — 공백 파일이면 `insertSpaces` 참·그 폭. 전에는 「이 편집기의
  단위는 탭 문자」라며 거짓으로 고정해, 공백 파일을 서버가 탭으로 바꿔 포맷할 수 있었다(계획 공격 1회차가 계약 대조로 찾았다).
- Enter 는 바꾸지 않는다(앞 공백을 글자 그대로 잇는다 — §3.9a).

### 괄호 Enter·닫는 괄호 내어쓰기 (TR2)

- 문법마다 괄호 표 — 괄호 색칠 `bracketRuleFor` 의 `chars` 를 L4 가 그대로 넘긴다(두 벌이면 한쪽만 낡는다). 평문은 괄호를 보지 않는다.
- **짝 없는 괄호를 어디서 보나**: VS Code 는 언어마다 갈린다 — TS·JS 는 `onEnterRules`(`^.*\{[^\}]*$` — 줄에 닫히지 않은 괄호), C·Rust·Go·JSON·CSS 는
  `increaseIndentPattern` 이 같은 모양이고, Python·Ruby·Bash·Markdown·HTML 은 기본 괄호 규칙(여는 괄호가 caret 앞 끝에 있을 때)뿐이다. 그 갈래를
  따른다(`Grammar.bracketEnterAnywhere`). 처음엔 모든 문법을 「어디든」으로 해 Markdown 산문의 `[the docs|]` 에서 Enter 가 링크를 쪼갰다(적대적 3회차).
- 문자열 따옴표는 문법마다(`Grammar.stringQuotes`) — Markdown·HTML·평문은 없음(낱말 속 아포스트로피), Rust 는 큰따옴표만(`'a` 수명).
- Enter: caret 앞 줄 조각을 왼쪽부터 읽어 **짝 없는 여는 괄호**가 남으면 한 단계 더. 그 괄호의 짝이 caret 뒤(공백 다음)에 바로 오면 가운데 줄을 들여쓰고 닫는 괄호는 원래 들여쓰기로 아래 줄에(VS Code `indentOutdent`). 읽을 때 문자열(`"`·`'`·`` ` ``)과 그 언어의 줄 주석 뒤는 건너뛴다.
- 닫는 괄호를 칠 때 caret 앞이 공백뿐이면 그 줄을 **짝 여는 괄호가 있는 줄의 들여쓰기**로 맞춘다(뒤로 읽어 짝을 찾는다 — 상한을 둔다; 못 찾으면 그대로).

### 언어 규칙 표 (TR3)

- **한 함수**: `session/editor/enter_rules.zig` 의 `decide(ctx, before, after, prev) Action` 이 Enter 의 갈래를 정한다(TR2 의 괄호 판정도 여기로 옮겼다). `line_ops.planNewline` 은 그 답을 글자로 옮길 뿐이다. 순서는 VS Code 와 같다 — 언어 규칙(주석 이어쓰기) → 괄호 → 들여쓰기 규칙.
- **답의 모양은 VS Code 와 같다**(`getEnterAction`): 새 줄 = 이어 받은 들여쓰기(`remove` 만큼 뺀다) + `append`. `append` 가 없으면 `indent`·`indent_outdent` 는 한 단계, 있으면 **그것이 한 단계를 대신한다**(VS Code 의 기본 `appendText` 가 탭이고 그것을 단위로 바꾸는 것과 같다 — `/** a| */` 의 가운데 줄은 ` * ` 이지 한 단계 + ` * ` 가 아니다; 처음엔 둘을 더해 갈렸다, 대조 판정자가 드러냈다).
- Python 제어문(`def`·`class`·`if`·`elif`·`else`·`for`·`while`·`try`·`except`·`finally`·`with`·`async`·`match`·`case`)이 `:` 로 끝나면(줄 끝 주석은 떼고) 한 단계.
- 블록 주석(C·C++·Java·JS·TS·TSX·Go·Rust·PHP·Kotlin·CSS): `/**`·`/*` 뒤 Enter 는 ` * `(caret 뒤가 `*/` 면 그것은 아래 줄로), 주석 안 ` * ` 줄 뒤는 `* `(앞 줄이 주석 안일 때만), ` */` 로 끝난 줄 뒤는 정렬 공백 하나 빼기. 줄 주석(`//`) 가운데 Enter 면 `// ` 로 잇는다(줄 끝이면 잇지 않는다).
- `case X:`·`default:` 뒤 한 단계(switch 를 쓰는 C 계열).
- Ruby: 블록을 여는 줄(첫 낱말이 `def`·`class`·`module`·`if`·`unless`·`while`·`until`·`case`·`begin`·`for`·`else`·`elsif`·`when`·`rescue`·`ensure`, `private`/`protected def`, `… do`·`… do |x|`, `= if`/`= case`) 뒤 한 단계. 한 줄로 닫힌 것(`… end`)·후위 조건(`return if x`)·문자열 안 `do` 는 아니다.
- HTML: 마지막 태그가 여는 태그(void·자기 닫힘·닫는 태그·주석이 아니다)이고 그 뒤에 다른 태그가 없으면(`<li>a|` 도) 한 단계, 그 닫는 짝이 caret 뒤에 바로 오면 가운데 줄.
- **낱말 내어쓰기**(타이핑 — `typing_ops.keywordOutdent`): Ruby `end`·`else`·`elsif`·`ensure`·`rescue`(낱말 끝 글자)·`when `(뒤 공백), Python `else:`·`elif …:`·`except …:`·`finally:`(`:`)를 줄 끝에서 다 치면 그 줄을 한 단계 내어쓴다 — 그 줄의 들여쓰기가 위쪽 내용 줄 이상일 때만(이미 맞췄으면 그대로). 같은 줄의 커서 여럿은 앞 것만.
- **VS Code 규칙 대조 판정자**(`INDR1`): `tools/editor/vscode_enter_oracle.mjs` 가 VS Code 내장 언어 설정(핀 커밋 `faa67179693e`)을 원래 의미(JS `RegExp`)로 돌려 말뭉치(77 줄 — TS·JS·Java·C·Go·Rust·Python·Ruby·HTML·CSS·JSON)의 답을 `enter_rules_vscode.zig` 에 찍는다(규칙 원문은 없다 — 답만). 판정자는 우리 `decide` 와 대조하고, 갈리는 것은 **의도한 차이 목록**(열하나 — 문자열·템플릿·줄 주석 안 괄호, C·Go·Rust 의 블록 주석 이어쓰기와 C 의 `case`, Python 줄 끝 주석·`match`, Ruby 문자열 안 `do`·한 줄로 닫힌 블록)에만 있어야 한다. 목록의 차이가 같아지면(VS Code 가 바뀌었거나 목록이 낡았다) 판정자가 실패한다.

### 구문 트리 문맥 (TR4)

- 자동 닫기: caret 이 문자열·주석 안이면 따옴표를 닫지 않는다(VS Code `notIn` 의 자리). 트리가 없거나 낡았으면 지금처럼(문맥 없이).
- 괄호 Enter 의 짝 찾기·닫는 괄호의 짝 찾기를 트리가 신선하면 트리로(문자열·주석·정규식 리터럴 안 괄호를 센다는 줄 스캐너의 한계를 지운다).

| --- | --- | --- |
| TR1 | 들여쓰기 단위 — 감지 결과를 `Tab`·여러 줄 들여쓰기·`Backspace` 탭 스톱·문서 포맷 options 에, Makefile 기본 탭 | 완료 |

## 한계 (받아들일 것)

- 감지는 Term 마다 한 번이다 — 빈 파일에 탭으로 쓰기 시작해도 단위는 열 때의 추정(언어 기본)이다(VS Code 도 같다).
- 줄 스캐너(TR2·TR3)는 여러 줄 문자열·블록 주석 안을 모른다 — TR4 의 트리가 보정한다.
- 사용자 정의 규칙은 없다(plugin 경계 결정 전).
- 낱말 내어쓰기는 낱말을 다 친 순간이라 Ruby `endpoint` 를 치면 `end` 에서 한 번 내어쓴다(VS Code 의 `decreaseIndentPattern` 도 같다).
- 중괄호 없는 `if (x)` 다음 한 줄만 들여쓰기(VS Code TS `indentNextLinePattern`)는 하지 않는다 — 다음 줄을 친 뒤 되돌려야 하는 상태가 생긴다.

## 적대적 검증 (TR1, 5회)

1. 계약 전수 대조 — 「들여쓰기 단위는 탭 문자」를 전제로 적은 자리를 문서·코드에서 훑었다. **언어 서버 문서 포맷이 `insertSpaces: false` 를 고정으로 보내고 있었다**(도구 §8.2e ③이 그 전제를 근거로 들었다) — 공백 파일을 서버가 탭으로 바꿔 포맷할 수 있다. 감지한 단위를 보내게 고쳤다(`INDT5`, 가짜 서버가 받은 options 를 문서에 적는다). 문서 일곱 곳(문서 모델 §3.9a·네이티브 §12·도구 §8.2e·입력 설정·키 입력·시각 매핑 §5.1c·잔여 점검)을 이었다.
2. VS Code 동작 대조 — `nextIndentTabStop`·`prevIndentTabStop`·`deleteLeft` 의 `useTabStops` 갈래와 맞췄다. **들여쓰기 안의 Backspace 가 공백만 넘게 만들었는데 VS Code 는 탭이 섞여도 앞 스톱 열에 닿는 자리까지 지운다**(`␣␣⇥|` 는 세 글자) → 줄 머리부터 열을 세어 그 자리를 찾게 고쳤다.
3. 상호작용 — 완성 목록이 열려 있으면 `Tab` 은 그쪽이 먼저 받는다(그대로), 비교·읽기 전용은 지금 길이 거절한다. **같은 들여쓰기에 커서가 둘이면 두 탭 스톱 범위가 겹쳐 Backspace 가 통째로 거절됐다**(죽은 키) → 뒤 커서는 앞 커서의 끝에서 멈춘다(`INDT3`).
4. 경계·적대 입력 — 아주 긴 들여쓰기에서 Backspace 의 열 계산이 자리마다 처음부터 세면 제곱이 된다 → 한 번만 걷는다. 단위 폭은 1~16 으로 묶인다(설정 범위). 들여쓴 줄이 없는 새 파일은 언어 기본 — **Makefile 은 문법이 없어 공백이 될 뻔했다**(레시피가 깨진다) → 경로로 탭(`IG12`·`INDT4`). 이름 없는 문서를 Makefile 로 저장하면 다시 추정한다(옛 경로가 없던 문서와 비교).
5. 변이 — 21개, 모두 잡혔다. 처음 회차에서 여섯(F1·F2·F4·F6·F17·F18)은 변이가 매개변수를 안 쓰게 만들어 **컴파일 오류로만** 죽었다 — 판정자를 잰 것이 아니라 다시 썼고(쓰는 꼴을 남긴 의미 변이) 모두 판정자 실패로 잡혔다.

## 적대적 검증 (TR2, 5회)

1. 계약 대조 — 문서 모델 §3.9a 의 「`{` 뒤 한 단계는 이 절이 아니다」를 괄호 Enter·닫는 괄호 내어쓰기 계약으로 바꿨다. 괄호 쌍은 괄호 색칠의 규칙을 L4 가 그대로 넘긴다(L2 는 구문 모듈을 못 들여온다 — 두 벌을 만들지 않으려고 호출자가 준다).
2. VS Code 대조 — TS 말뭉치 25 줄을 VS Code 규칙(`increaseIndentPattern`·`onEnterRules`, 원래 의미)과 우리 판정으로 돌려 21 줄이 같고 넷이 갈렸다 — 넷 다 의도한 차이(문자열 `"{"`·템플릿 `` `${x} {` ``·줄 주석 `// {`·줄 끝 주석 `if (a) // {` 안의 괄호). 정규식 리터럴 `/\{/` 은 둘 다 센다(TR4 의 트리가 보정한다).
3. 상호작용 — **처음엔 모든 문법이 「줄 어디든」이라 Markdown 산문 `see [the docs|]` 의 Enter 가 링크를 들여쓰며 쪼갰다** → VS Code 언어 설정의 갈래대로 끝의 여는 괄호만 보는 문법을 갈랐다(`bracketEnterAnywhere`). **같은 공백 줄에 커서가 둘이면 `}` 의 내어쓰기 범위가 겹쳐 입력 전체가 거절됐다** → 앞 커서만 맞춘다(`INDB5`). 자동 닫기 뒤 Enter·평문·문자열 안 괄호는 제품 키 경로로 쟀다(`INDB4`).
4. 경계 — 짝 찾기는 거슬러 64 KiB 까지, 줄 읽기는 한 번(스택 64 — 넘치면 오래된 것을 버린다; 마지막 것이 답), 닫히지 않은 문자열은 줄 끝까지 건너뛴다.
5. 변이 — 20개. 처음 하나(G17 — 앞 커서가 뒤 커서까지의 공백을 먹지 않게 하는 막음)가 살아남아 그 장면(`{|␣|␣}`)을 `INDB2` 에 더해 잡았다. 20개 모두 판정자 실패로 잡혔다.

## 적대적 검증 (TR3, 5회)

1. 계약 대조 — 문서 모델 §3.9a 의 「언어별 규칙은 이 절이 아니다」를 언어 규칙 계약(블록·줄 주석·Python·`case`·Ruby·HTML·낱말 내어쓰기·VS Code 대조)으로 바꿨다. TR2 의 괄호 판정을 `enter_rules` 로 옮겨 Enter 의 갈래가 한 함수다.
2. VS Code 대조 — 대조 판정자를 만들면서 셋을 고쳤다: **`appendText` 의 뜻**(있으면 한 단계를 대신한다 — 더하던 것), **`/** a| */`**(`*/` 를 아래 줄로), **HTML `<li>a|`**(여는 태그 뒤 글자가 있어도 — 줄이 `>` 로 끝나야 한다고 했던 것). 말뭉치 77 줄 중 갈리는 것은 의도한 차이 열하나뿐이다.
3. 상호작용 — **`/** a| */` 의 Enter 가 ` */` 앞 공백을 먹어 `*/` 가 어긋났다**(괄호 Enter 의 공백 먹기를 그대로 탔다) → 덧붙일 글자가 있는 갈래는 안 먹는다(VS Code 도 그대로 둔다). 같은 줄의 커서 둘에서 낱말 내어쓰기가 겹쳐 입력이 거절되지 않게 앞 커서만 맞춘다(`INDR6`). 재변환(IME)·평문·Markdown 은 낱말 내어쓰기를 타지 않는다.
4. 경계 — 낱말 내어쓰기가 위쪽 내용 줄을 찾아 빈 줄을 끝없이 거슬러 갔다 → 4096 줄 상한. Ruby 문자열 걷어내기는 512 바이트 버퍼(넘치면 앞부분만 — 판정이 보수적으로 「아님」 쪽).
5. 변이 — 22개. 처음 회차에서 다섯이 살아남았다 — 줄 끝에서 열린 Ruby 문자열 안 `do`(H11), `cases:` 라벨(H12), void 가 아닌 자기 닫힘 `<Foo />`(H14), `/** a| */` 의 가운데 줄(H17), 같은 줄 커서 둘의 낱말 내어쓰기(H21) — 장면을 더해 잡았다. 들여쓴 블록 주석의 ` */` 뒤 정렬 공백 빼기(H16)는 그 뒤에도 살아남아(0열 주석은 빼고 나면 종전 경로와 같은 답) 들여쓴 주석 장면을 더했다. 넷(H5·H6·H16·H18)은 처음에 매개변수를 안 쓰게 만들어 컴파일 오류로만 죽어 의미 변이로 다시 썼다. 22개 모두 판정자 실패로 잡혔다.
