# 언어별 들여쓰기·자동 닫기 규칙 구현 계획

상태: TR1(들여쓰기 단위)·TR2(괄호 Enter·닫는 괄호 내어쓰기)·TR3(언어 규칙 표)·TR4(구문 트리 문맥) 완료, 네 조각을 합친 최종 검토(2026-10-14) 반영. 계약은 [문서 모델](../native-editor-document-model.md) §3.7(타이핑 보조)·§3.9a(줄 조작과 들여쓰기)가 소유하고, 이 문서는 결정·실측·설계·조각·검증을 소유한다.

## 왜

[잔여 점검](editor-remaining-work.md)의 「언어별 들여쓰기·자동 닫기 문맥 규칙」이다. TR 전의 편집기는 VS Code 와 이렇게 갈렸다(2026-10-13 제품 경로 재현 — 임시 판정자, 커밋하지 않음).

| 입력(`|` = caret) | TR 전 (2026-10-13) | VS Code |
| --- | --- | --- |
| TS `function f() {|}` 에서 Enter | `{` ⏎ `|}` — 가운데 줄이 없다 | `{` ⏎ `→|` ⏎ `}` |
| TS `if (x) {|` 에서 Enter | 들여쓰기 그대로 | 한 단계 더 |
| TS 들여쓴 줄 뒤 Enter 후 `}` | `    }` — 안 내어쓴다 | `}` |
| Python `def f():|` 에서 Enter | 들여쓰기 그대로 | 한 단계 더 |
| C `/**|` 에서 Enter | 빈 줄 | ` * ` 로 잇는다 |
| TS 주석 `// a |` 에서 `'` | `''` 로 닫는다 | 안 닫는다(주석 안) |
| 공백 들여쓰기 파일에서 `Tab` | 탭 문자 | 공백(그 파일의 폭) |

## 결정 (2026-10-13 사용자)

- **들여쓰기 단위는 파일에서 감지한다**(VS Code `editor.detectIndentation` 기본과 같다). 안내선(시각 매핑 §5.1c)이 이미 쓰는 `indent_guides.guessWith` 그 결과를 쓴다 — 탭 파일이면 탭, 공백 파일이면 그 폭. 들여쓴 줄이 없으면 언어 기본(Go·Makefile 은 탭, 그 밖은 공백 `editor.tab-width` 칸).
- **규칙은 Zig 표로 적는다 — 정규식 엔진을 타이핑 경로에 붙이지 않는다.** 근거는 아래 「적대적 검증(결정)」.
- **범위는 넷 다**(사용자 「진행」 — 권장안): 들여쓰기 단위 → 괄호 Enter·닫는 괄호 내어쓰기 → 언어 규칙 표 → 구문 트리 문맥.

## 실측 — VS Code 내장 언어 설정 (2026-10-13, `microsoft/vscode` main 의 `extensions/*/language-configuration.json` 15개)

- 고유 정규식 49개(78번 등장 — 같은 규칙이 언어마다 복사돼 있다: 줄 주석 이어쓰기 한 쌍이 7개 언어, 블록 주석 규칙이 3개 언어).
- 규칙의 종류: 괄호 사이 Enter(들여쓰고 닫는 괄호는 아래로) · 여는 괄호 뒤 한 단계 · 닫는 괄호로 시작하는 줄은 한 단계 덜 · 블록 주석(`/**` → ` * `, ` * ` 줄 이어쓰기, `*/` 뒤 한 칸 빼기) · 줄 주석 가운데 Enter 면 `// ` 이어쓰기 · `case X:`·`default:` 뒤 한 단계 · 중괄호 없는 `if/else/for/while` 다음 한 줄만 · Python 제어문 `:` · Ruby `do`·`def`…`end` · HTML 태그 사이 · YAML `key:`.
- **원래 의미(JS `RegExp`)로 돌린 경계 입력의 오답** — 정규식이 문자열·주석을 모르는 탓이다:

| 입력 뒤 Enter | VS Code 규칙 | 맞나 |
| --- | --- | --- |
| TS `const s = "{";` | 들여쓰기 | ✗ 문자열 안 |
| TS `// {` | 들여쓰기 | ✗ 주석 |
| TS `const re = /\{/;` | 들여쓰기 | ✗ 정규식 리터럴 |
| Python `if x:  # note` | 없음 | ✗ 줄 끝 주석 |
| Python `match x:` | 없음 | ✗ 목록에 없음 |
| Ruby `s = "a do b"` | 들여쓰기 | ✗ 문자열 안 |
| YAML `key: &anchor` | 앵커 처리 안 됨 | ✗ 규칙 원문의 `&amp;`(HTML 이스케이프 오타) |

- 자동 닫기의 문맥 제외(`autoClosingPairs.notIn: string|comment`)는 VS Code 도 정규식이 아니라 토크나이저 스코프로 판정한다 — 우리는 tree-sitter 트리로 같은 판정을 한다(TR4).

## 적대적 검증(결정) — Zig 표 대 PCRE2 로 VS Code 규칙 옮기기

처음 근거 넷을 공격했다.
- 「PCRE2 와 JS 정규식이 다르다」 — **철회.** 49개가 쓰는 구문(전후방 탐색 14·역참조 2·`\b` 10·`\s` 37)은 PCRE2 가 다 지원한다.
- 「VS Code 는 짐작, 우리는 정확」 — **반만 맞다.** 들여쓰기 규칙엔 맞고, 자동 닫기 문맥 제외엔 VS Code 도 스코프를 쓴다.
- 「Zig 표 몇 줄」 — **과소평가.** 규칙 종류가 위 목록만큼이다. C 계열 한 벌을 열 개 문법이 나눠 써도 수백 줄이다.
- **설계 구멍 — 트리 신선도.** 구문 트리는 예산제로 갱신돼 Enter 순간 낡았을 수 있다. 줄 텍스트만 보는 규칙이 1급 경로이고 트리는 보정이다.

그래도 Zig 표를 고른다: VS Code 규칙을 옮기면 위 표의 오답이 그대로 들어온다(그 자리가 전부 「문자열·주석 안인가」 — 우리는 줄 스캐너가 문자열·줄 주석을 건너뛰고 트리가 보정한다). 규칙 원문을 복사하지 않아 라이선스 기록·갱신 추적이 늘지 않는다. **PCRE2 쪽이 이기는 축은 사용자 정의 규칙**인데 그것은 plugin/확장 경계 결정이라 미룬다 — 그때 바뀌어도 소비처(「이 줄 뒤 Enter 는 무엇을 하나」를 묻는 함수 하나)는 그대로다.

## 설계

### 들여쓰기 단위 (TR1)

- `indent_guides.Guess` 가 단위다 — `tabs` 면 탭 하나, 아니면 공백 `spaces` 칸. Term 마다 한 번 추정해 굳힌다(`editor_guides.guess` — 안내선과 **같은 칸**, 처음 묻는 쪽이 채운다). 편집으로는 다시 추정하지 않는다(VS Code 도 열 때 한 번). 탭 폭 설정이 바뀌면 버리고, 문법이 바뀌면 **언어 기본이 달라질 때만** 버린다(VS Code `_onDidChangeLanguage` — 두 언어의 옵션이 같으면 모델을 건드리지 않는다). **같은 문서의 공유 분할 뷰는 원래 뷰의 추정을 잇는다** — 새 뷰가 지금 내용으로 다시 추정하면 한 문서의 두 뷰가 다른 단위를 쓴다(최종 검토 — VS Code 는 그 옵션을 문서 모델에 둔다).
- 언어 기본(동률·들여쓴 줄 없음): Go 와 **Makefile**(`Makefile`·`GNUmakefile`·`*.mk` — 레시피가 탭이어야 한다; VS Code `[makefile]` 의 `insertSpaces: false`)은 탭, 그 밖은 공백. 안내선과 같은 함수를 쓴다.
- **`Tab`(한 줄 안)**: 탭 파일이면 탭 문자, 공백 파일이면 **다음 탭 스톱까지** 공백(VS Code `insertSpaces` — 열 5 에서 폭 4 면 공백 3).
- **`Tab`/`⇧Tab`(여러 줄)**: 한 단계를 넣고 뺀다. 내어쓰기는 지금처럼 「있는 만큼만」 — 탭 하나, 없으면 공백을 최대 단위 폭만큼.
- **`Backspace` 가 들여쓰기 안에서 탭 스톱까지 지운다**(VS Code `editor.useTabStops` 기본 켬): caret 앞이 그 줄의 공백·탭뿐이고 선택이 없으면 앞 스톱 열에 처음 닿는 자리까지 지운다(탭이 섞여도 — VS Code `deleteLeft` 와 같다; `␣␣⇥|` 는 세 글자). 같은 들여쓰기의 커서 여럿은 앞 커서의 끝에서 멈춘다. 자동 닫기 쌍 지우기(§3.7)가 먼저다.
- **언어 서버 문서 포맷의 `FormattingOptions`** 도 이 단위를 보낸다(도구 §8.2e ③) — 공백 파일이면 `insertSpaces` 참·그 폭. 전에는 「이 편집기의
  단위는 탭 문자」라며 거짓으로 고정해, 공백 파일을 서버가 탭으로 바꿔 포맷할 수 있었다(계획 공격 1회차가 계약 대조로 찾았다).
- TR1 은 Enter 를 바꾸지 않았다(앞 공백을 글자 그대로 잇는다 — §3.9a). TR2·TR3 이 더하는 한 단계가 이 단위다.

### 괄호 Enter·닫는 괄호 내어쓰기 (TR2)

- 문법마다 괄호 표 — 괄호 색칠 `bracketRuleFor` 의 `chars` 를 L4 가 그대로 넘긴다(두 벌이면 한쪽만 낡는다). 평문은 괄호를 보지 않는다.
- **짝 없는 괄호를 어디서 보나**: VS Code 는 언어마다 갈린다 — TS·JS 는 `onEnterRules`(`^.*\{[^\}]*$` — 줄에 닫히지 않은 괄호), C·Rust·Go·JSON·CSS 는
  `increaseIndentPattern` 이 같은 모양이고, Python·Ruby·Bash·Markdown·HTML 은 기본 괄호 규칙(여는 괄호가 caret 앞 끝에 있을 때)뿐이다. 그 갈래를
  따른다(`Grammar.bracketEnterAnywhere`) — 번들 문법 중 VS Code 내장 설정이 없는 Zig·Kotlin 과 같은 C 계열(C++·Java·PHP·TSX)도 「어디든」이다. 처음엔
  모든 문법을 「어디든」으로 해 Markdown 산문의 `[the docs|]` 에서 Enter 가 링크를 쪼갰다(적대적 3회차).
- 문자열 따옴표는 문법마다(`Grammar.stringQuotes`) — Markdown·HTML·평문은 없음(낱말 속 아포스트로피), Rust 는 큰따옴표만(`'a` 수명). 줄 주석 표식도
  문법에서 정한다(`Grammar.lineComment` — 경로로 정하면 이름 없는 문서에 문법을 골라 줘도 없다). 따옴표·줄 주석·「어디든」을 문맥으로 묶는 것은
  `enter_rules.contextFor` 한 자리다 — 호스트와 VS Code 대조 판정자가 같이 부른다(최종 검토: 판정자가 손으로 베낀 문맥을 대조해 호스트가 넘기는 값을 잴 수
  없었다).
- Enter: caret 앞 줄 조각을 왼쪽부터 읽어 **짝 없는 여는 괄호**가 남으면 한 단계 더. 그 괄호의 짝이 caret 뒤(공백 다음)에 바로 오면 가운데 줄을 들여쓰고 닫는 괄호는 원래 들여쓰기로 아래 줄에(VS Code `indentOutdent`). 읽을 때 그 문법의 문자열 따옴표와 줄 주석 뒤는 건너뛴다(트리가 없을 때 — 트리가 답하면 지운 사본을 읽는다, TR4).
- **한 단계는 이어 받은 들여쓰기의 열에서 다음 탭 스톱까지**다(`Unit.toNextStop` — `Tab` 과 같다; VS Code 도 들여쓰기 + 탭을 정규화한다). 정렬된 14 칸 줄 뒤는 16 칸이다 — 처음엔 단위를 그대로 더해 18 칸이 됐고 Backspace 한 번에 16 으로 갔다(최종 검토). 이어 받은 부분은 글자 그대로라 탭 파일의 공백 들여쓴 줄 뒤는 공백 + 탭이다(VS Code 는 통째로 탭으로 바꾼다 — 원문을 바꾸지 않는 §3.9a 쪽을 따른다).
- 선택이 여러 줄이면 caret 뒤 조각은 **선택 끝 줄**의 나머지다(VS Code `getEnterAction` 의 afterText — `foo(|a,` ⏎ `b|)` 의 Enter 는 가운데 줄; 처음엔 빈 조각으로 봐 `)` 를 못 봤다, 최종 검토).
- 닫는 괄호를 칠 때 caret 앞이 공백뿐이면 그 줄을 **짝 여는 괄호가 있는 줄의 들여쓰기**로 맞춘다(뒤로 읽어 짝을 찾는다 — 상한 `typing_ops.reindent_scan_limit`(64 KiB); 못 찾으면 그대로). 앞 커서가 그 줄 머리에 닿았으면(0 열의 커서) 맞추지 않는다 — 맞추면 앞 커서의 입력 뒤 공백을 지운다(최종 검토: `{` ⏎ `|····|` 의 `}` 가 `}}`).

### 언어 규칙 표 (TR3)

- **한 함수**: `session/editor/enter_rules.zig` 의 `decide(ctx, before, after, prev) Action` 이 Enter 의 갈래를 정한다(TR2 의 괄호 판정도 여기로 옮겼다). `line_ops.planNewline` 은 그 답을 글자로 옮길 뿐이다. 순서는 VS Code 와 같다 — 언어 규칙(주석 이어쓰기) → 괄호 → 들여쓰기 규칙.
- **답의 모양은 VS Code 와 같다**(`getEnterAction`): 새 줄 = 이어 받은 들여쓰기(`remove` 만큼 뺀다) + `append`. `append` 가 없으면 `indent`·`indent_outdent` 는 한 단계, 있으면 **그것이 한 단계를 대신한다**(VS Code 의 기본 `appendText` 가 탭이고 그것을 단위로 바꾸는 것과 같다 — `/** a| */` 의 가운데 줄은 ` * ` 이지 한 단계 + ` * ` 가 아니다; 처음엔 둘을 더해 갈렸다, 대조 판정자가 드러냈다).
- Python 제어문(`def`·`class`·`if`·`elif`·`else`·`for`·`while`·`try`·`except`·`finally`·`with`·`async`·`match`·`case`)이 `:` 로 끝나면(줄 끝 주석은 떼고) 한 단계.
- 블록 주석(C·C++·Java·JS·TS·TSX·Go·Rust·PHP·Kotlin·CSS): `/**`·`/*` 뒤 Enter 는 ` * `(caret 뒤가 `*/` 면 그것은 아래 줄로), 주석 안 ` * ` 줄 뒤는 `* `(앞 줄이 주석 안일 때만), ` */` 로 끝난 줄 뒤는 정렬 공백 하나 빼기. 줄 주석(`//`) 가운데 Enter 면 `// ` 로 잇는다(줄 끝이면 잇지 않는다). 트리가 답했으면 줄 주석 이어쓰기는 **caret 이 줄 주석 안일 때만**이다(TR4 — 표식 자리는 그 줄에서 시작한 주석의 머리, 위 줄부터 이어진 줄 주석이면 그 줄의 첫 글자: 맞닿은 줄 주석은 한 조각으로 합쳐지고 Rust `///` 는 개행까지 품는다). 블록 주석 규칙은 트리를 보지 않는다 — 닫히지 않은 `/**`(새 문서 주석을 쓰는 중)는 트리에서 오류 노드라 caret 이 코드로 나온다(VS Code 의 규칙도 줄 글자만 본다 — 곱셈을 잇는 줄 ` * b(|)` 뒤에 `* ` 를 넣는 것도 같다).
- `case X:`·`default:` 뒤 한 단계(switch 를 쓰는 C 계열).
- Ruby: 블록을 여는 줄(첫 낱말이 `def`·`class`·`module`·`if`·`unless`·`while`·`until`·`case`·`begin`·`for`·`else`·`elsif`·`when`·`rescue`·`ensure`·`in`, `private`/`protected def`, `… do`·`… do |x|`, `= if`/`= case`) 뒤 한 단계. 한 줄로 닫힌 것(`… end`)·후위 조건(`return if x`)·문자열 안 `do` 는 아니다.
- HTML: 마지막 태그가 여는 태그(void·자기 닫힘·닫는 태그·주석이 아니다)이고 그 뒤에 다른 태그가 없으면(`<li>a|` 도) 한 단계, 그 닫는 짝이 caret 뒤에 바로 오면 가운데 줄.
- **낱말 내어쓰기**(타이핑 — `typing_ops.keywordOutdent`): Ruby `end`·`else`·`elsif`·`ensure`·`rescue`(낱말 끝 글자)·`when `(뒤 공백), Python `else:`·`elif …:`·`except …:`·`finally:`(`:`)를 줄 끝에서 다 치면 그 줄을 한 단계 내어쓴다 — 그 줄의 들여쓰기가 위쪽 내용 줄 이상일 때만(이미 맞췄으면 그대로 — 거슬러 가는 줄 수 상한 `typing_ops.keyword_scan_lines`(4096)). 같은 줄의 커서 여럿은 앞 것만(앞 커서가 그 줄 머리에 닿았어도 — 닫는 괄호와 같다).
- **VS Code 규칙 대조 판정자**(`INDR1`): `tools/editor/vscode_enter_oracle.mjs` 가 VS Code 내장 언어 설정(핀 커밋 `faa67179693e`)을 원래 의미(JS `RegExp`)로 돌려 말뭉치(77 줄 — TS·JS·Java·C·Go·Rust·Python·Ruby·HTML·CSS·JSON)의 답을 `enter_rules_vscode.zig` 에 찍는다(규칙 원문은 없다 — 답만). 판정자는 우리 `decide` 와 대조하고, 갈리는 것은 **의도한 차이 목록**(열하나 — 문자열·템플릿·줄 주석 안 괄호, C·Go·Rust 의 블록 주석 이어쓰기와 C 의 `case`, Python 줄 끝 주석·`match`, Ruby 문자열 안 `do`·한 줄로 닫힌 블록)에만 있어야 한다. 목록의 차이가 같아지면(VS Code 가 바뀌었거나 목록이 낡았다) 판정자가 실패한다.

### 구문 트리 문맥 (TR4)

- **문맥의 출처는 하이라이트 capture 하나다**(`session/editor/literals.zig` — L2). `string…`·`comment…` capture 를 겹치지 않는 구간으로 펴고
  가장 안쪽이 이긴다 — 템플릿 `${…}`·f-string `{…}`·셸 `$(…)` 의 `embedded` 는 문자열 안이어도 다시 코드다. capture 이름은 grammar 가
  소유하는 관례라 색과 같은 출처다(문법 열여덟의 노드 이름을 따로 적지 않는다). 정규식 리터럴은 `string.special`·`string.regex` 라 문자열로 센다.
- **caret 의 문맥**: 조각이 caret 을 안쪽에 품어야 안이다(`|"ab"`·`"ab"|` 는 밖). 줄 주석은 그 끝(`// a|`)도 안이다 — 끝이 줄 끝이고 닫는
  표식(`*/`·`-->`)으로 끝나지 않을 때. 개행을 품은 조각(Rust `///` 문서 주석)은 그 개행에서 끝났다.
- **트리가 신선할 때만**(`!pending` 이고 트리가 있다). 편집 여섯 경로와 공유 문서의 다른 뷰가 모두 `onEditSpan` 으로 예산 없이 끝까지 다시
  파므로 낡은 자리는 처음 여는 큰 문서의 예산 파싱 동안뿐이다 — 그때는 지금처럼(줄 스캐너).
- **묻는 범위는 필요한 데까지만**(키 입력 하나의 값 — 쿼리 한 번이 caret 자리 3 µs · 한 줄 15 µs · 64 KiB 5.4 ms, ReleaseFast 실측). 한
  글자 입력은 커서마다 caret 자리(`[lo-1, hi+1)`)만. 공백뿐인 줄의 닫는 괄호는 caret 을 품은 트리 조상 중 그 여는 괄호로 시작하는 가장
  안쪽 것의 머리부터(잘 짜인 코드면 짝 찾기가 거기서 멈춘다 — 없으면 상한 `reindent_scan_limit`). 낱말 내어쓰기의 낱말을 다 쳤으면 기준이 될
  위쪽 내용 줄의 머리부터(`typing_ops.keywordQueryStart`). Enter 는 커서마다 그 줄 머리부터 caret 까지. 범위는 정렬해 합치고,
  `literal_query_limit`(1024) 개를 넘으면 하나로 묶고, 합이 `literal_window_limit`(1 MiB)를 넘으면 트리 없이 간다(호스트
  `app_session/editor/mod.zig`).
- **자동 닫기**(VS Code `notIn` 의 자리): 따옴표는 문자열 안이면 닫지 않고, `'`·`` ` `` 는 주석 안에서도 닫지 않는다(`"` 는 닫는다). VS Code
  내장 언어 설정 열셋(핀 커밋)을 대조한 공통분모다 — 따옴표는 전부 `notIn: string`, `'` 는 C·C++·JS·TS·Go·Python·CSS 가 주석도 제외한다.
  Java·Ruby·셸의 주석 안 `'` 닫기, JSON·CSS 의 문자열 안 괄호 제외는 따르지 않는다(주석은 산문이다 — 한 규칙으로). type-over·감싸기는 그대로다.
- **Enter**: caret 이 문자열 안이면 앞 공백만 잇는다(글자 안에 들여쓰기·표식을 넣지 않는다). 주석 규칙은 원래 글자로 읽되 줄 주석 이어쓰기는
  caret 이 줄 주석 안일 때만이다(표식 자리는 트리의 것 — 위 TR3) — 처음엔 줄 스캐너로만 읽어 정규식 `/\/\//`·템플릿 꼬리의
  `http://`·블록 주석 안 URL 의 `//` 뒤 Enter 가 `// ` 를 넣었다(최종 검토). 블록 주석 규칙은 트리를 안 본다(위 TR3 — 닫히지 않은 `/**`).
  괄호·언어 규칙은 문자열·주석을 공백으로 지운 사본으로 읽는다 — 그때 줄 스캐너의 따옴표·줄 주석 건너뛰기는 끈다
  (여러 줄 문자열의 둘째 줄에서 스캐너는 따옴표 짝을 거꾸로 읽는다).
- **닫는 괄호의 짝 찾기**는 문자열·주석 조각을 단번에 건너뛰고, caret 이 문자열·주석 안이면(여러 줄 문자열·블록 주석의 공백 줄) 내어쓰지
  않는다. **낱말 내어쓰기**도 caret 이 문자열·주석 안이면 하지 않고(파이썬 독스트링의 `else:`), 기준이 될 위쪽 내용 줄을 찾을 때 머리가
  문자열 안인 줄(여러 줄 문자열의 몸·닫는 `"""`)은 건너뛴다 — 처음엔 0 열의 `"""` 를 기준으로 `if` 블록의 `else:` 를 0 열로 내렸다(최종 검토).
- 괄호 색인(`bracketSource`)을 쓰지 않는 이유: 색인은 긴 줄(2 만 자 이상)의 괄호를 버리고(VS Code 와 같은 색칠 상한) 편집 뒤 다음 프레임의
  판정(`advanceBrackets`)까지 답하지 않는다 — 빠른 연타의 둘째 키는 스캐너로 떨어지고, 긴 줄에선 조용히 틀린다. 구간 목록은 키 입력 시점의 쿼리 한 번이라
  늘 맞다.

## 한계 (받아들일 것)

- 감지는 문서를 연 뷰마다 한 번이다(공유 분할 뷰는 원래 뷰의 것을 잇는다) — 빈 파일에 탭으로 쓰기 시작해도 단위는 열 때의 추정(언어 기본)이다(VS Code 도 같다). 앱을 다시 열어 복원한 두 뷰는 각자 같은 내용으로 추정한다.
- 줄 스캐너(TR2·TR3)는 여러 줄 문자열·블록 주석 안을 모른다 — TR4 의 트리가 보정하지만, 트리가 낡은 동안(처음 여는 큰 문서의 예산 파싱)과 커서가 1 MiB 넘게 흩어진 입력은 스캐너로 간다.
- 문맥은 하이라이트 capture 관례에 기댄다 — 문자열을 `string` 으로 칠하지 않는 grammar 가 들어오면 그 언어는 문맥 없이 간다(색도 같이 빠진다).
  지금 C 문자 리터럴·HTML 속성값이 그렇고(지금과 같다 — 문맥 없이), Kotlin `${…}` 는 `embedded` capture 가 없어 문자열로 본다(그 안에서
  따옴표를 닫지 않는다).
- 사용자 정의 규칙은 없다(plugin 경계 결정 전).
- 낱말 내어쓰기는 낱말을 다 친 순간이라 Ruby `endpoint` 를 치면 `end` 에서 한 번 내어쓴다(VS Code 의 `decreaseIndentPattern` 도 같다).
- 중괄호 없는 `if (x)` 다음 한 줄만 들여쓰기(VS Code TS `indentNextLinePattern`)는 하지 않는다 — 다음 줄을 친 뒤 되돌려야 하는 상태가 생긴다.
- 공백뿐인 줄의 닫는 괄호가 트리에 묻는 범위는 감싸는 여는 괄호부터라, 그 여는 괄호가 caret 앞에서 이미 닫혔는데 그 위에 문자열 속 닫는 괄호가
  있으면(`f(")",` ⏎ `(a) +` ⏎ `|`) 짝 찾기가 범위 밖의 그 괄호를 센다 — 내어쓰지 않을 뿐이다(최종 검토 — 잘 짜인 코드의 전제).
- Ruby `when ` 의 뒤 공백을 `Tab` 이 공백 하나로 넣으면(단위 폭 5 에 `when` 이 5 열 — 탭 스톱까지 한 칸) 낱말 내어쓰기를 탄다(`Tab` 도 한 글자
  입력 경로를 지난다).

## 적대적 검증 (TR1, 5회)

1. 계약 전수 대조 — 「들여쓰기 단위는 탭 문자」를 전제로 적은 자리를 문서·코드에서 훑었다. **언어 서버 문서 포맷이 `insertSpaces: false` 를 고정으로 보내고 있었다**(도구 §8.2e ③이 그 전제를 근거로 들었다) — 공백 파일을 서버가 탭으로 바꿔 포맷할 수 있다. 감지한 단위를 보내게 고쳤다(`INDT5`, 가짜 서버가 받은 options 를 문서에 적는다). 문서 일곱 곳(문서 모델 §3.9a·네이티브 §12·도구 §8.2e·입력 설정·키 입력·시각 매핑 §5.1c·잔여 점검)을 이었다.
2. VS Code 동작 대조 — `nextIndentTabStop`·`prevIndentTabStop`·`deleteLeft` 의 `useTabStops` 갈래와 맞췄다. **들여쓰기 안의 Backspace 가 공백만 넘게 만들었는데 VS Code 는 탭이 섞여도 앞 스톱 열에 닿는 자리까지 지운다**(`␣␣⇥|` 는 세 글자) → 줄 머리부터 열을 세어 그 자리를 찾게 고쳤다.
3. 상호작용 — 완성 목록이 열려 있으면 `Tab` 은 그쪽이 먼저 받는다(그대로), 비교·읽기 전용은 지금 길이 거절한다. **같은 들여쓰기에 커서가 둘이면 두 탭 스톱 범위가 겹쳐 Backspace 가 통째로 거절됐다**(죽은 키) → 뒤 커서는 앞 커서의 끝에서 멈춘다(`INDT3`).
4. 경계·적대 입력 — 아주 긴 들여쓰기에서 Backspace 의 열 계산이 자리마다 처음부터 세면 제곱이 된다 → 한 번만 걷는다. 단위 폭은 1~16 으로 묶인다(설정 범위). 들여쓴 줄이 없는 새 파일은 언어 기본 — **Makefile 은 문법이 없어 공백이 될 뻔했다**(레시피가 깨진다) → 경로로 탭(`IG12`·`INDT4`). 이름 없는 문서를 Makefile 로 저장하면 다시 추정한다(옛 경로가 없던 문서와 비교).
5. 변이 — 21개, 모두 잡혔다. 처음 회차에서 여섯(F1·F2·F4·F6·F17·F18)은 변이가 매개변수를 안 쓰게 만들어 **컴파일 오류로만** 죽었다 — 판정자를 잰 것이 아니라 다시 썼고(쓰는 꼴을 남긴 의미 변이) 모두 판정자 실패로 잡혔다.

## 적대적 검증 (TR2, 5회)

1. 계약 대조 — 문서 모델 §3.9a 의 「`{` 뒤 한 단계는 이 절이 아니다」를 괄호 Enter·닫는 괄호 내어쓰기 계약으로 바꿨다. 괄호 쌍은 괄호 색칠의 규칙을 L4 가 그대로 넘긴다(L2 는 구문 모듈을 못 들여온다 — 두 벌을 만들지 않으려고 호출자가 준다).
2. VS Code 대조 — TS 말뭉치 25 줄을 VS Code 규칙(`increaseIndentPattern`·`onEnterRules`, 원래 의미)과 우리 판정으로 돌려 21 줄이 같고 넷이 갈렸다 — 넷 다 의도한 차이(문자열 `"{"`·템플릿 `` `${x} {` ``·줄 주석 `// {`·줄 끝 주석 `if (a) // {` 안의 괄호). 정규식 리터럴 `/\{/` 은 둘 다 센다(TR4 의 트리가 보정한다).
3. 상호작용 — **처음엔 모든 문법이 「줄 어디든」이라 Markdown 산문 `see [the docs|]` 의 Enter 가 링크를 들여쓰며 쪼갰다** → VS Code 언어 설정의 갈래대로 끝의 여는 괄호만 보는 문법을 갈랐다(`bracketEnterAnywhere`). **같은 공백 줄에 커서가 둘이면 `}` 의 내어쓰기 범위가 겹쳐 입력 전체가 거절됐다** → 앞 커서만 맞춘다(`INDB5`). 자동 닫기 뒤 Enter·평문·문자열 안 괄호는 제품 키 경로로 쟀다(`INDB4`).
4. 경계 — 짝 찾기는 거슬러 64 KiB 까지, 줄 읽기는 한 번(스택 64 — 넘치면 오래된 것을 버린다; 마지막 것이 답), 닫히지 않은 문자열은 줄 끝까지 건너뛴다.
5. 변이 — 20개. 처음 하나(G17 — 앞 커서가 뒤 커서까지의 공백을 먹지 않게 하는 막음)가 살아남아 그 장면(`{|␣|␣}`)을 `INDB2` 에 더해 잡았다. 20개 모두 판정자 실패로 잡혔다.

## 적대적 검증 (TR3, 5회)

1. 계약 대조 — 문서 모델 §3.9a 의 「언어별 규칙은 이 절이 아니다」를 언어 규칙 계약(블록·줄 주석·Python·`case`·Ruby·HTML·낱말 내어쓰기·VS Code 대조)으로 바꿨다. TR2 의 괄호 판정을 `enter_rules` 로 옮겨 Enter 의 갈래가 한 함수다.
2. VS Code 대조 — 대조 판정자를 만들면서 셋을 고쳤다: **`appendText` 의 뜻**(있으면 한 단계를 대신한다 — 더하던 것), **`/** a| */`**(`*/` 를 아래 줄로), **HTML `<li>a|`**(여는 태그 뒤 글자가 있어도 — 줄이 `>` 로 끝나야 한다고 했던 것). 말뭉치 77 줄 중 갈리는 것은 의도한 차이 열하나뿐이다.
3. 상호작용 — **`/** a| */` 의 Enter 가 ` */` 앞 공백을 먹어 `*/` 가 어긋났다**(괄호 Enter 의 공백 먹기를 그대로 탔다) → 덧붙일 글자가 있는 갈래는 안 먹는다(VS Code 도 그대로 둔다). 같은 줄의 커서 둘에서 낱말 내어쓰기가 겹쳐 입력이 거절되지 않게 앞 커서만 맞춘다(`INDR6`). 재변환(IME)·평문·Markdown 은 낱말 내어쓰기를 타지 않는다.
4. 경계 — 낱말 내어쓰기가 위쪽 내용 줄을 찾아 빈 줄을 끝없이 거슬러 갔다 → 4096 줄 상한. Ruby 문자열 걷어내기는 512 바이트 버퍼(넘치면 앞부분만 — 판정이 보수적으로 「아님」 쪽).
5. 변이 — 22개. 처음 회차에서 다섯이 살아남았다 — 줄 끝에서 열린 Ruby 문자열 안 `do`(H11), `cases:` 라벨(H12), void 가 아닌 자기 닫힘 `<Foo />`(H14), `/** a| */` 의 가운데 줄(H17), 같은 줄 커서 둘의 낱말 내어쓰기(H21) — 장면을 더해 잡았다. 들여쓴 블록 주석의 ` */` 뒤 정렬 공백 빼기(H16)는 그 뒤에도 살아남아(0열 주석은 빼고 나면 종전 경로와 같은 답) 들여쓴 주석 장면을 더했다. 넷(H5·H6·H16·H18)은 처음에 매개변수를 안 쓰게 만들어 컴파일 오류로만 죽어 의미 변이로 다시 썼다. 22개 모두 판정자 실패로 잡혔다.

## 적대적 검증 (TR4, 5회)

1. 실제 문법 대조 — 문법 열일곱(TS·JS·TSX·Python·Rust·Go·C·C++·Java·Ruby·셸·HTML·CSS·JSON·Zig·PHP·Kotlin)의 실제 트리로 모든 caret 자리의

   가 가른 조각의 경계를 진짜 끝처럼 다뤘다 → 그 경계를 「글자 안」으로 표시한다(`LIT5`). Rust 수명 `'a`·`///` 뒤 빈 줄·Go raw·Zig `\\`·Ruby
   `=begin` 은 맞았다. C 문자 리터럴·HTML 속성값·Kotlin 보간은 capture 가 없거나 안 갈라 한계에 적었다.
2. 키 입력 하나의 값 — 처음 배선은 첫 커서의 줄 머리부터(닫는 괄호면 64 KiB 위부터) 통째로 물었다. 쿼리 비용을 재니(ReleaseFast) 압축한 한
   줄 500 KB 에서 64 ms, 보통 코드 64 KiB 에서 5.4 ms 였다 — 긴 줄에서 키마다 수십 ms → 커서마다 caret 자리만, 공백 줄의 닫는 괄호는 감싸는
   여는 괄호부터(`INDL4` — 시간이 아니라 묻는 범위를 단언한다).
3. 신선도 전제·계약 — 「편집 뒤 트리는 늘 신선하다」를 코드로 확인했다: 편집 여섯 경로가 `refreshViewAfterEdit` 한 자리를 지나 `onEditSpan`(범위를
   모르면 통째 `reparse`)을 부르고, 공유 문서의 다른 뷰도 `shared_edit` 가 뷰마다 같은 함수를 부른다. 괄호 색인은 편집 뒤 다음 프레임의 판정
   까지 답하지 않아 쓰지 않았다(설계에 이유). 문서에서 「문맥을 묻지 않는다」류의 낡은 서술은 `pairs.zig` 머리 주석 하나였다.
4. 극단 입력 — 커서가 수천이면 커서마다 묻는 값이 커서 수에 곱해진다 → 범위가 1024 개를 넘으면 하나로 묶는다(합의 상한 1 MiB 는 그대로).

5. 변이 — 28개. 처음 회차에서 다섯이 살아남았다: 시작이 같은 capture 의 순서(M2), 맞닿은 조각을 이을 때 끝 표시(M4), 문자열 안 caret 의 Enter 가
   규칙을 안 타는 것(M18·M21 — 지운 사본에 괄호가 안 남는 장면뿐이었다), 조상이 caret 줄에서 시작하는 경우(M23). M4 를 쫓다가 **보간에 맞닿은
   이스케이프(`"a\n${x}"`)가 폭 0 조각을 만들어 경계 표시를 지우는 결함**을 찾았다 → 같은 종류의 안쪽 capture 는 조각을 가르지 않는다(`LIT6`).
   장면을 더해(`LIT6`·`INDL3` 의 `` f(`a| ``·템플릿 안 `/* a|`·`INDL4` 의 `  |{}`) 모두 잡았다.

## 최종 검토 (TR1~TR4 전체, 2026-10-14)

조각마다 다섯 번씩 본 적대적 검증은 그 조각의 각도였다. 네 조각을 합친 main 에서 네 각도로 다시 봤다 — 조각이 만나는 자리, 입력 경로·견고성,
문서와 코드의 어긋남, 판정자가 제품 배선을 무는가.

- **결함 일곱** — 모두 고쳤다(판정자 `INDF1`~`INDF5`).
  1. CRLF 파일의 줄바꿈 안(`\r`·`\n` 사이 — → 로 줄 끝을 넘으면 닿는다)에서 Python·Ruby 글자를 치면 낱말 내어쓰기가 거꾸로 된 slice 로 죽었다(TR3).
  2. 트리가 답해도 줄 주석 이어쓰기는 줄 스캐너로만 읽어 코드(정규식·URL)에 `// ` 를 넣었다(TR3 × TR4). 블록 주석의 ` * ` 도 트리로 막았다가
     닫히지 않은 `/**` 의 둘째 줄(오류 노드)을 놓쳐 되돌렸다 — 판정자 `INDR5` 가 잡았다. 「그 줄에서 시작한 주석」만 보던 첫 고침은 이어진 Rust
     `///` 줄(한 조각)의 둘째 줄부터 잇지 않았다 — 위 줄부터 이어진 줄 주석은 그 줄의 첫 글자를 표식으로 본다(VS Code 대조 회차).
  3. 공유 분할 뷰가 지금 내용으로 단위를 다시 추정해 한 문서의 두 뷰가 다른 단위를 썼다(TR1 × 공유 문서).
  4. Enter 의 한 단계가 탭 스톱을 무시했다(TR1 × TR2 — `Tab`·Backspace 와 어긋났다).
  5. 여러 줄 선택의 Enter 가 선택 끝 줄의 나머지를 못 봤다(TR2).
  6. 0 열의 앞 커서와 같은 줄의 닫는 괄호·낱말 내어쓰기가 앞 커서 뒤 공백을 지웠다(겹침 가드가 `>=` — TR2·TR3).
  7. 낱말 내어쓰기의 기준 줄이 여러 줄 문자열 안이었다(TR3 × TR4).
- **판정자 구멍** — 제품 경로 판정자가 전부 탭 폭 4·커서 하나·끝의 여는 괄호였다. 호스트가 넘기는 단위 폭·탭 폭·「어디든」·따옴표·줄 주석·괄호
  집합·커서 여럿의 트리 문맥을 지워도 살아남을 자리였다 → 값이 답을 가르는 장면(`INDF2`). VS Code 대조 판정자는 문맥을 손으로 베껴 호스트 값을
  잴 수 없었다 → `contextFor` 한 자리.
- **문서 어긋남** — §3.9a 의 「문법이 필요 없다」, 입력 설정의 「`Tab` 키는 그대로다」, 시각 매핑 §5.1c 의 「안내선에만」, 네이티브 §12 의 계약 밖
  목록, 몇 주석의 조각 표기·낡은 「아직 없다」를 지금 코드에 맞췄다.
