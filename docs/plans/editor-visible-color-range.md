# 본문 색 조회와 실제 표시 범위

상태: 선행 #4599이 실제 main `b8b0e9296`에 머지됐고 전체 트리 일치와 메인의 단위/자료/문서
재검증을 통과했다. 이 단계는 기존 조회 범위를 재현·측정하며 제품 변경은 아직 없다.

## 확인할 문제

현재 일반 본문의 `syntaxColors`는 화면 높이를 받지 않고 최대 256개 논리 줄을 고른다.
`lineColorsInto`는 그 창에 대해 `spansForRange`를 한 번 호출한다. 줄마다 질의하는 구조는 아니다.
기존 내부 귀속 #4582와 최근 전체 귀속은 실제 파일에서 캡처 조회/본문 색의 비용을 보였다.
새로 같은 내부 계측을 재구현하지 않고, 실제 표시 범위보다 넓게 조회하는지를 먼저 확인한다.
256줄보다 큰 창에서는 반대로 필요한 색이 부족할 가능성도 결과로 확인해야 한다.

## 재현과 채택 조건

별도 제품 소스 사본의 실제 PaneFixture·기하·원문으로 화면 크기/표시 행 상한과 현재 색 행을
함께 기록한다. 첫 관측은 랩·접힘·IME 없는 보통 본문으로 범위를 좁히고 그 사실을 명시한다.
작은 창·일반 창·큰 창·스크롤 위치와 실제 파일을 구분한다. 함수 미시 비용과 전체 입력/프레임을
구분하며 기존 분포에서 차이를 빼 개선량으로 만들지 않는다.

범위가 줄어도 실제 표시되는 모든 색이 전체/기존 판정과 같아야 한다. 경계의 여러 줄 문법과
UTF8·CRLF·빈 줄, 스크롤·큰 창·랩 첫 조각·접힘·분할·IME 투영·병합 호출을 별도 확인한다.
semantic/inlay 등 LSP의 기존 요청/미리 읽기 범위를 무심코 바꾸지 않는다. 렌더 범위 제한을
모델 전체의 편집·검색·명령 범위 제한으로 사용하지 않는다.

재현한 효과와 기존 동작 보존을 확인한 뒤에만 제품 변경을 판단한다. 새 캐시/worker/사용자 포맷은
도입하지 않는다. 표시 행 계산은 기존 중립 렌더 기하를 재사용하고 순수 계산을 host에 복제하지 않는다.
구현한다면 다섯 독립 결함 검증과 정상 대조, 관련 제품 회귀·실측·시각 증거·전체 게이트를 확인한다.

## 재현 결과

재현 도구는 [실행 안내](../../tools/editor-visible-colors/README.md)를 따른다.
제품 기반은 `b8b0e9296`이며 제품 소스·빌드는 변경하지 않았다. 준비 빌드와 구분한 세 파일의
각 별도 실행이 모두 통과했다. 각 실행에서 세 높이, 높이마다 6쌍·각 32호출을 비교했다.
함수 비용은 각 묶음의 호출당 경과시간 6개의 중앙값이다. 첫 할당 비용과 프로세스 간 분산은
이 결과로 판단하지 않는다. LSP는 끄고 첫 줄은 렌더 축 31, 폭은 960px, cell 높이는 16px다.

본문 높이는 각 140·600·9,960px다. 후보는 `ceil(body.h / cell_h) + 1`이며 여백·막대·sticky를
차감하지 않은 보수적 상한이다. 작은/일반 창에서 불필요한 조회와 함수 비용을 재현했다.
큰 창에서는 후보가 기존보다 많은 줄을 계산해 비용도 늘었다. 실제 그려진 행을 아직 대조하지
않았으므로 큰 창의 색 누락을 확정하지 않는다. 모든 후보·기존 결과는 같은 시작 줄에서
남은 원문 전체를 조회한 결과의 해당 앞부분과 일치했다. 같은 알고리즘을 사용하므로 문법 자체의
독립 정확성 검증은 아니다. 랩·접힘·IME 없는 범위만 확인했다.

첫 사본은 색 배열 길이 287을 조회 줄 256으로 잘못 비교해 실패했다. 배열 앞의 빈 31슬롯이
원인이며 수정한 두 번째 사본을 채택했다. 첫 자료도 보존한다. 분석기는 실제 테스트 runner가
첫 관측 앞에 붙이는 이름 접두사를 처리한다. 원시 로그 누락을 성공으로 간주하지 않는다.

집계 단위 7개와 실제 Swift 원시 로그에 대한 다섯 독립 손상을 대조했다. 창 크기 누락,
절대 슬롯/조회 수 혼동, 높이를 무시한 후보, 색 대조 누락, 호출 수 손상을 각각 거절하고
각 손상 전후 정상 입력과 원본 불변을 확인했다. 이것은 재현 도구의 판정 검증이며 제품 최적화의
결함 주입을 대신하지 않는다.

근거는 저장소 밖 `/Users/yoonhb/.cache/maru-agent-artifacts/visible-color-query-repro-2`의
소스·입력·실행 파일·원시 로그·해시이며, 독립 읽기 결과는 같은 부모의
