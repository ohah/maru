# Save As와 위치 결과 목록의 탐색 계약

상태: 저장 후 원본 경로 탐색 정상 대조와 인코딩 오염 재현·수정 및 최종 로컬 회귀 검증 통과.

## 계약과 범위

참조·구현·타입 정의·선언의 행은 응답의 경로·줄·열을 복사한 값이다. Save As 뒤에도
이전 경로가 존재한다면 그 경로로 탐색하는 것 자체를 코드 액션의 이전 파일 편집과
같은 결함으로 세지 않는다. 기존 목록의 snapshot 정책과 파일을 수정하지 않는 탐색을 유지한다.

실제 Save As로 두 경로의 bytes·대상 epoch를 확인하고, 기존 목록 선택이 복사된 경로와
응답 서버의 위치 인코딩을 유지하는지 검사한다. 대기 중 결과는 기존 요청 owner 규칙대로
새 대상에 적용되지 않아야 한다. 다른 원본의 새 요청·positive/null·재시도도 대조한다.

특히 목록이 열린 뒤 다른 서버의 새 요청이 같은 State.enc를 갱신할 때 이미 표시된 행의
character 해석이 바뀌는지 확인한다. 실제 UTF-8/UTF-16 fake 프로세스의 협상을 사용하며
제품 Client.encoding을 테스트에서 바꾸지 않는다. 확인된 결함만 기존 snapshot 계약의
누락으로 수정하고, 새 상태/ABI가 필요하면 이유와 범위를 먼저 보고한다.

## 증거

최소 20개의 서로 다른 조건과 정상 대조를 기록한다. native controller·실제 파일·실제
서버 협상과 직접 callback 순서 제어를 구분한다. OS/HID/픽셀 증거로 확대하지 않는다.
raw 실패·최종 로그와 조건별 관측은 외부 Library/Caches/maru-verification에 둔다.

## 발견과 수정

Save As 뒤 복사된 이전 경로 선택은 정상적으로 원본 파일을 열었고 디스크를 수정하지 않았다.
하지만 UTF-16 결과가 열린 뒤 다른 실제 UTF-8 서버에 새 요청을 보내면 request가 State.enc를
덮어 기존 행의 character 3을 UTF-8로 해석했다. 한글·이모지 뒤 기대 byte 7 대신 3으로 이동했다.

인코딩은 기존 State.enc에 결과와 함께 게시한다. onClientResponse가 검증한 origin.encoding을
onLocationsResponse에 전달하며, owner/overlay 검사를 통과해 행을 만든 뒤에만 저장한다.
새 대기나 버려진 결과는 기존 표시의 인코딩을 바꾸지 않는다. 단일 결과의 즉시 이동도
같은 응답 인코딩을 사용한다. 새 상태·ABI·UX·탐색 정책은 없다.

첫 로그는 두 번째 root 생성 뒤 무효화된 Client 포인터를 사용한 하네스 오류다.
현재 Client를 다시 조회하도록 고친 position-before 로그에서 정상 대조 통과와 실제 위치
오염 실패를 분리해 보존한다. 제품 Client.encoding이나 문서 epoch는 임의로 바꾸지 않는다.

집중 9개(행동 5개·초기화 4개)와 기존 읽기 원본 15개가 통과했다.
표시된 결과는 네 종류 × UTF-8/UTF-16 양방향 × 새 요청 없음/대기/positive/null/재시도
40조건이다. 이전 목록 선택 뒤 새 서버의 결과도 정상 위치로 이동하는 대조를 유지한다.
대기 중 Save As는 네 종류 × 두 인코딩 × 이전 positive/null/재시도의 24조건이다.
새 URI의 같은 primary가 재결합한 뒤 이전 seq가 새 대기를 끝내지 않는 것도 확인한다.
두 경로와 다른 root의 실제 disk bytes 및 Undo 이력을 보존한다.

전역 한글 fixture 두 개는 UI 문구가 아닌 위치 변환용 문서 내용이다. i18n 원장 경계가
이 둘을 집계한 실패는 용도 주석과 원장 4→6(전체 424→426)으로 동기화해 해결했다.
독립 원장 검사와 이후 전체 경계 재실행이 통과했다.

최종 Debug/ReleaseFast의 집중 9개·읽기 원본 15개·참조 피커 IME 42개·Save As 명령 16개와
IME 산출물 판정자 3개가 통과했다. Debug의 ABI 라이브러리·전체 경계·문서 링크/좌표·
포맷 검사도 통과했다. 선행 PR 머지 후 최신 main 리베이스 전후 파일 tree가 같은 것을
확인하고 Debug 명령 전체를 다시 실행해 통과했다. 초기화는 고유 합계로 더하지 않으며
원격 CI·머지와 로컬 결과를 구분한다. 원시 기록은 외부 `lsp-location-picker-save-as-*.log`,
조건별 관측은 `lsp-location-picker-save-as-adversarial.json`에 보존한다.
