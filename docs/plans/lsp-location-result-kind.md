# 위치 결과의 검색 종류와 실패 안내

상태: 잘못된 실패 안내 재현·수정 및 최종 로컬 회귀 검증 통과.

## 계약과 가설

참조·구현·타입 정의·선언 결과가 열린 뒤 다른 종류의 새 요청이 나가더라도, 표시된
결과에서 파일을 열지 못했을 때의 안내는 그 결과의 검색 종류를 따른다. 새 대기의 종류로
기존 결과를 설명하지 않는다. 기존 snapshot 탐색·root 제한·대기 원본 정책은 유지한다.

현재 goToRow의 실패 안내가 waiting_kind를 읽는다. 실제 결과 목록과 다른 종류의
REFSTALL 대기를 만들고, 목록이 가리키던 파일을 삭제한 뒤 native Enter로 선택해
올바른 i18n 키·안내와 새 대기 보존, 파일·Undo 보존을 대조한다.

재현되면 표시된 결과의 종류를 인코딩과 같은 게시 경계에 보관한다. 새 상태가 필요하면
기존 macOS app-host ABI 동기화 규칙에 따라 버전을 함께 올린다. 이는 기존 결과 snapshot의
metadata 분리이며 새로운 오류 문구나 탐색 정책을 추가하지 않는다.

최소 20개의 서로 다른 조건과 정상 대조를 남긴다. 실제 파일·native controller와 직접
callback 순서 제어를 구분하며 OS/HID/픽셀 증거로 확대하지 않는다. 원시 기록은 외부
Library/Caches/maru-verification에 보존한다.

## 발견과 수정

참조 결과 두 개를 표시하고 구현 검색을 보류한 뒤, 닫힌 결과 파일을 실제로 삭제했다.
native Enter 선택에서 기대 `No references found` 대신 `No implementation found`가 표시됐다.
검색 종류를 응답이 실제 게시되는 경계에서 State.result_kind로 보관하고, 탐색 실패는
이 필드를 읽도록 한다. 새 대기·버려진 결과·재시도는 기존 표시 종류를 바꾸지 않는다.

상태 필드 추가에 맞춰 app_session ABI·C header·고정 버전 검사를 252→253으로 동기화한다.
기존 i18n 키를 사용하며 새 문구·탐색 정책·workspace 데이터 포맷은 추가하지 않는다.
초기 URI helper 이름과 선택 미준비는 하네스 문제로 분리하고, notice-before3 로그를
실제 제품의 잘못된 안내 재현 증거로 보존한다.

집중 8개(행동 4개·초기화 4개), 읽기 원본 15개와 위치 목록 Save As 9개가 통과했다.
네 표시 종류 × 네 새 요청 종류 × 대기/positive/null/재시도 64조건이며, 이 중 같은 종류
16조건은 정상 대조다. 버려진 응답은 기존 행의 generation과 종류를 보존한다.
각 조건에서 실제 대상 파일을 삭제한 뒤 native Enter의 기존 안내와 새 대기/예약 보존을
확인한다. 이어 새 단일 결과의 정상 이동과 삭제된 단일 결과의 새 종류 안내를 대조한다.
기존 파일 bytes·Undo를 보존하고 의도적으로 지운 fixture가 다시 생성되지 않는 것도 확인한다.

최초 전체 경계의 실패는 복구 입력 경계가 ABI 252를 고정한 것이었다. 세 고정값을
253으로 동기화하고 trust-picker의 ABI drift 변이도 253→252로 갱신했다. 기존 필드·호출
제약은 유지했다. 같은 변이를 격리 사본에 적용해 경계가 거절하는 것과 원본 전후 통과를
확인했다(종료 코드 0/1/0). 실제 작업 소스의 해시는 동일하다. 이는 소스 경계 증거다.

최종 Debug/ReleaseFast 집중 8개·읽기 원본 15개·위치 목록 Save As 9개·참조 피커 IME
42개와 IME 산출물 판정자 3개가 통과했다. Debug의 ABI 라이브러리·전체 경계·문서
링크/좌표·포맷 검사도 통과했다. 그 뒤 별도로 실행한 macOS 앱 호스트 ABI 전체 계약
집계도 exit 0이다. 빌드가 정한 샤드·fresh 분리와 skip을 유지하며 등록 수를 고유 passed
합계로 더하지 않는다. 로컬 결과와 원격 CI·머지는 구분한다.
원시 기록은 외부 `lsp-location-result-kind-*.log`, 조건별 관측은
`lsp-location-result-kind-adversarial.json`, ABI 경계 변이는 `lsp-location-kind-abi-mutation.json`에 둔다.
