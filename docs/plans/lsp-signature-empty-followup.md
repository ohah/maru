# 빈 시그니처 응답 뒤 후속 요청

상태: 재현·수정과 로컬 검증 완료.

## 계약과 가설

기존 시그니처 계약은 같은 원본의 대기 중 트리거를 응답 뒤 한 번으로 합친다.
현재 빈 결과 경로는 hide가 dirty까지 지워 이 후속 요청을 잊을 수 있다.
이전 요청에는 결과가 없더라도 새 입력 위치에는 결과가 있을 수 있다.

기존 API와 State를 유지한다. 빈 결과는 기존 표시를 닫고, 응답 전 합쳐진 트리거가
있으며 원본이 여전히 보이면 현재 위치에서 content_change 요청 하나를 보낸다.
빈 결과만으로 새 요청을 만들지 않는다. 종료·Esc·원본 변경으로 취소한 요청은 되살리지 않는다.
호버가 소유한 박스는 보존한다. 새 UX·의존성·ABI 정책은 없다.

## 검증

실제 fake 서버에 요청을 보낸 AppSession에서 빈 응답을 직접 전달해 대기/표시/전송 수를
대조한다. 직접 응답 전달은 실제 SDK·OS 입력·픽셀 증거가 아니다. inactive/active,
반복 트리거, 낡은 seq·다른 root, 취소와 정상 최종 빈 결과를 구분한다.
회귀를 먼저 실패시킨 뒤 수정하고 Debug/ReleaseFast·기존 출처/서버 종료 gate를 실행한다.
원시 로그와 결함 대조는 저장소 밖 Library/Caches/maru-verification에 둔다.

## 발견과 결과

수정 전 컴파일된 SIGE1은 전송 수 기대 2, 실제 1로 실패했다(15개 중 14개 통과).
수정 후에는 dirty와 원본 surface를 hide 전에 보존해 빈 결과 뒤 한 번 더 요청한다.
SIGE1은 초기 표시 유무·반복 명령·실제 `1,` 편집 뒤 최신 version/focus와 정상 응답,
낡은 응답 재생 및 최종 빈 결과의 무반복을 확인한다. SIGE2는 Esc·숨겨진 원본·
다른 root·잘못된 seq·호버 소유·실제 LSP 비활성화 처리 뒤 늦은 응답을 확인한다.

최종 Debug/ReleaseFast 시그니처 gate는 16개(행동 12개, 모듈 초기화 4개)가 모두 통과했다.
Debug 참조/시그니처 출처 15개, ABI 라이브러리 빌드, 문서 링크·줄 참조·전체 경계도 통과했다.
같은 최종 소스에서 기존 Save As·원본 닫기·서버 종료·auxiliary 격리를 다시 검사했다.
서로 다른 적대적 조건 22개와 정상 대조, 초기 실패는 외부의
`lsp-signature-empty-adversarial.json` 및 `lsp-signature-empty-*.log`에 기록한다.
SIGE의 빈/정상 응답은 순서 제어를 위한 직접 주입이며 실제 SDK/HID/픽셀 증거는 아니다.
새 State 필드가 없어 ABI 252를 유지한다. 원격 CI와 머지 확인은 로컬 결과와 별개다.
