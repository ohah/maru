# Save As 중 표시된 호버·시그니처 수명

상태: 시그니처 표시 잔존 재현·수정과 최종 로컬 회귀 검증 통과.

## 계약과 가설

Save As가 성공해 저장 대상 epoch/URI가 바뀌면 이전 대상에서 계산한 호버·시그니처 표시도
종료한다. 취소·실패로 대상이 유지되거나 다른 문서가 저장되면 유효한 표시는 보존한다.
기존 응답 원본 검사가 대기 중 callback은 막아도 이미 표시된 상자가 본문 revision이
같다는 이유로 남을 수 있는지 실제 Save As로 확인한다.

## 재현과 수정 경계

실제 fake LSP의 요청과 표시용 응답으로 상자를 열고, 실제 Save As actor/worker와 파일
bytes·epoch를 확인한다. 재현되면 성공한 adopt 뒤의 기존 공유 view/window 순회에서
해당 원본의 대기와 표시만 종료하는 기존 host lifecycle 경로를 사용한다. 새 상태/ABI나
새 UX 정책이 필요하면 먼저 보고한다. 서로 다른 대기/표시 원본을 함께 취소하지 않는다.

## 검증

호버·시그니처의 표시·대기, 같은/공유 뷰 성공·취소·실제 worker 충돌 실패·다른 문서
저장과 지연 positive/null을 대조한다. 최소 20개의 독립 조건과 새 요청 정상 대조를 남긴다.
실제 디스크/native controller와 직접 callback·clock seam은 OS/HID/픽셀 증거와 구분한다.
raw 재현/최종 로그와 조건별 관측은 저장소 밖 Library/Caches/maru-verification에 둔다.

## 발견과 수정

Save As는 LSP 버전을 실제로 증가시킨다. 버전이 유지된다는 초기 테스트 가정은 실패했고
제품 결함 증거로 세지 않는다. 이 가정을 제거한 실행에서 호버는 기존 refresh가 닫았지만
표시된 시그니처는 새 요청을 시도하면서 이전 내용을 유지해 새 대상에서도 남았다.

시그니처만 성공한 adopt 뒤에 알린다. 기존 L2 sourceMatches로 같은 대상의 대기와 표시를
따로 정리한다. hide의 표시 정리 본문을 분리해 A의 이전 표시를 닫더라도 B의 새 대기를
지우지 않는다. 새로운 상태 필드·ABI·편집 정책은 없다. 호버 제품 코드는 변경하지 않는다.

집중 9개(행동 5개·초기화 4개), 기존 호버 원본 10개・시그니처/참조 원본 15개가 통과했다.
26조건은 같은/공유 뷰의 표시 성공 4개, 취소/worker 충돌/다른 문서 성공 12개,
대기 중 positive/null 8개, 표시와 대기 원본이 다른 두 채택 순서 2개다.
새 URI에 같은 primary가 재결합한 뒤 새 요청이 표시되고 이전 응답은 새 대기를 지우지 않는다.
취소/실패 대조는 기존 표시와 본문·선택·Undo 및 실제 파일 bytes를 보존한다.

Debug/ReleaseFast에서 집중 9개·호버 원본 10개·시그니처/참조 원본 15개·시그니처
재시작 16개·Save As 명령 16개가 각각 통과했다. Debug의 completion Save As 10개,
ABI 라이브러리·전체 경계·문서 링크/좌표·포맷 검사도 통과했다. 초기화를 고유 합계로
더하지 않으며 원격 CI·머지와 로컬 결과를 구분한다.
