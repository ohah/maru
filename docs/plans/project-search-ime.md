# 프로젝트 검색 도크 IME 문맥

상태: 구현·자동 회귀와 네 입력칸 실제 입력 진단 통과. 고정 앱의 화면 기록 허용 후 PNG/OCR 검증 대기.

## 보존할 계약

검색 도크의 TextField 네 개는 검색어(0), 포함 경로(1), 제외 경로(2), 바꿀 문자열(3)이다.
기존 caret·선택·NFD 원문·길이 정책을 유지하며, 검색 엔진·glob 해석·치환 적용 정책은 바꾸지 않는다.
입력 순서는 기존처럼 검색어→바꾸기→포함→제외이며 숨긴 입력은 Tab 대상에서 제외한다.

프로젝트 검색은 조합 시작 시 이전 요청·결과·미리보기를 무효화한다. 일반 Find의 결과 보존
정책을 옮기지 않는다. 검색어·포함·제외의 확정은 기존 300ms debounce를 사용하고, 바꿀
문자열의 변경은 미리보기·적용 계획만 무효화한다. 후보 확정 Return은 즉시 검색이나 치환
명령으로 재생하지 않으며, 별도로 누른 Return의 기존 검색 실행은 유지한다.

## 설계

공유 TextField IME adapter를 `.verbatim`으로 재사용한다. 칸마다 동적 UTF-16 문맥과 deep
snapshot을 소유하고, 해당 State의 수명이 끝나면 모두 해제한다. 이 State는 공유 Find와 달리
view별 swap/복제 대상이 아니다. 포커스 epoch와 입력칸·활성 surface·root 세대로 네이티브
owner를 구분한다. 결과 generation은 조합 중에도 변하므로 owner 신원으로 사용하지 않는다.

입력칸 이동·검색 도크 이탈·닫기 후에는 이전 owner의 콜백을 소비한다. A→B→A 이동도 epoch로
구분하며 단조 증가 토큰은 포화 시 fail closed 한다. 탭 topology가 없으면 owner를 제공하지 않는다.
입력 중 실패한 콜백은 해당 키의 문자열·caret·선택을 복구하며, 이미 취소한 검색 요청을 되살리지는
않는다. 복구된 입력에 맞춰 기존 무효화/대기 정책을 다시 적용한다.

콜백은 범위 편집과 요청 무효화만 수행한다. 검색 worker 시작과 치환 적용은 기존 명령 경로가
소유하며, IME key가 끝나기 전에 실행하지 않는다. 새 의존성이나 키 replay 정책은 추가하지 않는다.
기존 표시·포인터 계산과 후보 anchor를 공유하고, 긴 줄·중간 선택·marked 내부 caret을 함께 검사한다.

## 구현·검증 순서

1. 기존 코드의 중간 UTF-16 replacement 무시를 실패 검사로 재현한다.
2. 중립 모델의 NFD·emoji·surrogate·긴 입력·선택·실패 원자성과 네 칸 독립성을 검사한다.
3. host 연결 뒤 조합 무효화·300ms 대기·바꾸기 분리·Return·Tab·숨김·닫기·root 변경·늦은
   콜백·동일 칸 재진입·초기화 전 상태를 정상 대조군과 함께 검증한다.
4. 서로 다른 적대적 조건 20개 이상, 제품 변이와 검증기 음성 대조군을 포함한다. 전체 경계·기존
   검색/Find/다른 IME 회귀를 실행한다. ABI 저장 상태와 토큰 비트 예약은 최신 main에 맞춘다.
5. 고정된 실제 앱으로 네 입력칸의 두벌식·후보 취소·한자 확정·Tab·검색/문서 불변 조건을 확인한다.
   독립 창 식별·PNG 해시·OCR과 입력 소스 복원을 검사한다. 권한은 최종 빌드를 고정한 뒤 확인한다.
   PNG·로그·빌드는 저장소 밖에 보관하고 실제 이미지는 PR 본문에만 업로드한다.


## 발견·수정 및 검증 경계

기존 range ABI에서 `a😀z`의 UTF-16 범위 `(1,2)`를 `韓`으로 교체하면 fallback이 범위를
무시해 `a😀z韓`을 만들었다. 중립 TextField 문맥으로 연결한 뒤 `a韓z`를 확인했다. 조합
문자열 `가나`에서 내부 caret을 지정해도 표시가 끝으로 가던 문제도 함께 수정했다. 표시와
anchor는 같은 선택 위치를 사용하며 NFD cluster 내부는 paint만 snap하고 의미 범위는 보존한다.

입력칸 왕복·숨김·도크 이탈·root/활성 surface 변경·토큰 포화·잘못된 범위·snapshot 및 growth
할당 실패·후보 취소·독립 Tab/Return·기존 화살표 replay를 확인했다. 집중 명령은
`zig build test-project-search-ime`이다. 공유 범위 모델 변이에서 후보 키 소비의 순수 대조군
누락을 찾아 추가했고, 정상 대조군 뒤 다섯 모델 변이가 모두 검사 실패로 검출됐다.

실제 진단은 `MARU_PROJECT_FIELD=0`(검색어), `1`(포함), `2`(제외), `3`(바꾸기)와
`python3 tools/project-search-ime/run.py --output <새 외부 경로> --mode diagnostic --app <고정 바이너리>`를
사용한다. 같은 고정 빌드에서 네 칸 모두 후보 취소·한자 확정·실제 Tab·검색 결과/파일 불변·
터미널 복귀·입력 소스 복원을 통과했다. 초기 포커스 검사 중단 실행도 외부 증거에 보존하며 성공
증거로 세지 않는다. `--mode live`의 독립 창/PNG/OCR은 화면 기록 권한을 확인한 뒤 실행한다.

fixture는 격리된 root에 `한`·`韓` 두 파일과 초기 입력만 준비한다. 조합과 칸 이동은 외부 HID가
수행한다. 검색 관련 칸의 후보 미리보기에서는 결과와 요청이 무효화되고, 바꾸기에서는 기존
결과를 유지한다. 파일 두 개의 원문은 관측 코드와 독립 Python 검사기가 각각 다시 읽어 확인한다.
네 칸의 Tab 이동 때문에 전용 private runner의 실행 한도만 195초로 두며 제품 검색 예산과
다른 private 장면의 기본 115초는 유지한다.
