# 원격 SCM — 활성 pane 이 원격이면 그 저장소를 본다

**사용자 결정 2026-08-31**: 「원격일 때도 변경사항이 갱신되게」, 그리고 **쓰기까지 전부** 원격으로 간다.

소유 관계: [에디터 Surface 도크 §3.5](../editor-surface-dock.md)가 「저장소를 어떻게 고르는가」를 소유하고,
이 문서는 그 판정에 **원격 축**을 더한다. 전송(ControlMaster)·안전 규율은 [SSH 통합 §4·§9](../ssh-integration.md)가
단일 출처이며 여기서 다시 정하지 않는다.

## 1. 지금 무엇이 잘못됐나

`git_ops.termCwd` 는 원격 Term 에 **null 을 낸다**([git.zig](../../src/platform/macos/app_session/git.zig)) —
OSC 7 은 host authority 를 버리고 경로만 남기고, 커널 조회는 로컬 `ssh` 클라이언트의 cwd 를 답하기 때문이다.
그래서 `gitRepoTarget` 의 1 순위가 비고 **2 순위(직전에 읽은 로컬 저장소)가 답한다.**

결과: **원격 pane 으로 포커스를 옮겨도 도크에는 로컬 저장소의 목록이 그대로 남는다.** 사용자는 그것을
지금 보는 터미널의 것으로 읽는다. 그 상태에서 스테이지·되돌리기를 누르면 **보고 있지도 않은 로컬 파일**이
바뀐다 — §9.4 가 링크 감지에서 막은 것과 같은 함정이고, 목록은 그보다 위험하다.

옛 규정(§3.5 ⑵ 「원격은 지우지 않는다」)은 **읽을 방법이 없다**는 전제 위에 있었다. 그 전제는 이제 틀렸다 —
[ssh_upload.zig](../../src/platform/macos/ssh_upload.zig) 가 ControlMaster 위에서 원격 명령을 이미 실행한다.

## 2. 계약

### 2.1 저장소 신원은 (host, path) 쌍이다

§9.2 가 cwd 에 대해 정한 것과 같은 모양이다. 로컬은 `host = null`.

- **활성 Term 이 원격이면** 그 Term 의 관측 cwd 와 `ssh_remote_dest` 가 대상이다.
- 원격 저장소 루트는 **원격에서** 정한다(`rev-parse --show-toplevel`) — 로컬 walk-up 은 원격 경로에 뜻이 없다.
- 두 축을 **함께** 저장한다(`git_repo` 옆에 `git_repo_dest`). 목록·diff·쓰기가 같은 쌍을 봐야
  「목록은 원격, 클릭은 로컬」이 원리적으로 불가능해진다.

### 2.2 원격은 셸을 거친다 — 그것이 유일한 예외다

[git_command.zig](../../src/session/git_command.zig) 헤더의 읽기 전용 계약은 「셸·alias 를 거치지 않는다」였다.
원격에서는 `ssh <dest> <command>` 가 **원격 로그인 셸**에 문자열을 넘기므로 그 조항이 성립하지 않는다.
그래서 예외를 좁게 정의한다:

1. **모든 토큰을 작은따옴표로 인용**한다(내부 `'` 는 `'\''`). 인용은 argv 를 만드는 순수 함수가 하고,
   L4 는 그 결과를 그대로 exec 한다.
2. **제어문자가 든 토큰은 거부**한다(`0x00`–`0x1F`, `0x7F`). 인용으로도 안전하지만, 그런 값이 왔다는
   것 자체가 관측이 오염됐다는 뜻이라 명령을 만들지 않는다.
3. **config·env 덮어쓰기를 원격에도 그대로 싣는다** — `env GIT_OPTIONAL_LOCKS=0 … git -c core.pager=cat …`.
   로컬에서 닫아 둔 구멍(pager·hook·external diff·credential helper)이 원격에서 열리면 안 된다.
4. **원격 `git` 은 PATH 로 찾는다.** 로컬은 절대경로 계약이지만(§6 PATH hijack) 원격의 설치 위치는 우리가
   모른다. 그 대신 원격 명령은 항상 우리가 만든 문자열이고 사용자 입력이 토큰으로 들어가지 않는다.
5. **새 연결을 몰래 열지 않는다.** `-S <control socket>` 로만 붙고, 호출 전에 그 소켓의 존재를 확인한다.
   소켓이 없으면 원격 SCM 은 **꺼진 채로 그 사실을 말한다**(비밀번호 프롬프트가 뜨는 것이 최악이다).

### 2.3 화면

- 도크 머리에 **`user@host`** 를 적는다. 로컬과 원격을 눈으로 못 가르면 §1 의 사고가 이름만 바뀐 채 돌아온다.
- 원격에서 아직 지원하지 않는 동작은 **비활성으로 보여 주고 이유를 말한다**(§3.5 의 Fetch 규율과 같다).

## 3. 단계

| 단계 | 범위 | 상태 |
| --- | --- | --- |
| **RS1** | 순수 층: `Remote` 타입 · argv 인용·조립 · 토큰 검증 + 판정자 | ✅ 2026-08-31 |
| **RS2** | 읽기 배선(`runOn` 하나가 감싸기를 소유) · 원격 판정(`remoteScmTarget`) · `(host, path)` 상태 · **로컬 보호 가드** | ✅ 2026-08-31 (도크 머리 표시는 RS3 로 미룸) |
| **RS3a** | diff 열기: 좌우 모두 원격에서 읽는다 · 원격 저장소 루트(`--show-toplevel`)를 목록과 **같은 왕복**에 얹는다 · 비교 열기 인텐트를 원격에서 연다 | ✅ 2026-08-31 |
| **RS3b** | 도크 머리의 `user@host` — 화면 변경이라 골든을 함께 갱신한다(§2.3) | 다음 |
| **RS4** | 쓰기: stage · unstage · discard · commit · fetch 원격 라우팅 + 확인 문구에 host 명시 | 다음 |

**RS3a 에서 새로 정한 것 둘.**

1. **작업트리 쪽은 git 으로 못 읽는다.** `git show :<path>` 는 index 이고 `HEAD:<path>` 는 커밋이라, 작업트리의
   지금 내용을 내는 git 명령이 없다. 그래서 **그 한 자리만** git 이 아닌 명령을 원격에 보낸다
   (`head -c <상한> -- '<abs>'`). §2.2 의 인용·검증 규율은 그대로 적용되고, 상한은 **원격에서** 건다 —
   로컬은 받은 뒤 자르지만 원격은 그전에 바이트가 링크를 다 건너온다.
2. **저장소 루트를 목록과 같은 왕복에 얹는다.** 따로 물으면 원격 왕복이 하나 더 늘고, 그 사이 pane 이
   바뀌면 루트와 목록이 **다른 저장소**의 것이 된다.

그리고 diff entry 는 **열 때 (host, root) 를 박는다** — `diff_repo` 와 같은 이유다. 나중에 세션 상태를 다시
읽으면, diff 를 열어 둔 채 다른 pane 으로 옮겼을 때 그 비교가 다른 호스트의 것으로 해석된다.

**원격 diff Term 이 읽기 전용인 것은 이미 성립한다** — `saveDocument` 가 `editor_diff != null` 이면 거부한다.
RS4 에서 원격 쓰기를 열 때도 이 자리는 그대로 둔다(diff 뷰어는 저장하는 화면이 아니다).

**RS2 가 「읽기」보다 「가드」에 더 들었다.** 원격 목록을 띄우는 것 자체는 배선 몇 줄인데, 그 화면이 떠 있는 동안
**로컬에 손이 가는 길**이 열 곳 넘게 있었다(아래 §5). 그 길을 막지 않고 목록만 띄우면 RS2 는 기능이 아니라 사고다.

**RS1 을 먼저 떼는 이유**: 안전 조건이 전부 이 층에 있다(§2.2). 배선보다 먼저 전수로 고정해 두면,
뒤 단계는 「그 argv 를 어디로 보내나」만 다루게 된다.

## 4. 검증

- **인용·주입**: 공백·작은따옴표·`;`·`$(…)`·개행이 든 경로가 원격에서 **한 인자로** 도착하는지, 제어문자가
  든 토큰은 명령 자체가 만들어지지 않는지. 이 저장소에서 원격 명령을 만드는 첫 자리이므로 전수로 짚는다.
- **덮어쓰기 보존**: 로컬 argv 의 `-c` 쌍과 env 가 원격 문자열에도 **하나도 빠짐없이** 실리는지.
- **라우팅**(RS2 부터): 활성 pane 이 원격↔로컬로 바뀔 때 목록이 그 pane 의 저장소로 갈아타는지, 그리고
  원격 목록을 보는 동안 로컬 경로로 가는 쓰기가 **원리적으로** 없는지(쌍을 함께 읽는다).
- **실물 SSH**: 기존 `tools/session-host/p5d_ssh_smoke.sh` 하네스가 harness-owned localhost OpenSSH 를
  띄운다 — RS2 부터 그 위에서 `status` 한 번을 끝까지 본다.

## 5. 적대적 검증 기록 (2026-08-31, RS2)

**1회차 — 자동 경로.** 인텐트를 안 거치고 tick 이 굴리는 읽기 셋이 `git_repo`(원격 경로)로 **로컬 git** 을 불렀다:
`pumpScmLog`(히스토리) · `pumpCommitFiles`(펼친 커밋·턴의 파일 목록) · `captureTurnSnapshot`. 셋 중 마지막이
가장 나쁘다 — `add -A` 로 **작업트리를 통째로 임시 index 에 굳히는** 경로라, 로컬에 같은 경로가 있으면 그 로컬
트리가 원격 세션의 턴 스냅샷으로 박힌다. 셋 다 `scmTargetIsRemote` 로 막았다.

**2회차 — 전환의 잔여.** 「호스트가 바뀌면 직전 동작 결과 줄을 버린다」를 `rememberGitRepo` 가 하는 줄 알았는데
그쪽은 **경로로만** 판정해서, 로컬 `/srv/app` → 원격 `/srv/app` 처럼 **경로가 같고 호스트만 바뀌는** 전환을 못 본다.
그 상태에서는 원격 안내가 로컬 목록 위에 남는다. 판정을 `rememberGitRepoDest` 로 옮겼다.

**3회차 — 게이트 우회.** 인텐트 게이트가 첫 겹인데 쓰기로 들어가는 길이 그것만이 아니었다: 커밋은 **키 입력**
경로(`settleCommitInput`)로도 들어오고, 기준(base) 변경은 **상태바 메뉴**라 인텐트를 아예 안 거친다. 두 번째 겹을
`submitWrite` 와 커밋 제출 자리, `setScmBase` 에 뒀다.

**5~7회차 (RS3a) — 셋 중 둘이 진짜였다.**

**5회차 — 소유권.** diff entry 에 `(host, root)` 를 박는 세 자리가 `freeDiffPaths` **뒤에** 대입하는지 봤다.
셋 다 그 순서였다(재오픈이 먼저 푼다) — 이상 없음.

**6회차 — 소켓이 사라지면 로컬로 떨어졌다.** ⚠️ `remoteControlSocketFor` 가 null 이면 `remote = null` 로
넘어가 **원격 경로를 로컬 git 에 넘겼다.** 로컬에 같은 경로가 있으면 남의 파일 내용이 「원격 비교」로 뜬다 —
RS2 가 목록에서 막은 사고가 diff 로 돌아온 것이다. 소켓이 없으면 **요청을 걸지 않고 실패로 표시**한다:
그 화면은 이유를 말하고, 로컬 파일을 원격인 척 보여 주지 않는다.

**7회차 — 잘림을 로컬 상한으로만 봤다.** ⚠️ `runArgvWithEnv` 는 `max_output_bytes`(16 MiB)로 판정하는데
원격은 그 전에 `head -c` 로 **4 MiB 에서 잘린다.** 그대로 두면 잘린 파일이 `truncated = false` 로 와
**온전한 파일처럼** 뜬다(뷰어가 「너무 큼」을 말할 기회를 잃는다). 원격 상한으로 다시 판정한다.

**4회차 — 판정자가 나를 잡았다(둘).** ⑴ 「원격이면 `.unknown`」 단언이 처음에 빨갛게 났는데, 그 실패가 가드의
전제를 드러냈다 — 활성 Term 이 로컬이면 **1 순위가 답하는 것이 맞고**, 가드가 필요한 상태는 1 순위가 비는 원격
Term 하나뿐이다. ⑵ 「호스트가 바뀌면 안내를 버린다」를 **한 방향만** 구현해 두었다(로컬→원격). 원격→로컬에서
남은 안내를 판정자가 잡아 양방향으로 고쳤다.
