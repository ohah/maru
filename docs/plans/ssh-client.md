# SSH 클라이언트 — 구현 계획

계약은 [ssh-client.md](../ssh-client.md) 가 단일 출처다. 여기는 **순서와 진행**만 든다.

## 왜 이 순서인가

**아래에서 위로 쌓는다** — 패킷이 틀리면 그 위 전부가 틀리고, 어디가 틀렸는지 못 가른다.
각 슬라이스는 **헤드리스로 판정 가능**해야 하고(순수 함수 + 바이트 열), 실서버 대조는 그
위에서 한 번에 한다.

| | 내용 | 판정 |
|---|---|---|
| S0 | **계약**([ssh-client.md](../ssh-client.md)) — 지원 집합·안 하는 것·보안 규칙·계층 | 문서 |
| S1 | **바이너리 패킷** — 인코딩/디코딩, 패딩, 길이 상한. 압축 없음. **시퀀스 번호는 여기 없다** — AEAD 논스·MAC 이 쓰는 값이라 암호 계층(S4)이 든다 | 바이트 열 단위 테스트 |
| S2 | **버전 교환 + KEXINIT** — 알고리즘 협상, strict 표시자(**초기 KEXINIT 에서만** 읽는다), 서버 추측 패킷을 버릴지 판정 | 협상 결과를 값으로 |
| S3 | **KEX(curve25519)** — 임시 키쌍(씨앗 주입)·공유 비밀·교환 해시 `H`·키 유도. **서명 검증은 안 한다**(S5) | RFC 7748 §6.1 벡터 + `H`·키 조립을 손계산과 대조 |
| S4 | **암호(chacha20-poly1305@openssh.com)** — 길이 필드 별도 키(**K_2** — 구형 OpenSSH 문서와 이름이 반대다, [계약 §3](../ssh-client.md)), AEAD, 패딩 규칙(길이 필드 제외) | **명세 Appendix A 워크드 예제와 바이트 일치** + 변조 거부 |
| S4b | **전송 루프** — 시퀀스 번호(방향별)·`NEWKEYS` 전환(옛 키로 보내고 그 뒤 교체)·평문↔암호 프레이밍 전환·추측 패킷 폐기(번호는 올린다)·strict KEX 수신 게이트 넷([계약 §4](../ssh-client.md)) | 바이트 열로 상태 전이 |
| S5a | **호스트키 서명·지문** — `ssh-ed25519` blob 파싱, 교환 해시 서명 검증, `SHA256:` 지문 | RFC 8032 §7.1 벡터 + `ssh-keygen -lf` 와 지문 일치 |
| S5b | **`known_hosts` 대조** — 호스트 매칭(평문 패턴·부정·해시 `\|1\|`)·`@revoked`·`@cert-authority` 제외·판정 넷 | 줄 파싱 + 판정 + `ssh-keygen -H` 와 해시 일치 |
| S6a | **인증 프로토콜** — service 요청, `publickey`(session_id 를 덮는 서명)·`password`, 응답 넷, 배너 거르기. **S6a-2**(완료): 그 `password` 를 세션이 실제로 쓴다 — 키가 거절되고 서버가 열어 뒀으면 멈춰서 묻고(`password_needed`), 답을 받아 잇는다. ABI(`maru_mobile_ssh_password`)·펌프·두 host·묻는 화면까지 배선했다. **키가 없어도 붙는다** — `none`(§5.2)으로 방법 목록만 묻는다(iOS 는 키 파일이 없으면 접속 자체를 안 하고 있었다) | RFC 8032 벡터로 서명 + 응답 파싱, **실서버 열다섯째 회차**(비밀번호만 여는 sshd 에서 묻는 자리에 서고 틀린 값은 되묻지 않는다) + **기기**(두 기기에서 화면에 치면 sshd 가 `Failed password` 를 남긴다) |
| S6b | **`openssh-key-v1` 파싱** — 평문 키와 암호화 키(`aes256-ctr` + OpenSSH bcrypt KDF), `checkint`·패딩·공개키 일치 검사 | `ssh-keygen` 이 만든 같은 키의 평문본·암호본이 같은 값을 낸다 |
| S7 | **채널** — `session`·`pty-req`·`shell`·데이터·`window-change`·`exit-status` + **보내는 쪽 흐름 제어**(윈도·최대 패킷을 넘겨 보내지 않는다 — 실서버가 초기 윈도 `0` 을 광고하므로 첫 바이트부터 필요하다) | 상태 전이 + 실서버 왕복 |
| S7b | **받는 쪽 흐름 제어** — 우리 윈도 소비(자동)와 `WINDOW_ADJUST` 보내기(절반에서). 잊으면 조용히 멈추는 대신 `WindowExhausted` 로 죽는다 | 초기 윈도의 3000 배를 흘려 보낸다 — 보충 없이는 못 지난다 |

| S8 | **실서버 검증 하니스** — 소켓 어댑터(`std.c`)와 드라이버로 진짜 sshd 와 왕복한다. `mise run ssh-client-smoke` 가 **일회용 sshd 를 스스로 띄우고** 8MiB 를 받는다. **제품 경로가 아니다**(아래) | 실서버 왕복 + 흐름 제어가 실제로 도는지 |
| S9 | **모바일 배선** — host 소켓 ABI(브리지엔 OS 호출 0), 키 저장은 Keychain/Keystore. **S9-1**: 세션 상태기계(`client.zig`)를 도구에서 승격 — 검증 도구와 모바일이 같은 것을 쓴다. **S9-2**: C ABI + 브리지(`maru_mobile_ssh_*` — 핸들·세대·양방향 배압, 난수는 host 가 준다). **S9-3**: 두 host 가 함께 쓰는 소켓 펌프(`platform/mobile_host/ssh_pump.c` — 데스크톱에서 실서버로 먼저 증명한다) → 안드로이드 포그라운드 서비스(소켓 소유 — 배경 유지를 에뮬레이터로 실측) → iOS host(유예 시간 뒤 정직하게 끊고 복귀 시 재접속 — 시뮬레이터로 실측). **거기서 정할 것 둘**: (1) 붙었을 때
화면을 어떻게 시작하나 — 지금 모바일 터미널은 데모 바이트가 먼저 들어가 있어 원격 출력이 그 밑에

스레드의 자물쇠 — iOS 도 이제 직렬화가 필요하다([모바일 계약](../mobile-platform.md) §3) | S9-1·S9-2 는 실서버 열 회차(pty·no-pty·echo·rekey·rekey-echo·self-rekey·banner·disconnect·**ABI**·**ABI 에코**), S9-3 은 기기 |
| S9b | **서버 목록 화면** — 호스트·사용자·포트·키를 등록·관리(모바일은 UI 가 유일한 입력 경로). **S9b-1**(완료): chrome **글자 칸** — 설정의 문자열 줄을 눌러 치고(글자 단위 백스페이스·엔터 확정), 키보드 종류를 브리지가 정한다(0 터미널·1 숫자·2 글자 — 글자 칸을 터미널과 같은 0 으로 말하면 하드웨어 키보드로 친 글자가 사라진다). 커서 이동·선택은 아직 없다. **S9b-2a**(완료): 접속 정보를 config 가 든다 — `ssh.server.<n>.*` 를 브리지가 파싱해 들고 host 는 ABI 로만 본다(`maru_mobile_server_*`·`maru_mobile_take_server_connect`). 개발용 `ssh.conf` 는 두 host 에서 통째로 없앴다. 재접속 판단도 브리지로 모았다(원격 세션이 없을 때만 요청 — 그 사실은 입력 목적지가 이미 안다). **S9b-3b**(완료): 연결 진단 — 실패를 터미널 화면 위쪽 띠에 **사람 말로** 보이고 목록 줄에도 상태를 적는다. **S9b-3**(완료): 처음 붙는 서버의 지문을 보여 주고 승인받는다 — 승인하면 그 줄에 적어 다음부터는 핀 고정이다(아는 서버가 다른 키를 내밀면 묻지 않고 끊는다). **S9b-2b-1**(완료): 서버 목록 화면 — 세션 목록의 "서버" 줄로 들어가 골라 붙는다(접속할 수 없는 줄은 그렇게 말하고 요청을 안 낸다). **S9b-2b-2**(완료): 등록·수정·삭제 — 글자 칸(S9b-1)으로 값을 치고 저장하면 목록을 통째로 다시 적는다(번호는 그때 다시 매긴다). 그 회차가 **숫자 키보드의 숫자가 네이티브 입력 큐로 와서 버려지던 결함**을 잡았다(포트 칸에 아무것도 못 쳤다) | S9b-1·S9b-2a·S9b-2b-1·S9b-2b-2 는 **기기**(에뮬레이터·시뮬레이터에서 색을 쳐 넣고 배경 픽셀이 그 값이 되는 것을 봤다), 나머지는 화면 |

| S10 | **컨트롤 플레인 부착** — 같은 SSH 연결에 **채널을 하나 더** 열어 원격의 `maru control --stdio` 와 ndjson 을 주고받는다(M3 이 여기로 흡수된다). **이름 주의 — 세션 호스트(MRSH)가 아니다**: 컨트롤 소켓을 여는 것은 **GUI 앱**이고(`app_host_abi.zig`), 그래서 이 축은 만들기(`platform/mobile/mobile_control.zig`). **S10d-2**(완료): ABI(`maru_mobile_control_feed`·`_take_control_request`·`_control_state`·`_off_reason`·`_session_count`·`_listed`·`_reset`)와 세션 목록 화면 — 목록이 **받는 중·없다·줄들** 세 상태를 갈라 그린다. **S10d-3**(완료): 두 host 가 채널을 굴린다(`driveControlChannel` 한 벌) — 목록 화면에 들어갈 때 열고 나갈 때 닫으며, 이미 선 축은 다시 안 연다. 시한(5초)은 host 가 잰다. `maru` 경로는 서버 항목(`ssh.server.<n>.maru-path`)에서 받아 **코어가 인용해** 싣는다. **남은 것**: `browser.*` 의 surface 앵커(원격은 `MARU_PANE_ID` 가 없어 셀렉터가 비어 있다 — [컨트롤 플레인 §4a](../control-plane.md)), 배경 갱신 정책, `maru-path` 입력 칸. **S10e**(완료 — 2026-08-29, 다만 **두 막힘을 우회해서**): 고른 세션의 화면을 폰이 본다. 목록 줄을 누르면 `maru attach --stream <runtime_id>` 가 화면 레코드(`MRSS` 프레임)를 흘리고 폰이 조립해 그린다(읽기 전용). 실기 확인 완료 — 임시 sshd 위에서 시뮬레이터가 실제 맥 세션 화면을 그렸다. **아래 두 막힘은 없어진 것이 아니라 우회됐다**: ① `session.capture` 는 **여전히 라이브에 없다**(라우터가 균일 `unauthorized` 로 접는 것도 그대로다) — 화면을 세션 호스트 쪽 축(`attach --stream`)으로 받았기 때문에 그것이 선행 조건이 아니게 됐다. ② 브리지의 `term_core` 단일 변수도 **그대로다** — 원격 화면은 코어 격자를 안 거치고 별도 조립기(`platform/mobile/mobile_screen.zig`)로 들기 때문에 U2 를 안 기다린다. **남은 것**: **여러 세션을 동시에 드는 것**(그건 여전히 U2 다). 색·커서는 끝났고, **둘러보기(팬)는 필요가 없어졌다** — 아래 S11 을 본다. 아래는 그 전 서술이다. **두 겹으로 막혀 있다**(2026-08-21 코드로 확인). 첫째, **서버가 화면을 줄 방법이 라이브에 없다**: `session.capture` 의 순수 코어는 있지만(`session/control_capture.zig` — 839줄·테스트 16개) 라우터는 그것을 균일 `unauthorized` 로 접고(`control_dispatch.zig`), 라이브 서버는 그 파일을 **아예 안 부른다** — `hello` 의 capabilities 에도 없다(실측: `sessions.list`·`session.get`·`browser.*` 18개뿐). 즉 read-output grant + chunk 배선이 선행 조건이다. 둘째, **U2(다중 세션)에 막혀 있다**: 브리지가 `term_core` 단일 변수라 세션이 하나뿐이다([모바일 계획](mobile-platform.md) U2). 그 의존을 먼저 풀거나 화면을 갈아 끼우는 최소판으로 간다 | S10b 는 실서버 회차 — **다만 지금 스모크 sshd 는 `ForceCommand` 를 쓴다**(세 곳). 강제 명령이 걸린 서버는 우리 `exec` 을 무시하므로 그 회차는 **그 설정 없는 서버를 따로 띄워야** 한다(적대적 검증 2회차가 잡았다). 나머지는 기기 |
| S11 | **고른 세션의 화면을 본다** — 목록 줄을 눌러 그 세션의 화면을 폰에 그린다(읽기 전용). **S10e 의 두 막힘을 우회한 축이다**: 화면을 `session.capture`(라이브 미배선) 대신 **세션 호스트 축**으로 받고, 코어 격자(`term_core` 단일 변수 = U2) 대신 **별도 조립기**로 든다. **S11-0~1**(완료): 세션 호스트 registry base 를 CLI·앱이 같은 자리로 보고(`MARU_SESSION_HOST_ROOT`), `runtime list` 에 제목을 싣는다. **S11-2**(완료): `maru attach --stream <32-hex>` — ANSI 대신 **화면 wire** 를 stdout 으로 흘린다(`MRSS` 프레임: magic·kind·len·payload). ANSI 를 안 쓰는 이유는 폰이 그것을 다시 파싱해야 하고 그러면 코어 격자가 필요해지기 때문이다. **S11-3**(완료): 코덱을 폰이 쓸 자리로 옮긴다(`session/screen_stream.zig`·`screen_assembler.zig` — `terminal.Color` 의존을 `ColorIntent` 로 끊었다). **S11-4**(완료): 컨트롤 채널이 그 명령을 연다 — 한 채널에 `ControlWant`(`sessions`|`screen`)가 명령을 정하고, **소비자도 원하는 것이 정한다**(ndjson 파서 vs MRSS 리더). **S11-5**(완료): 폰이 레코드를 조립한다(`platform/mobile/mobile_screen.zig`, sans-io). **S11-6**(완료): `sessions.list` 에 `runtime_id` 를 싣고, 목록 줄을 눌러 그 화면을 연다. **S11-7**(완료 — 2026-08-29 실기 확인): 임시 sshd 위에서 시뮬레이터가 실제 맥 세션 화면을 그렸다. 그 회차가 결함 셋을 찾아 고쳤다 — 앵커 없는 연결의 목록이 언제나 비던 것([컨트롤 플레인 §4a](../control-plane.md)), 죽은 host 줄이 쌓이면 `attach` 가 조용히 전부 denied 하던 것([영속 세션 호스트](../persistent-session-host.md)), 원격 화면이 창을 안 덮어 폰 터미널과 겹쳐 그려지던 것. **색·커서**(완료 — 2026-09-01): run 이 든 색을 그대로 풀고(태그드 intent), inverse 는 두 색을 맞바꾸며, 커서를 사각으로 그린다. **둘러보기(팬)는 «필요가 없어졌다»**: 팬은 「세션이 폰보다 넓어 오른쪽이 잘린다」를 풀려던 것인데, 뷰포트 선언([영속 세션 호스트](../persistent-session-host.md) §S11-6 — **다른 번호 공간이다**, 이 표의 S11-6 과 무관)이 세션을 폰 격자에 맞춰 그 문제 자체를 없앴다. 세로는 계약이 **행을 안 줄이고** 폰이 «아래 기준»으로 그리는 쪽으로 정했다(맥 창이 23행을 잃는 대가를 안 치른다) — 그래서 창 위로 넘는 행은 **여전히 안 보이지만**, 그것을 보는 것은 팬이 아니라 **스크롤백 축**이고 지금 계약 밖이다. 그리기 루프의 가로 클립은 남지만 그것은 이제 방어이지 기능 공백이 아니다. **남은 것**: **여러 세션을 동시에** 드는 것(그건 U2 다) | 실기(시뮬레이터 + 임시 sshd + 실 세션 호스트). 화면 절반은 헤드리스로도 잰다(`p5c3d --stream` 제품 E2E) |

**S8 은 제품 경로가 아니라 시험대다.** 데스크톱의 `maru ssh` 는 시스템 `ssh` 를 부르는 래퍼로
**그대로 둔다**(계약 §3.4 — 그쪽이 agent·`ProxyJump`·2FA 를 다 한다). 내장 클라이언트는 **모바일용**
이고, 데스크톱에서는 **검증 경로**로만 쓴다. 그래서 S8 이 만드는 것은 "데스크톱에서 내장 SSH 로
접속하는 기능" 이 아니라 **소켓 어댑터 + 실서버 스모크**다.

**그런데 그 시험대가 없으면 안 되는 이유가 있다.** 지금까지 만든 것은 전부 sans-io 라 **스스로는
아무 데도 못 붙는다**. 그리고 더 중요하게, 교환 해시 `H` 와 키 유도는 **손으로 조립한 값과 맞댄
것뿐**이라 명세 *해석*이 틀렸다면 테스트도 같이 틀린다([검증 매트릭스](../verification-matrix.md)에
그렇게 적어 뒀다). 그것을 깨는 방법은 하나다 — **진짜 sshd 가 `H` 에 서명하고 그 서명이 검증되면**
우리 `H` 가 서버 것과 같다는 뜻이다.

**S8 을 S9 보다 먼저 둔다.** 데스크톱은 소켓이 `std.net` 이라 배선이 짧고 CI 가 돌릴 수 있으며,
무엇보다 **상호운용 결함과 배선 결함을 가른다** — 모바일에서 처음 붙이면 "안 된다" 가 프로토콜
탓인지 host 소켓 탓인지 모른다(모바일에서 이 실수를 여러 번 했다). 데스크톱에서 붙는 것을 보면
프로토콜은 맞다는 것이 확정되고, 이후 모바일 실패는 배선으로 좁혀진다.

## 지금 있는 것 / 없는 것

- `src/cli/ssh.zig`(518줄)는 **래퍼**다 — terminfo 를 심고 시스템 `ssh` 로 `exec` 한다.
  프로토콜 코드가 아니라 **재사용분이 0** 이다. 그대로 둔다(데스크톱에서 유용하다).
- 암호 원시함수는 **`std.crypto` 에 다 있다** — X25519·Ed25519·ChaCha20-Poly1305·SHA-2·HMAC·
  `bcrypt.pbkdf`. 외부 C 의존이 없다.
- 컨트롤 플레인 인증은 `same-uid + MARU_PANE_ID` 라 **로컬 전용**이다 — 원격 축이 비어 있었고,
  이 계획이 그 자리를 SSH 로 채운다.

## 위험

- **상호운용은 명세만으로 안 닫힌다.** 서버 구현마다 관대함이 다르다 — S8 의 실서버 왕복이
  유일한 진짜 판정자다.
- **보안 결함은 조용하다.** 호스트키 검증을 빠뜨려도 화면은 멀쩡하다 — S5 를 인증(S6)보다
  **먼저** 두는 이유다(검증 없이 붙는 경로가 잠깐이라도 존재하지 않게).
- **재키잉·큰 데이터**는 오래 켜 둔 세션에서만 드러난다. 스모크에 `yes | head -c 10M` 같은
  대량 전송을 넣어 강제한다 — **채널 흐름 제어(S7b)가 빠지면 정확히 여기서 멈춘다**.
- **`keyboard-interactive` 를 뺀 것이 붙는 서버를 줄인다**([계약 §3](../ssh-client.md)) — 키 없이
  비밀번호로만 여는 서버가 흔하고 그들 중 다수가 이 방식을 쓴다. 넓힐 때 첫 후보다.
