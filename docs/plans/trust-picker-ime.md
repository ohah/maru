# 신뢰·환경 이름 목록 검색창 IME 범위 문맥

상태: 두 모드의 중간 UTF-16 교체 실패를 먼저 재현하고 구현했다. host/ABI 42개와 중립 모델 Debug/ReleaseFast 각 13개가 통과했다. 최종 고정 앱으로 두 모드의 실제 두벌식·후보 취소 5회·한자 확정·별도 Return·편집 복귀 진단도 통과했다. 전체 macOS 제품 회귀·기존 복구/참조/심볼 IME·Swift·경계·문서 검사와 제품 변이/정상/원복 대조군이 통과했다. PNG/OCR은 같은 앱의 화면 기록 권한을 기다린다.

## 유지할 계약

신뢰 목록과 환경 변수 이름 목록은 같은 trust_picker를 쓰지만 동작은 다르다.
신뢰 목록은 열 때 만든 결정 사본을 검색하고, 별도 Return에서 선택한 key를 현재 신뢰 표로 재검증해
기존 관리 확인창을 연다. 목록에서 신뢰를 부여하거나 자동으로 철회·잊기하지 않는다.
환경 목록은 값 없이 이름·제외 여부만 보이며 별도 Return은 닫기만 한다.
후보 미리보기·후보 Return은 어떤 모드에서도 관리창 열기·닫기·신뢰 변경으로 전달하지 않는다.

query/preedit의 NFD·UTF-8 원문과 기존 동적 길이를 유지한다. 비교에만 기존 composeHangul과 ASCII fold를
적용하며, 신뢰 모드는 실제 경로와 표시 경로(~/ 또는 목적지:경로)를 모두 검색한다. 환경 모드는 이름만 검색한다.
기존 legacy 필터의 한글 조합 할당 실패 시 원문 비교 fallback은 유지한다. native 키의 필터 준비 실패는
키 snapshot 전체를 복원하고 기존 query/preedit·행·선택·스크롤·프롬프트를 보존한다.

## 책임과 수명

공용 overlay_input_ime.Projection/Transaction이 범위·선택·취소·키 rollback을 소유한다.
중립 chrome 모듈이 비교와 인덱스 준비를 소유하고 host는 기존 표시 label/환경 상태를 제공한다.
준비된 결과를 성공 뒤 게시해 새 query와 이전 행이 섞이지 않는다. 성공한 검색은 기존대로 선택·스크롤을 초기화한다.
owner는 열기 세대·활성 surface·목록 mode·열 때의 항목 사본에 묶는다. 신뢰 표의 외부 변경은 열려 있는 사본을
바꾸지 않는다. 닫기/재열기·mode 전환·빈 topology·bootstrap·terminal pin·세대 포화는 이전 콜백을 차단한다.
bit 50 namespace를 사용하며 Session Dock token 상한을 그 아래로 둔다. AppSession 필드 변경은 ABI에 반영한다.

## 검증

먼저 a😀z의 UTF-16 (1,2) 교체가 a韓z가 되는지 두 모드에서 실패를 재현한다.
범위·NFD·비-BMP·잘못된 입력·취소·다중 콜백·긴 문자열·owner 전환·각 할당 실패와 다음 키 회복 등
서로 다른 20개 이상 조건을 검사한다. 후보 Return은 관리창/닫기/신뢰 변경을 일으키지 않고 별도 Return만
기존 accept를 따른다. 사용자 신뢰 파일·환경 값은 검증에 사용하지 않는다.
제품 변이 7종과 정상/원복 대조군, 기존 신뢰·환경·복구·참조·심볼 입력·전체 ABI·Swift·경계·문서 회귀를 확인한다.
실제 private 신뢰 사본/환경 이름 장면에서 두벌식·후보 취소 5회·한자 선택·별도 Return·복귀를 확인한다.
실제 후보창 PNG/hash/OCR을 진단과 구분하며 이미지·원시 증거는 저장소 밖과 PR 본문에만 보존한다.

## 발견과 수정

신뢰·환경 두 모드에서 `a😀z`의 UTF-16 `(1,2)` 교체가 `a😀z韓`로 뒤에 붙었다.
공용 native 범위·키 transaction을 연결해 `a韓z`로 고쳤다. 후보 Return은 필터만 게시하고
관리창/닫기로 전달하지 않으며, native 필터 준비 실패는 이전 입력과 목록·선택·스크롤·프롬프트를 보존한다.

실제 환경 이름 목록 검증에서 영문 안내가 61칸(대기 안내 63칸)인데 패널 상한은 60칸이라
caret이 패널 안에 만들어지지 않았다. 같은 의미의 짧은 영문 안내로 바꾸고 한국어·영어의 목록/빈 목록/
대기 안내 모두에서 한글 입력 caret이 패널 안에 남는 모델 검사를 추가했다. 실패한 실제 진단과
`maru-trust-picker-ime-prompt-red-20261027.log`를 외부에 보존했다.

초기 실제 앱 시작에서 헤더와 Zig의 ABI 선언 불일치도 확인해 247로 통일했다. 집중 게이트에 기존 ABI
계약 검사를 포함해 앱을 만들기 전에 같은 오류를 잡도록 했다. 범위 무시·필터 조기 파괴·게시 누락·mode
누락·후보 Return 누출·영문 안내 재확장·ABI 선언 어긋남의 컴파일 가능한 제품 변이 7종을 행동 검사로
거부했고 정상/원복 대조군도 통과했다.

원시 증거는 저장소 밖 `maru-trust-picker-ime-*20261027*` 작업별 디렉터리에 보존한다.
환경 이름 장면은 셸 환경 실행을 끄고 사유 HOME과 명시한 런처 환경으로 준비한다. 실제 값은 관측·출력하지
않으며 검색 결과 0개에서도 두벌식·후보 취소/선택과 별도 Return 닫기를 검사한다.
