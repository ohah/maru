# 신뢰 감사 기록 구현 계획

상태: TA1·TA2 완료(계획 끝). 계약은 [tooling §8.2a 「신뢰」 행](../editor-surface-tooling.md)이 소유하고, 이 문서는 결정·설계·조각·검증을 소유한다. [워크스페이스 신뢰 계획](workspace-trust.md)의 「범위 밖 — 감사 로그」를 이어받는다.

## 왜

신뢰 결정(허용·거부·철회·잊기)은 앱 전역 표 하나에 산다. 그런데 **언제·어디서** 바뀌었는지는 남지 않는다. 신뢰 파일(`lsp-trust`)은 줄을 덧붙이기만 하지만 시각·출처 칸이 없고, 다음 실행이 읽을 때 `forget` 줄은 항목과 함께 사라진다.

컨트롤 플레인(WT4b)은 같은 uid 의 연결이 확인 없이 철회·잊기를 부르게 했다. 이때 「에이전트가 잊기를 부른 뒤 허용 클릭을 유도할 여지」를 받아들였다(WT4b 「누가 부르나」). 그 일이 일어났는지 사용자가 볼 길이 없었다.

## 결정 (2026-10-12 사용자)

- **따로 쓰는 로그 파일** — 신뢰 파일 옆에 `lsp-trust-log` 를 둔다. 신뢰 파일의 형식은 그대로라, 옛 빌드와 섞여도 결정을 잃지 않는다. 신뢰 파일 줄에 칸을 더하는 안은 고르지 않았다. 칸 수가 바뀌면 옛 빌드가 그 줄을 모두 무시하기 때문이다.
- **보이는 곳은 목록 행과 CLI** — 신뢰 목록(팔레트 「Language Server: Repository Trust…」)의 각 행에 마지막 변경의 시각과 출처를 보인다. 전체 기록은 컨트롤 플레인과 CLI 로 본다(TA2). 팔레트용 기록 목록은 두지 않는다.
- **출처는 종류와 CLI 프로세스** — 종류는 넷이다. 신뢰 시트의 답, 관리 상자, 컨트롤 플레인, 옛 자리 이관이다. 컨트롤 플레인이면 소켓 상대의 pid 와 실행 파일 이름도 남긴다(TA2).

## 설계

- **줄 형식**: `‹unix ms›\t‹동사›\t‹출처›\t‹상대›\t‹키›`.
  - 동사는 `allow`·`deny`·`forget` 이다. 철회는 출처가 관리 상자나 컨트롤인 `deny` 다.
  - 출처는 `sheet`·`manage`·`control`·`migrate` 다.
  - 상대는 `-`, 또는 `‹pid›:‹이름›` 이다. 이름은 64 바이트에서 글자 경계로 자르고, 탭과 제어 문자는 `?` 로 바꾼다. TA1 은 늘 `-` 를 적는다(읽기는 둘 다 받는다 — TA2 가 형식을 바꾸지 않게).
  - 키는 신뢰 파일과 같다. 로컬은 `‹볼륨 16진›\t‹실제 경로›`, 원격은 `ssh\t‹목적지›\t‹원격 실제 경로›` 다.
  - 순수 층은 `session/lsp/trust_log.zig` 다.
- **남기는 때**: 표의 결정이 **바뀔 때만** 남긴다. 기록하는 자리는 `trust_store.decide`·`forget` 이고, 호출자가 출처(`Origin`)를 넘긴다.
  - 같은 답을 다시 한 것(`touch`)과 잊을 결정이 없던 잊기는 남기지 않는다.
  - 옛 자리 이관은 새 파일을 다 쓴 뒤 이관한 결정마다 한 줄을 남긴다. 시각은 이관한 때다.
- **끊긴 줄**: 신뢰 파일과 같은 규칙이다. 개행으로 끝나지 않은 줄은 읽지 않는다. 덧붙일 때 파일 끝이 개행이 아니면 `\t\n` 으로 닫아, 그 줄이 어느 칸 수로도 읽히지 않게 한다.
- **크기**: 256 KiB 를 넘으면 덧붙이기 전에 `lsp-trust-log.1` 로 옮기고(덮어쓴다) 새로 시작한다. 파일은 둘까지다. 읽는 쪽은 `.1` 다음 지금 파일 순서로 읽는다. 결정 하나가 대략 100 바이트라 둘을 합쳐 수천 건이다.
- **권한**: 0600 이다. 신뢰 파일과 같다.
- **실패**: 기록을 못 남겨도 결정은 그대로 선다. 알리지도 않는다. 결정의 저장 실패는 따로 알린다(WT4a).
- **목록 행**(TA1): 상세 칸은 「‹결정› · ‹시각› · ‹출처›」이다. 시각은 올해면 `MM-DD HH:MM`, 다른 해면 `YYYY-MM-DD` 이다. 패널이 60 칸까지라 행의 주인인 경로를 덜 밀어내도록 짧게 둔다. 그래도 경로에 16 칸이 안 남으면 시각·출처를 빼고 결정만 보인다. 쓰는 기록은 그 키의 **마지막 기록이 지금 결정과 같은 동사일 때만**이다. 기록이 없는 결정(이 기능 전의 결정·로그를 못 쓴 결정·옛 빌드가 바꾼 결정)은 결정만 보인다. 남의 기록을 붙이지 않는다. 시각은 각 시점의 로컬 오프셋으로 바꾼다(서머타임 — `scm_dock.utcOffsetAt`). 「올해」 판정과 기록의 시각은 같은 시계(`trust_store.nowMs`)를 쓴다.

- **기록 조회**(TA2): 컨트롤 `lsp.trust.log {limit?}` 는 기록의 **최근 `limit` 건**(기본 50, 1..200)을 줄 순서대로 내고, 앞선 기록이 더 있으면 `more` 를 세운다. 읽기만 한다 — 기록을 고치거나 지우는 메서드는 없다. 관문은 다른 `lsp.trust.*` 와 같다(셀렉터 없는 연결만). 응답이 프레임 상한 근처(`cp.default_max_frame` − 16 KiB)를 넘으면 건수를 반씩 줄여 최근 것을 남긴다 — 경로의 제어 문자가 JSON 에서 여섯 배가 된다(적대적 검증 TA2 1회차).
- **CLI**(TA2): `maru editor lsp trust log [--limit n]` 은 한 줄에 「로컬 시각(`YYYY-MM-DD HH:MM:SS`) · 동작 · 출처 (pid 이름) · 저장소」를 찍는다. 시각은 각 기록 시점의 이 기계 오프셋이다(`main.zig` 의 `localtime_r`). 서버가 준 경로·목적지·이름의 제어 문자는 `?` 로 찍는다(목록·철회·잊기의 문구도 같다 — 적대적 검증 TA2 2회차).
- **상대**(TA2): 컨트롤의 철회·잊기는 그 요청을 보낸 소켓 상대를 남긴다. pid 는 `LOCAL_PEERPID`(그 소켓을 마지막으로 다룬 프로세스 — 연결 스레드가 프레임을 읽은 직후라 그것을 쓴 프로세스에 가장 가깝다, 1g 와 같은 한계)이고, 이름은 `proc_name`(실행 파일 이름, 32 바이트까지)이다. 이름을 못 읽으면 `?`, pid 를 못 읽으면 상대 칸은 `-` 다.

## 한계 (받아들인 것)

- 두 앱 인스턴스가 같은 순간에 돌리기(rename)를 하면 한쪽의 `.1` 내용을 잃을 수 있다. 감사 기록은 결정의 단일 출처가 아니라서 받아들인다.
- 이 기능 전의 결정에는 기록이 없다. 신뢰 파일에는 시각이 없어 거슬러 만들 수 없다.
- 상대 이름은 소켓을 연 프로세스의 이름이라, CLI 로 부르면 거의 늘 `maru` 다. 그 CLI 를 부른 쪽(셸·에이전트)은 남기지 않는다 — pid 로 그때의 프로세스를 짚을 수 있을 뿐이다(끝나면 사라진다).
- 시계를 되돌리면 기록의 시각도 되돌아간다. 줄의 순서가 시간 순서다.
- `.1` 로 옮기지 못하면(그 자리에 디렉터리가 있다) 지금 파일이 계속 자란다. 상한 + 한 줄을 넘은 파일은 읽기가 건너뛰어 목록 행에 시각이 안 붙는다. 결정에는 영향이 없다.
- 신뢰 파일을 못 읽은 실행(1 MB 초과·권한)에서도 기록은 남는다. 그 결정은 다음 실행에 사라지므로, 마지막 기록의 동사가 파일의 결정과 우연히 같으면 행이 그 실행의 시각을 보일 수 있다.

## 검증

- `TAL1`(순수): 줄 왕복(로컬·원격·잊기·상대), 거절할 모양(칸 수·동사·출처·시각·상대 경로·끊긴 줄의 `\t\n` 닫기). `TAL1b`: 상대 이름 다듬기(빈 이름·UTF-8 글자 경계).
- `TAL2`(순수): 키의 마지막 기록(줄 순서가 이긴다), 시각 표기(올해·다른 해·각 시점의 오프셋·자정과 해의 경계).
- `TAB1`(플랫폼): 결정·철회·잊기가 출처와 함께 남고 바뀌지 않은 답은 안 남음, 원격 키·상대, 끊긴 끝 닫기, 돌리기 두 번(`.1` 을 덮음·끊긴 채 옮긴 `.1` 뒤의 첫 줄), 0600, 두 파일을 잇다 할당이 실패해도 새지 않음. `LST8` 에 이관 줄(`migrate`)을 더했다.
- `LSPB43`(제품 경로): 시트의 답·관리 상자의 철회·컨트롤의 잊기가 각자의 출처로 남고(같은 답의 컨트롤 철회는 안 남음), 목록 행이 마지막 변경을 보이며(다른 해면 날짜만, 좁은 패널이면 결정만), 동사가 다른 기록은 붙지 않는다. `LSPB23`(소스 판정)이 부르는 자리마다의 출처 수와 목록이 표를 읽기만 함을 센다.

- `control_lsp_trust`(TA2 순수): 메서드 넷(부여 없음), 최근 `limit` 건·`more`·상대·원격 키·못 읽는 줄, params(`limit` 1..200 정수만), 예산을 넘으면 반씩 줄여 최근 것을 남김.
- `control_dispatch` WT4b 보강: `lsp.trust.log` 도 셀렉터 없으면 L4, 있으면 `unauthorized`, 틀린 `limit` 은 `invalid_params`.
- `cli/lsp_trust`(TA2): `log [--limit n]` 파싱·요청이 서버 해석기를 지남·서버 직렬화기 출력을 로컬 시각·출처·상대·원격 키로 찍음·`more` 안내·빈 기록, 제어 문자를 `?` 로(목록·기록·철회·잊기).
- `LSPB44`(제품 경로): 컨트롤 철회가 상대와 함께, 창 없는 잊기는 상대 없이 남고, `lsp.trust.log` 가 최근 둘과 `more` 를 내며 조회는 기록을 늘리지 않는다.
- `TA2 컨트롤 상대`(ABI): 실제 소켓(socketpair)에서 pid·이름, 닫힌 fd 는 상대 없음. `자기 프로세스의 실행 파일 이름`(`procName`).
- `WT4b live hello`: `lsp.trust.*` 넷을 광고. `LSPB23`: Op 넷·기록에 닿는 자리는 읽기 하나·컨트롤 출처는 상대와 함께.

## 적대적 검증 (5회)

1. 좁은 화면 — 상세 칸(「거부 · 2026-10-12 14:03 · 신뢰 시트」 35 칸)이 60 칸 패널에서 경로를 19 칸으로 밀어냈다. → 올해는 `MM-DD HH:MM`·다른 해는 날짜만으로 줄이고, 경로가 16 칸 아래면 결정만 보인다(고침, 변이 A13 이 잡는다).
2. 문서 정합성 — 계약·계획의 시각 표기가 1회차 수정과 어긋났고, 상대 칸을 「지금 적는 것」처럼 읽히게 적었다(고침).
3. 수명·누수 — `readLog` 가 메모리 부족에서 `return null` 로 나가 `errdefer` 가 안 돌아 버퍼가 샜다. → 오류 반환 함수로 나눴다(고침, 할당 실패 주입 판정자 — 변이 A27 이 잡는다).
4. 판정자의 우연 — 목록 행의 「올해」 판정을 주입 시계 대신 실제 시계로 바꿔도 오늘이 2026 년이라 통과할 자리였고, 끊긴 줄로 끝난 `.1` 이 없어 두 파일 사이 닫기를 지워도 살아남을 자리였다. → 다른 해 장면과 끊긴 채 옮기는 장면을 더했다(변이 A14·A10 이 잡는다).
5. 기록 자리의 빈틈 — 결정이 바뀌는 길을 전수로 봤다(시트·SCM 시트·원격 시트는 `answerTrust` 하나, 관리 상자, 컨트롤, 하니스, 이관). `touch`·`rekeyRoot`·`load` 는 결정을 바꾸지 않는다. 표를 못 적는 키(탭이 든 경로)는 기록도 못 적는다(같은 키 규칙). 결함 없음.

TA1 변이 27개 — 모두 잡혔다. 그중 여섯(A1·A3·A11·A19·A21·A22)은 처음에 컴파일 오류로만 죽어 의미 변이로 다시 써 돌렸다.

## 적대적 검증 (TA2, 5회)

1. 응답 크기 — 경로의 제어 문자는 JSON 에서 `\u00XX` 로 여섯 배라, 상한 건수로도 프레임 상한 1 MiB 를 넘어 CLI 가 응답을 통째로 거절할 수 있었다. → 예산을 넘으면 건수를 반씩 줄인다(고침).
2. 터미널 출력 — CLI 가 서버가 준 경로를 그대로 찍어, 경로의 ESC 가 사용자 터미널을 조종할 수 있었다(TA1 이전의 `list` 와 철회·잊기 문구에도 있던 구멍). → 제어 문자를 `?` 로(고침).
3. 수명 — 상대 pid 는 메인이 응답하기 전, 연결 스레드가 기다리는 동안 읽으므로 fd 가 닫히거나 재사용되지 않는다(결함 없음).
4. 문서 정합성 — 메서드 표·보안 문서·CLI 명령 목록 넷(개발 명령·프로젝트 구조·`maru editor open` 계획·CLI 감사)·계약에 `log` 를 더했다(결함 없음 — 이 PR 안에서 맞췄다).
5. 권한 — 기록 조회는 같은 uid 의 셀렉터 없는 연결만 연다. 기록이 드러내는 것(저장소 경로·프로세스 이름)은 같은 uid 가 파일로 이미 읽을 수 있다. 셀렉터를 댄 연결은 `unauthorized` 다(결함 없음).

TA2 변이 21개 — 모두 잡혔다(B4 는 처음 문법 오류로만 죽어 의미 변이로 다시 써 돌렸다).
