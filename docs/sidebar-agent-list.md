# 사이드바 에이전트 목록(워크스페이스 카드 하위 목록)

이 문서는 왼쪽 워크스페이스 사이드바의 **카드 하위 에이전트 목록**과 그에 따른 **카드 동적 높이**의 단일 출처다.
카드 자체의 줄 구성(이름·브랜치·경로)은 [탭·split·레이아웃 전략](tabs-splits-layout.md)이, 에이전트 **상태 판정**은
[에이전트 세션 관측](agent-session.md)이, 그룹 헤더·접힘 행 모델은 [사이드바 그룹 전략](sidebar-groups.md)이
각각 단일 출처다. 이 문서는 그 셋 위에 "한 워크스페이스가 들고 있는 **에이전트들**을 어떻게 나열·조작하는가"만 얹는다.

## 1. 목표 UX

워크스페이스 카드가 지금은 에이전트를 **탭당 대표 1개**로 압축해 보여준다(제목 옆 아이콘 + 4번째 상태줄). 한
워크스페이스에서 에이전트를 둘 이상 돌리면 나머지는 화면에 존재하지 않는다. 목표는 그 압축을 풀어 **그 워크스페이스가
들고 있는 모든 에이전트를 카드 하위 목록으로** 드러내는 것이다.

```
● fix/pc-seller-delivery-port-re…        [기본]
  ⎇ fix/pc-seller-delivery-port-recovery
  ┌─────────────────────────────────┐
  │ 2 agents                      ⌄ │      ← 2개 이상일 때만. 클릭하면 접힘/펼침
  └─────────────────────────────────┘
    ✓ ✶ hi                        just now  ← 마지막 사용자 프롬프트 + 마지막 활동 시각
        안녕하세요! PC 셀러 프로젝트…          ← 마지막 에이전트 응답(흐린 색)
    ✓ ✶ 22                        just now
        "22"만으로는 무엇을 원하시는지…
```

- **에이전트가 없으면** 카드는 지금과 같다(이름 + 브랜치 + 경로, 1~3줄).
- **1개면** 토글 없이 행 하나만 붙는다.
- **2개 이상이면** `N agents` 토글 행이 먼저 오고 그 아래 행들이 붙는다. 기본은 **펼침**이다 — 접기는 카드가 길어질 때
  사용자가 선택하는 것이고, 기본을 접힘으로 두면 이 기능의 목적(안 보이는 에이전트를 드러내기)이 첫 화면에서 무효가 된다.
- **행을 누르면** 그 에이전트가 도는 자리로 이동한다(§5).
- 카드 높이는 이 내용에 따라 **행마다 다르다**(§3).

**베이스/결정**: 이 배치는 Maru 독립 설계다. 카드 안에 접이식 하위 목록을 두는 형태 자체는 흔한 UI 관용이고, 여기서의
결정은 (1) **압축 대신 전수 나열**, (2) **1개일 때 토글 생략**, (3) **기본 펼침** 셋이다. 셋 다 "안 보이는 실행 중
에이전트를 없는 것처럼 만들지 않는다"는 같은 목적에서 나왔다.

## 2. 무엇을 나열하는가 — Term 단위 전수

**Term 하나가 행 하나다.** 에이전트 감지는 Term의 PTY 포그라운드 프로세스로 이뤄지므로(`pollAgentKinds`·`classifyAgent`)
`agent_kind`/`agent_state`는 Term마다 붙는다. 그 워크스페이스의 **모든 Pane × 모든 Term**을 훑어 `agent_kind != .none`인
Term을 전부 행으로 만든다.

Pane 단위로 묶지 않는 이유: Pane은 여러 Term을 가로 탭으로 담고 **활성 Term 하나만 화면에 그린다**. Pane당 대표 하나만
내면 같은 Pane의 가려진 탭에서 도는 에이전트가 목록에서 사라진다 — 화면에 안 보이는 에이전트를 드러내는 것이 이 기능의
목적이므로 그 압축은 목적과 정면으로 충돌한다. **화면에 보이지 않아도 PTY도 프로세스도 살아 있다**는 사실을 목록이
그대로 반영해야 한다.

정렬은 **트리 순서**(Pane 순회 → Pane 안 Term 순서)를 쓴다. 상태나 시각으로 재정렬하면 같은 자리의 에이전트가 상태
변화마다 목록에서 튀어 클릭 대상이 흔들린다.

**기존 대표 표시는 제거한다.** 제목 옆 대표 아이콘과 4번째 상태줄(파형/✓)은 이 목록으로 **대체**된다(사용자 결정).
같은 정보가 두 곳에 서로 다른 형태로 나오면 어느 쪽이 권위인지 알 수 없고, 대표 하나를 고르는 규칙
(`tabAgentRepresentative`의 blocked > running > idle > unknown 우선순위)도 목록 앞에서는 의미가 없다.

## 3. 행 모델과 동적 높이

사이드바는 이미 **가변 높이 행**을 다룬다. `sidebar.Row`가 union이고 `rowHeight`/`rowTop`/`slotAt`/`contentHeight`가
고정 나눗셈이 아니라 **행 높이 누적**으로 좌표를 환산한다(그룹 헤더가 카드보다 낮은 것을 이 방식으로 이미 처리한다).
따라서 카드 높이를 카드마다 다르게 만드는 것은 새 메커니즘이 아니라 **기존 프리미티브의 확장**이다.

`Row`에 두 종류를 더한다.

| Row | 내용 | 높이 |
| --- | --- | --- |
| `card` | 기존(이름·브랜치·경로) | **줄 수로 계산**(고정 slot 폐기) |
| `agent_toggle` | `N agents` + 접힘 표시. 소속 tab 인덱스 | 얇은 한 줄 |
| `agent` | 상태·kind·라벨·시각 + (대화 보강 시) 응답 줄 | 1줄 또는 2줄 |

카드 높이가 고정 `card_slot_h`에서 **줄 수 기반**으로 바뀌는 것이 이 슬라이스의 핵심 변경이다. 지금은 브랜치·경로줄이
없어도(git repo 밖) 슬롯 높이가 그대로라 빈 공간이 남는다. 줄 수 기반으로 바꾸면 그 낭비가 사라지고 에이전트 행도 같은
규칙으로 얹힌다.

**불변식**: `rowTop`/`slotAt`/`contentHeight`는 이 세 종류를 모두 누적 대상으로 다뤄야 한다. 하나라도 빠지면 클릭 좌표와
렌더 좌표가 어긋나 "보이는 곳과 눌리는 곳이 다른" 회귀가 난다(그룹 헤더 도입 때 이미 겪은 클래스).

## 4. 접기 상태

토글 상태는 **워크스페이스(Tab)에 저장**한다 — 그룹의 `group_collapsed`와 같은 자리, 같은 수명이다. workspace 파일에
영속하지 않는다: 에이전트 구성은 세션마다 달라지고(어제 2개, 오늘 0개), 접힘 상태만 남으면 복원 후 빈 토글이나 어긋난
상태가 된다. **파생 상태는 영속하지 않는다**는 기존 규율(에이전트 아이콘·상태와 동일)을 그대로 따른다.

에이전트가 1개 이하로 줄면 토글 행 자체가 사라지므로 저장된 접힘 값은 무시된다(다시 2개가 되면 기본 펼침).

## 5. 클릭 라우팅

에이전트 행을 누르면 **세 단계**로 그 자리에 도달한다.

```
1. 그 Term이 속한 워크스페이스로 전환   (다른 카드였다면)
2. 그 Term이 속한 Pane으로 포커스        focusPaneByPtr
3. 그 Pane 안에서 그 Term 탭 활성화       focusTerm
```

셋 다 기존 함수가 있다. **3단계가 핵심**이다 — Pane까지만 이동하면 그 Pane의 현재 활성 탭이 보일 뿐, 사용자가 목록에서
지목한 에이전트는 여전히 가려진 탭에 있다.

행이 가리키는 Term이 사이 tick에 사라졌을 수 있다(사용자가 닫음·프로세스 종료). 행은 **Term 포인터가 아니라 인덱스
경로(tab/pane/term)** 를 들고, 클릭 시점에 재조회해 유효하지 않으면 무동작한다(stale 포인터 deref 금지 — 사이드바 드래그
경로에서 이미 겪은 UAF 클래스).

토글 행 클릭은 접힘만 바꾸고 포커스를 옮기지 않는다.

## 6. 렌더 경계

현재 `buildSidebarDrawList`는 `names`/`branch_lines`/`path_lines`/`status_lines` **고정 4배열**을 row 인덱스로 병렬
색인한다. 카드 한 장이 최대 4줄이라는 가정이 인터페이스에 박혀 있어 가변 개수의 에이전트 행을 실을 수 없다.

**행 목록으로 일반화한다**: 카드/토글/에이전트를 구분하지 않고 `{ 소속 row, 들여쓰기, 텍스트, 역할(색), 선행 아이콘 }`의
평탄한 줄 배열을 넘기고, row별 시작 인덱스와 개수를 함께 준다. 렌더러(.m)는 지금처럼 "row 안 몇 번째 줄"만 알면 되고,
줄 수 상한이 인터페이스에서 사라진다.

색·아이콘은 지금 규율을 유지한다 — kind는 브랜드색(claude 코랄 / codex 청록), 상태는 별도 표현, 대화 텍스트는 흐린 색.
글리프는 **터미널 폰트가 보유한 것만** 쓴다(미보유 코드포인트는 CoreText fallback으로 넘어가 글리프가 어긋난다 — 기존
아이콘 선정에서 이미 겪은 문제).

## 7. 마지막 대화 보강

행에 **마지막 사용자 프롬프트**와 **마지막 에이전트 응답**을 함께 보여준다. 이 데이터는 화면이 아니라 각 CLI가 남기는
**세션 기록 파일**에서 읽는다.

**왜 화면이 아닌가**: 상태 판정(`❯` 프롬프트, `esc to interrupt` 같은 짧은 마커)과 달리 대화 **본문**을 화면 위치로 뽑는
것은 프롬프트 박스 테두리·줄바꿈·들여쓰기에 훨씬 민감하다. 더 결정적으로, `/clear`를 하거나 응답이 길어 프롬프트가 스크롤
밖으로 밀리면 그 텍스트는 **화면에 존재하지 않는다**. 화면은 대화의 렌더 결과이지 대화가 아니다.

**왜 훅이 아닌가**: 세션 파일과 Term을 잇는 데 provider 훅(사용자 config 수정)이 필요하지 않다는 것을 실측으로 확인했다
(§7.2). 훅은 사용자의 provider 설정 파일을 Maru가 고쳐 쓰고 설치·제거·자가정리를 유지해야 하며, 사용자가 그 설정을
손대면 조용히 깨진다. 그 비용을 치를 만한 정확도 이득이 없다.

### 7.1 계약

1. **선택적 보강이다.** 매핑·파싱에 실패해도 행은 아이콘·상태·시각으로 정상 동작하고, 대화 줄만 비운다. 이 계약이 없으면
   provider가 포맷을 바꿀 때 목록 전체가 죽는다.
2. **프로세스에서 파일을 추론하지 않는다.** "그 Term이 출력한 시점에 갱신된 파일"을 매번 따라간다. **매핑을 고정하지
   않는다**(§7.2 반증 2).
3. **스캔 범위를 좁힌다.** provider별로 서브에이전트 기록을 반드시 배제한다(§7.3).
4. **tail만, mtime 변화 시에만, throttle.** 파일 전체를 파싱하지 않는다.

### 7.2 매핑 — 실측으로 확정한 것

설계 후보 셋을 실제 데이터로 검증했고, **둘이 반증됐다**.

| 후보 | 결과 |
| --- | --- |
| 프로세스 시작 시각 ↔ 세션 시작 시각 매칭 | ❌ **반증**. `--continue`/`--resume`이 흔해 프로세스는 방금 떠도 파일 시작은 며칠 전이다. 정답을 아는 프로세스로 대조해 **틀린 세션을 고르는 것**을 확인했다(차이 -2.3일까지 관측). |
| 매핑을 한 번 확정하고 고정 | ❌ **반증**. `/clear`로 **같은 프로세스가 세션 파일을 갈아탄다**(같은 pid가 파일 A로 대화하다 파일 B로 이동). 고정하면 그 시점부터 영원히 옛 대화를 보여준다. |
| 활동 상관(그 시점에 갱신된 파일) | ✅ 채택 |

활동 상관이 성립하는 근거도 실측했다.

- **유휴 세션은 스스로 갱신되지 않는다.** 최근 활동 세션 21개를 60초 관찰해 갱신된 파일은 **활동 중인 1개뿐**이었다.
  하트비트 같은 배경 쓰기가 없으므로 "갱신됨 = 그 세션이 방금 말했다"가 성립한다.
- **교대 입력을 정확히 추적한다.** 같은 작업 디렉터리에 세션 둘을 두고 번갈아 입력하며 매 시점의 최신 파일을 정답과
  대조했다 — **claude 4/4, codex 3/3**.
- **동시 활동도 갈린다.** 두 세션을 동시에 돌려도 실제 파일 쓰기 시점은 1.6초 벌어졌고, 파일 mtime은 **나노초 해상도**다.
- **재개는 같은 파일에 append된다**(양쪽 CLI). 세션이 이어질 때 파일이 새로 생기지 않으므로 추적이 끊기지 않는다.

고정하지 않고 매번 따라가는 방식은 `/clear`·resume·재시작에 **자동으로 적응**하며 상태를 덜 든다.

### 7.3 provider 어댑터

`agent_observer`가 provider별 규칙 집합을 두는 것과 같은 패턴으로, **경로 규칙 + 레코드 파서 + 서브에이전트 배제**를
provider마다 둔다. 위쪽(행 모델·렌더·throttle)은 공통이다.

| | claude | codex |
| --- | --- | --- |
| 경로 | 작업 디렉터리를 인코딩한 디렉터리 아래 세션 파일 | 날짜 계층 아래 세션 파일 |
| 작업 디렉터리 판별 | 디렉터리 이름으로 즉시 | 파일을 열어 첫 레코드에서 읽어야 함 |
| **서브에이전트 배제** | 서브에이전트는 `<세션 id>/` **하위 디렉터리**에 쌓인다 → **직속 파일만** 스캔 | 서브에이전트가 **같은 계층에 섞인다** → 첫 레코드의 세션 출처 필드가 사용자 세션인 것만 |
| 대화 추출 | 사용자/어시스턴트 레코드의 텍스트 블록 | 응답 레코드의 role + content |

**서브에이전트 배제는 선택이 아니라 필수다.** 실측에서 한 작업 디렉터리의 직속 파일이 54개인데 하위까지 포함하면
**1805개**였고, 서브에이전트 기록이 거의 항상 더 최근이다. 배제하지 않으면 사용자 카드에 서브에이전트 내부 대화가 뜬다
(검증 중 실제로 이 오류를 재현했고, 그 덕에 이 제약을 찾았다).

### 7.4 성능

| 측정 | 값 |
| --- | --- |
| claude: 작업 디렉터리(54개)에서 최신 파일 찾기 | 0.14ms |
| codex: 최근 파일 20개만 열어 판별 | 1.3ms (전량 233개 파싱은 82ms — 61배) |
| 대용량 파일 읽기 | 47MB 파일도 **끝 256KB**만 |

Term 8개 기준 매 tick 스캔해도 1.1ms지만 **tick마다 할 이유가 없다**. mtime이 변한 파일만, throttle을 두고 읽는다.
관측 주기 규율은 [에이전트 세션 관측](agent-session.md)의 polling 정책을 따른다.

## 8. 관측 가능성

- 매핑 결과(어느 Term ↔ 어느 세션 파일)와 확정/미확정 여부를 `MARU_DEBUG` 게이트 아래 남긴다. **대화 본문·작업
  디렉터리 경로는 로그에 남기지 않는다**([필수 프로젝트 규칙](project-rules.md)의 redaction 기준 — 홈 경로가 그대로 드러난다).
- 목록 자체는 기존 observer 스냅샷을 소비한다. 사이드바 전용 상태 판정을 새로 만들지 않는다.

## 9. 단계 분해

각 단계가 독립적으로 동작하고, 3단계까지만 해도 사용자에게 쓸모가 있다(대화 텍스트 없이 목록·이동만으로도 목적 달성).

1. **문서**(이 PR) — 계약과 경계 확정.
2. **동적 높이** — 카드 높이를 줄 수 기반으로. 에이전트 행 없이 기존 카드만으로 회귀 없음을 먼저 고정한다.
3. **에이전트 행 목록** — Term 전수 나열, `N agents` 토글, 클릭 라우팅(워크스페이스 → Pane → Term), 기존 대표 표시 제거.
4. **claude 어댑터** — 매핑(활동 상관·직속 스캔) + 대화 추출 + 행 2줄 렌더.
5. **codex 어댑터** — 경로/파서/서브에이전트 필터 차이만 흡수.

## 10. 검증

- **행 모델**: 에이전트 0/1/2+ 각각에서 `rowTop`·`slotAt`·`contentHeight`가 일치하는지(보이는 곳 = 눌리는 곳).
- **클릭 라우팅**: 가려진 Term(비활성 Pane의 비활성 탭)을 지목했을 때 3단계가 모두 수행되는지. 사라진 Term을 가리키는
  행이 무동작인지.
- **접기**: 2개 이상에서만 토글이 생기고, 1개 이하로 줄면 사라지는지. 영속되지 않는지.
- **매핑**: fixture 기반 — 유휴 파일 무시, 교대 활동 추적, `/clear`로 파일이 바뀌었을 때 새 파일을 따라가는지,
  서브에이전트 기록이 후보에서 배제되는지.
- **degrade**: 세션 파일이 없거나 포맷이 달라도 행이 아이콘·상태·시각으로 정상 동작하는지.

## 11. 범위 밖

- 대화 **전체 이력** 표시. 마지막 교환 한 쌍만 보여준다.
- provider 훅 설치·관리(§7 "왜 훅이 아닌가").
- 에이전트 상태 판정 규칙 변경 — [에이전트 세션 관측](agent-session.md)이 단일 출처다.
