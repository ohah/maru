# `src/platform/macos`

macOS 전용 bridge를 담는 폴더다.

초기 후보 책임은 AppKit host, Metal surface, CoreText font access, openpty-backed PTY, clipboard, IME, accessibility다. PTY 운영은 [문서](../../../docs/pty-operating-model.md)를 따른다.

현재 `*.m` 파일들은 제품 UI가 아니라 smoke bridge다. 얇은 C ABI로 Zig에서 AppKit/Metal/CoreText의 저수준 경계를 검증하기 위해 Objective-C로 둔다. Swift는 실제 macOS app host를 시작할 때 도입한다. 그때 대상은 지속 실행되는 `NSApplication`, window/tab/split lifecycle, menu/command, preferences, IME/accessibility/focus/input routing 같은 제품 UX 영역이다. Swift app host가 생겨도 기존 Objective-C smoke는 low-level regression smoke로 남긴다.

`app_host_abi.h`와 `app_host_abi.zig`는 제품 Swift host가 Zig에 호출할 C ABI의 첫 고정점이다. Swift는 이 header의 fixed-width DTO만 보고 key/resize/close 같은 app event를 넘기며, Zig는 `PtySession`, `SurfaceRuntime`, `FrameLoop`, renderer resource를 계속 소유한다. `app_session.zig`는 Swift가 opaque handle로만 보유하는 Zig app session을 만든다. 이 session은 heap에 고정되어 `LivePtySession`, shell surface, `RuntimeEventPump`, `FrameLoop`, `RendererState`를 소유한다. `MaruAppHost.swift`는 `mise run macos-app`로 실행되는 Swift `NSApplication` app shell이다. 현재는 Zig ABI static library를 링크하고 placeholder window lifecycle을 검증하면서, summary에 `terminal_surface=true`와 frame/output/input/resize/close 통계를 남긴다. 아직 Swift window 안에 Metal terminal view를 붙이지 않았으므로 화면은 placeholder이고, resize cell 수는 placeholder 추정값이다. 실제 macOS 제품 앱 경계는 [문서](../../../docs/macos-app-host-boundary.md)를 따른다.

`coretext_probe.zig`는 smoke native ABI의 결과/record shape와 probe category 해석을 소유한다. 이 파일은 제품 shaper가 아니라 `coretext_smoke.m`이 만든 고정 C record를 `coretext_font.zig`가 받을 수 있는 record로 바꾸는 probe 경계다. 이 경계를 따로 둔 이유는 다음 Metal/CoreText 화면 smoke가 `coretext_smoke.zig`의 summary code를 import하거나 같은 category/font-name 변환을 다시 쓰지 않게 하기 위해서다.

`coretext_font.zig`는 smoke 전용 Objective-C ABI가 아니라 제품 macOS font backend 후보 경계다. CoreText가 선택한 glyph id와 PostScript font name을 renderer 중립 `ShapedGlyphRecord`로 바꾸고, 실제 bitmap을 만들 drawable glyph만 `FontIdentityRegistry`에 intern한다. 이 파일이 필요한 이유는 `coretext_smoke.zig` 안에 font identity 규칙을 계속 두면 다음 제품 shaper가 smoke 파일을 의존하거나 같은 규칙을 복제하게 되기 때문이다.

`coretext_shaper.zig`는 CoreText가 이미 만든 glyph record 배열을 제품 renderer의 `GlyphRunList`로 바꾸는 제품 후보 shaper 경계다. 이 모듈은 CoreText runtime을 직접 호출하지 않고, `coretext_font.zig -> FontIdentityRegistry -> ShapedGlyphRecord -> GlyphRunList` 변환과 `ShapedGlyphSurface` metadata 보존만 맡는다. 제품 경로에서는 실제 `DrawList`의 size/cursor/dirty/overlay를 넘겨야 하고, smoke처럼 DrawList가 없는 probe만 `deriveProbeSurfaceFromCoreTextGlyphs`를 사용한다.

현재 native DrawList shaper에는 cell 단위 경계 검증에서 비롯된 두 가지 알려진 한계가 있다. 첫째, native bridge는 한 cell이 여러 glyph(예: base + combining mark, ligature)로 분해되면 그 glyph마다 record를 만들되 모두 같은 `(row, col)`을 부여한다. 따라서 결합 문자/리거처 cell은 같은 격자 위치에 glyph가 겹쳐 그려지고, line-level shaping/cluster 위치 보정은 아직 다루지 않는다. 둘째, 한 cell이라도 `.notdef`(glyph 0)로 매핑되면 native가 `missing_glyph_count`를 올려 최종 status를 실패로 닫고, Zig shaper는 `CoreTextDrawListShapeFailed`로 프레임 전체를 버린다. 즉 임의의 셸 출력에 폰트+fallback 체인에 없는 코드포인트가 하나라도 들어오면 해당 cell만 tofu로 그리는 게 아니라 frame 전체가 실패한다. 현재 fixture(`"Maru 한"`)는 두 경우를 모두 트리거하지 않으며, 둘 다 line-level shaper 단계에서 다룬다.

`coretext_raster.zig`는 renderer의 `GlyphRasterRequest`를 macOS CoreText glyph bitmap으로 바꾸는 제품 후보 rasterizer 경계다. 이 모듈은 native CoreText를 직접 링크하지 않고 함수 포인터 bridge를 주입받아, 기본 Zig 테스트에서는 FontId -> PostScript name 조회와 `RasterizerFailed` 매핑만 검증한다. 현재 실제 native glyph bytes는 `coretext_smoke.m`의 smoke bridge가 공급하지만, 제품 renderer가 나중에 같은 wrapper를 재사용할 수 있게 smoke 파일 안에 rasterizer 정책을 두지 않는다. native가 glyph를 그렸지만 non-clear pixel이 없는 zero-ink 결과(status 7)는 실패가 아니라 renderer의 `zero_ink_uploads`로 회계되는 정상 결과이므로, 이 경계가 zero-ink를 `non_clear_pixels=0` 성공으로 닫는다. 나머지 non-zero status만 공통 `RasterizerFailed`로 매핑한다.

`coretext_frame_builder.zig`는 active `AppWindow` surface를 macOS CoreText 기반 `AppHostFrame`으로 조립하는 제품 후보 경계다. `FrameLoop`는 CoreText를 import하지 않고 순서만 소유하며, 이 builder가 `TerminalCore snapshot -> DrawList -> CoreTextDrawListShaper -> CoreTextGlyphRasterizer -> RendererState -> RenderFrame` 변환을 맡는다. 이 파일이 필요한 이유는 live PTY Metal smoke 안에 frame builder를 계속 두면 이후 Swift/AppKit host가 같은 조립 규칙을 재사용하지 못하고 smoke 코드를 의존하거나 복제하게 되기 때문이다. 기본 Zig 테스트는 native Objective-C bridge 없이 fake shape/raster 함수 포인터를 주입해 active surface, drain summary, process state, prepared RenderFrame 계약을 고정한다. `FrameLoop` 단위 테스트는 같은 주입형 builder가 output, key input 뒤 output, idle, exit tick을 같은 `RendererState`로 반복 처리할 수 있음도 고정해, 지속 실행되는 제품 host가 별도 frame 조립 경로를 만들지 않게 한다.

native single-glyph rasterizer(`coretext_smoke.m`)는 `CTLineDraw` 경로와 달리 y-flip CTM을 적용하지 않는다. `CTFontDrawGlyphs`가 이 `CGBitmapContext`에서 이미 Metal upload가 기대하는 top-to-bottom memory order로 그리기 때문이다. 두 raster 경로의 좌표 규약이 다르고 이 차이는 현재 주석으로만 묶여 있으며, Metal numeric readback은 동일 source bytes를 비교하므로 source bitmap이 통째로 뒤집힌 경우를 자동으로 잡지 못한다. 제품 renderer(`maru_metal_renderer.m`)에는 이제 `MARU_SCREENSHOT=<path>` env로 한 frame을 오프스크린 텍스처에 그려 PPM artifact로 남기는 screenshot 경로가 있다(`MARU_SCREENSHOT=/tmp/maru.ppm mise run macos-app`). 창의 CAMetalLayer drawable은 `framebufferOnly=true`라 직접 readback할 수 없어 같은 크기·픽셀포맷 오프스크린 텍스처에 그린 뒤 blit readback한다. PPM writer는 smoke와 같은 `maru_ppm_writer.h` 단일 출처를 공유한다. 이로써 제품 renderer 출력을 사람이 눈으로 확인할 수 있다. 다만 좌표 규약을 한 helper로 모으는 것과 이 artifact를 골든 이미지와 비교해 시각 회귀를 **자동** 검출하는 단계는 아직 후속 과제다.

`window_smoke.zig`와 `appkit_window_smoke.m`은 첫 visible UI smoke다. 이 경로는 실제 터미널 화면이나 Metal renderer를 검증하지 않고, macOS window server와 AppKit lifecycle에 접근할 수 있는지만 확인한다. 계약 테스트는 `mise run test-macos-window-smoke`, 실제 창 smoke는 `mise run macos-window-smoke`다.

`metal_smoke.zig`와 `appkit_metal_smoke.m`은 첫 Metal 제품 atlas shader sampling smoke다. 이 경로는 실제 `TerminalCore -> DrawList` fixture를 `CoreTextDrawListShaper` native bridge로 shape한 뒤 `RendererState -> RenderFrame -> coretext_raster.zig` 경로에 태우고, 제품 `RenderFrame`이 소유한 `GlyphQuadFrame`의 slot-backed 셀과 UV를 AppKit 창 위 CAMetalLayer에 올린다. 제품 `GlyphRasterFrame.uploads/pixels`는 CoreText rasterizer가 만든 glyph bitmap bytes이며, Metal `RGBA8Unorm` atlas texture에 업로드한 뒤 fragment shader가 그 atlas를 샘플링한다. smoke는 atlas upload/readback byte 비교가 성공하면 `product_atlas_uploaded=true`, source raster 안에서 고른 non-clear texel이 drawable readback에서도 같은 색으로 보이면 `product_atlas_sampled=true`를 남긴다. `glyph_text`는 별도 라벨이 아니라 `product_atlas_sampled`(샘플링 증거)이고 그 fixture가 실제 CoreText glyph bytes를 쓴 경우에만 참이다. 즉 rasterizer가 빈 bitmap으로 퇴화하거나 샘플링이 실패하면 `glyph_text`도 자동으로 거짓이 되어, 라벨이 스스로의 증거 없이 "CoreText glyph를 화면에서 봤다"고 단정하지 않는다. 같은 drawable 전체를 PPM screenshot으로 쓰면 `screenshot_artifact=true`와 `screenshot_path=zig-out/maru-macos-metal-smoke/metal-frame.ppm`도 남긴다. source texel을 찾지 못한 visible cell은 readback 실패가 아니라 `atlas_sample_missing_cells`로 기록한다. upload가 0개인 all-skip frame도 GPU 인프라 실패가 아니라 visible cell의 sample source 누락으로 분리한다. summary에는 `renderer_input=terminal_core_draw_list`, `renderer_shaper=coretext_draw_list`, `renderer_rasterizer=coretext_glyph_rasterizer`, `renderer_frame_prepared=true`, `renderer_atlas_slot_placement=true`, `renderer_glyph_uv_ready=true`, `renderer_glyph_raster_ready=true`, `product_atlas_uploaded=true`, `product_atlas_sampled=true`, `screenshot_artifact=true`, glyph/atlas/raster/screenshot 통계가 남는다. 계약 테스트는 `mise run test-macos-metal-smoke`, 실제 Metal smoke는 `mise run macos-metal-smoke`다.

`app_pty_metal_smoke.zig`는 headless `app-pty-smoke`와 visible `metal_smoke.zig` 사이의 첫 연결 smoke다. controlled command의 실제 PTY output을 `PtyReader -> RuntimeEventPump -> SurfaceRuntime -> FrameLoop -> coretext_frame_builder.zig(active AppWindow surface -> TerminalCore -> DrawList -> CoreTextDrawListShaper -> CoreTextGlyphRasterizer -> RendererState -> GlyphQuadFrame/GlyphRasterFrame) -> appkit_metal_smoke.m` 경로로 넘기고, 실제 AppKit/CAMetalLayer 창과 `app-pty-metal-frame.ppm` screenshot artifact로 확인한다. smoke는 기본적으로 AppKit synthetic `keyDown:`을 같은 Metal terminal window에 전달한 뒤, 그 native key payload를 `FrameLoop.handleKeyEvent -> KeyBindingResolver -> SurfaceRuntime.writeInput`으로 보내 terminal input bytes가 같은 화면 경로로 되돌아오는지도 확인한다. keyDown 수집용 ready frame은 별도 `RendererState`로 만들어 final frame의 glyph atlas cache를 오염시키지 않고, key input 뒤 최종 frame은 제품 후보 `FrameLoop.tickAfterDrainWithFrameBuilder -> coretext_frame_builder.zig` 경로로 만든다. 마지막 frame 뒤에는 같은 Metal terminal window의 AppKit close delegate가 Zig callback을 호출하고, callback은 `FrameLoop.closeActiveLivePty -> host.closeActiveLivePty -> LivePtyRegistry.closeActive -> LivePtySession.closeAndDetach`로 내려가 active surface/link 검증, registry mapping 제거, runtime detach, late output/input 거부를 확인한다. `MARU_APP_PTY_METAL_KEYDOWN_SOURCE=manual`을 명시하면 사용자가 같은 Metal terminal window에서 직접 누른 `Cmd+B` payload를 같은 resolver 경로에 태운다. `MARU_APP_PTY_METAL_SCENARIO=interactive-shell` 또는 `mise run macos-app-pty-interactive-metal-smoke`는 같은 executable을 실제 `$MARU_INTERACTIVE_SHELL` 또는 `$SHELL -i`로 실행하고 marker command와 `exit`를 shell에 보내, dotfile/prompt 영향을 받는 shell도 visible renderer까지 한 번 통과하는지 확인한다. summary에는 `renderer_input=surface_runtime_live_pty_frame_loop_coretext_render_frame`, `interactive_shell`, `frame_loop_ticks`, `frame_loop_final_tick_index`, `frame_loop_final_ended`, `close_lifecycle=appkit_terminal_window_close_callback_after_visible_frame`, `native_close_*`, `terminal_close_*`, `terminal_window_closed`, `close_surface_detached`, `close_registry_unregistered`, `input_source=appkit_keydown_to_app_host_keybinding_resolver`, `native_key_event_source=metal_terminal_synthetic_keydown` 또는 `metal_terminal_manual_keydown`, raw/screen/snapshot artifact, PTY 종료 정보, Metal atlas upload/sample/screenshot gate가 함께 남는다. 이 smoke는 실제 PTY bytes와 같은 Metal terminal window의 AppKit `keyDown:`에서 온 keybinding-resolved terminal input bytes가 보이는 UI까지 도달하고 같은 terminal window close delegate callback도 app host close action을 호출한다는 증거이고, manual mode는 물리 키보드 한 번까지 확인한다. interactive shell mode도 아직 사용자가 계속 타이핑하는 제품 event loop나 제품 tab/window close button 검증은 아니다. 계약 테스트는 `mise run test-macos-app-pty-metal-smoke`, controlled visible smoke는 `mise run macos-app-pty-metal-smoke`, 실제 shell visible smoke는 `mise run macos-app-pty-interactive-metal-smoke`다.

`coretext_smoke.zig`와 `coretext_smoke.m`은 첫 CoreText font shaping/renderer-frame/raster smoke다. 이 경로는 창과 GPU를 만들지 않고 default raw config를 `ResolvedAppearance`로 검증한 뒤, 그 font family/size 요청을 CoreText bridge로 넘긴다. CoreText는 요청 font를 먼저 시도하고, 실제 결과의 family/PostScript/full name이 요청과 맞지 않으면 macOS system monospace/Menlo fallback으로 물러난다. `requested_font_matched`는 요청 font가 설치되어 실제로 쓰였는지 보는 진단값이다. 그 다음 ASCII/CJK/emoji probe 문자열이 glyph run으로 shape되는지 확인한다. glyph count만 보지 않고 각 probe 구간이 `.notdef`가 아닌 glyph로 매핑됐는지도 확인한다. 그 다음 CoreText glyph id/font face 후보를 `coretext_probe.zig`, `coretext_font.zig`, `coretext_shaper.zig`, `coretext_raster.zig`의 adapter로 넘겨 renderer 중립 `ShapedGlyphRecord -> GlyphRunList -> RendererState -> RenderFrame -> GlyphRasterFrame` 경로에 넣고, atlas/UV/raster 준비 후보가 만들어지는지도 확인한다. 추가로 실제 `TerminalCore -> DrawList` fixture를 `CoreTextDrawListShaper` native bridge로 shape해 같은 `RendererState -> RenderFrame -> GlyphRasterFrame` 준비 경로에 넣는다. `coretext_raster.zig`가 같은 PostScript name으로 native smoke bridge를 호출해 제품 `GlyphRasterFrame` bytes를 만들 수 있는지도 확인하며, 같은 `CTLine`을 CPU bitmap에 그려 non-clear pixel이 생기는지도 확인한다. summary에는 fixed probe 경로의 `renderer_input=coretext_shaped_glyph_run_list`, `renderer_shaper=coretext_shaped_records`, `renderer_rasterizer=coretext_glyph_rasterizer`, `renderer_frame_prepared`, `renderer_surface_cols/rows`, `renderer_glyph_raster_*` 통계와 실제 DrawList 경로의 `drawlist_input=terminal_core_draw_list`, `drawlist_renderer_shaper=coretext_draw_list`, `drawlist_frame_prepared`, `drawlist_surface_cols/rows`, `drawlist_glyph_raster_*` 통계가 함께 남는다. CoreText smoke는 GPU 없이 제품 shaper/rasterizer 준비를 분리 검증하고, Metal smoke는 같은 DrawList shaper 경계를 실제 CAMetalLayer atlas sampling까지 연결한다. 진단 summary는 probe build가 실패해도 항상 먼저 기록한 뒤 종료 코드로 실패를 보고하므로, fixed probe와 DrawList probe의 Zig 실패는 `fixed_probe_error`/`drawlist_probe_error`로 남는다. exit gate는 fixed probe(`shaped_text`, `glyph_rasterized`)뿐 아니라 헤드라인인 실제 DrawList 경로(`drawlist_frame_prepared`, `drawlist_glyph_raster_ready`)까지 포함해, DrawList 프레임이 조용히 unprepared인 채 통과하지 않게 한다. probe record 변환은 `coretext_probe.zig`, 제품 shaper/rasterizer 경계는 `coretext_shaper.zig`와 `coretext_raster.zig` 단위 테스트가 검증한다. native bridge ABI 시그니처는 `coretext_smoke_bridge.zig`가 단일 출처로 선언해 CoreText smoke와 Metal smoke가 공유하고, native ABI 구조체 크기는 각 boundary 모듈의 `@sizeOf` 테스트가 드리프트를 잡는다. 계약 테스트는 `mise run test-macos-coretext-smoke`, 실제 CoreText smoke는 `mise run macos-coretext-smoke`다. 아직 설정 파일/설정 UI/runtime reload는 없으며, native CoreText raster 구현은 아직 smoke bridge에 있다.

`glyph_texture_smoke.zig`와 `glyph_texture_smoke.m`은 첫 CoreText bitmap -> Metal texture upload smoke다. 이 경로는 창을 만들지 않고 CoreText/CoreGraphics가 만든 CPU glyph bitmap을 Metal texture에 업로드한 뒤 blit readback으로 source bitmap과 같은지 확인한다. 계약 테스트는 `mise run test-macos-glyph-texture-smoke`, 실제 texture smoke는 `mise run macos-glyph-texture-smoke`다. 아직 shader sampling이나 실제 화면 glyph draw 검증은 아니다.

`glyph_text_smoke.zig`와 `appkit_glyph_text_smoke.m`은 첫 glyph texture shader sampling smoke다. 이 경로는 실제 AppKit 창과 CAMetalLayer를 만들고, CoreText/CoreGraphics가 만든 CPU glyph bitmap을 Metal texture로 올린 뒤 fragment shader로 샘플링한다. source glyph의 ink 위치를 drawable 좌표로 변환해 blit readback하고, 선택한 모든 샘플이 clear 색이 아니며 배경과 luma가 충분히 대비되고(light/dark theme 모두) `glyph-text-frame.ppm` screenshot artifact가 쓰였을 때만 성공한다. 색은 하드코딩이 아니라 `config.resolveAppearance`로 검증된 값을 쓴다 — `theme.background`는 Metal clear color로, `theme.foreground`는 CoreText glyph fill로 적용하고, readback 예측자도 같은 resolved background를 기준으로 쓴다(`cursor` 색은 resolve해 `applied_cursor`로 기록만 하고 아직 그리지 않는다). 같은 smoke는 Zig 제품 경로의 `RendererState -> RenderFrame/GlyphQuadFrame/GlyphRasterFrame` probe 통계도 남기지만, 이 probe는 아직 실제 CoreText shaper가 아니라 `renderer_shaper=fake_font_backend` 경로이며 raster bytes도 fake rasterizer 계약이다. 계약 테스트는 `mise run test-macos-glyph-text-smoke`, 실제 화면 smoke는 `mise run macos-glyph-text-smoke`다. 아직 제품 terminal renderer, atlas packing, cell-grid text layout 검증은 아니다.
