# 접힘 재사용의 50ms 연타 표시 지연

100ms 결과와 같은 고정 앱에서 접힘 후보 재사용만 끄고 켰다. 여러 줄 함수 3천/5만 개 × 단일/공유 뷰 × 경로별 3프로세스, 총 24프로세스·720키가 검증됐다. 첫 키를 포함하며 반복 순서를 교대한다. 100ms 모집단과 합치지 않는다.

| 함수 수 | 뷰 | 첫 표시 중앙값(ms) | 첫 표시 p95(ms) | 마지막 입력→구문 표시 중앙값(ms) | 다음 입력 전 구문 표시 |
| --- | --- | --- | --- | --- | --- |
| 3000 | 공유 | 32.00 → 34.55 | 42.36 → 47.92 | 33.90 → 35.35 | 77/87 → 81/87 |
| 3000 | 단일 | 30.57 → 31.53 | 41.02 → 43.46 | 38.75 → 36.35 | 77/87 → 85/87 |
| 50000 | 공유 | 34.47 → 37.13 | 44.57 → 46.84 | 156.51 → 93.93 | 0/87 → 0/87 |
| 50000 | 단일 | 32.29 → 33.30 | 45.70 → 42.45 | 140.18 → 67.84 | 0/87 → 0/87 |

표는 재사용 끔 → 켬이다. 첫 표시는 90키의 pooled median/nearest-rank p95, 마지막 구문 표시는 프로세스별 마지막 키 지연 3개의 중앙값이다. 구문 준비와 최종 색 표시는 이번 모집단에서 같은 프레임이었다. 다음 입력 전 표시의 분모는 프로세스별 앞 29키의 합계다.

큰 문서의 입력 종료 후 구문 갱신은 빨라졌지만, 50ms 입력 중 다음 키 이전 구문 표시는 여전히 0/87이다. 첫 글자 표시의 개선은 일관되지 않는다. 작은 공유 뷰의 재사용 켬에서 최대 166.16ms가 관측됐다(끔 최대 53.28ms). 포커스·입력 소스·문서·프레임 검증은 통과했으며 표본을 제거하거나 원인을 확정하지 않는다. 전체 프로세스 peak 최대는 343.45→347.78MiB로, 캐시 할당량이나 통계적 회귀율로 해석하지 않는다.
