# pane 구문 준비와 본문 색 내부 실측

제품 원본은 main `0ca99f728`과 목록의 모든 파일 해시가 같다.
준비·실행 HEAD는 `5d942b10ec3abaa5a50e22bd490e88ccdd59b222`이며, 생성기와 원본/계측 소스·실행 파일·표본·실제 실행 순서를 보존한다.
`setup-1.json`의 원본/계측 목록은 중립 색 변환 소유자까지 19개다. 생성기 사본 `inner-generator.py`도 빌드 전에 고정했다.
제품의 정책·캐시·알고리즘은 변경하지 않는다.

기존 FRAME/PROVIDER/PANE·LOWERING 대조를 유지하고 INNER의 10구간을 별도로 기록했다.
성능 30회·600편집과 별도 정확성 10회·200편집 및 전체 sticky 기준 대조 300뷰를 완료했다.
한 경우의 성능 표본은 첫 편집을 포함한 60개다. 시간 측정이 끝난 뒤 정확성 oracle을 수행한다.

단위는 ms, 각 칸은 **p50 / p95 / 최대**다. 일반은 한 뷰, shared는 두 뷰 합계다.
구간 호출과 비어 있지 않은 조건을 구분하며, 중첩된 부모/자식 또는 다른 구간의 중앙값을 더하지 않는다.
백그라운드 부하는 완전히 통제하지 못했다. 함수 경과시간이며 GUI/HID·present·RSS의 증거는 아니다.

## 독립 검증과 원시 자료

다섯 독립 실패 가설에서 43개 손상을 거절했다. 표본 누락·중복·순서,
각 구간의 잘못된 호출/레이어 조건, 음수·부모 초과·형제 합계 중첩, 형식·target·생성기,
제품/oracle·소스·바이너리·CLI의 다른 모델과 기존 표본 덮어쓰기를 검사했다.
각 묶음 앞뒤 정상 대조와 실제 원본 불변 대조가 유지됐다.

저장소 밖 `pane-syntax-attribution-formal/`에 준비 metadata·생성기·원본/계측 소스·성능/정확성 로그·
실행 파일과 실제 실행 순서를 보존한다. `pane-syntax-formal-review.json`은 세 도구 파일의 해시와
독립 손상 검증을, `production-baseline-proof.json`은 원본이 main과 같은지 기록한다.
초기 단발성 진단 `pane-syntax-inner-probe/`는 별도 보존하며 이 분포에 합치지 않는다.
