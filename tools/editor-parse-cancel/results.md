## 확인 결과

기존 다섯 원문의 해시를 이전 실험과 대조했다. 열 개 독립 프로세스에서 파일별 다섯 반복을 실행했고,
각 반복은 진입 전 취소·진입 후 취소·정상 완료·본문 복사 할당 실패의 네 경우다.
총 **200경우·50개 완성 행**을 수집했으며 빌드 확인 실행과 실패 주입은 제외했다.

- 실제 C progress 콜백이 장벽에 진입했고, 메인이 장벽을 해제하기 전 작업은 끝나지 않았다.
- 진입 전/후 취소는 C 반환 후 트리가 없었고, 취소하지 않은 정상 대조군에는 트리가 생겼다.
- 워커의 본문 복사는 원문 해시와 같았다. 메인이 원본 rope를 편집·종료한 뒤에도 스냅샷 전체 byte는 원문과 같았다.
- 본문 복사의 실제 FailingAllocator 실패에서는 parser 생성과 callback 호출이 모두 없었다.
- 스냅샷은 메인에서 join 이후 해제했고, 워커 본문·Provider는 C 반환 이후 워커에서 해제했다.

별도 실행에서 취소 무시·정상 작업 오취소·본문 변조·실패 allocator 우회·장벽 우회를 주입해
다섯 실제 assertion 실패를 확인했다. 주입 위치는 시험용 어댑터이며 제품 결함 다섯 건을 발견했다는 의미가 아니다.
독립 검증기는 원시 행·완료 개수·callback 최소 호출·결과 JSON·원문/바이너리/제품 사본/계측 패치 해시를
대조했다. 집계 변조·행 변조·행 누락·바이너리 및 fixture identity 손상도 별도 사본에서 거절했다.

## 설계 판단

취소 플래그가 세워졌다고 C 호출의 자원을 즉시 반환해도 되는 것은 아니다. 이 시험의 소유권 순서는
실제 C 반환 이후까지 취소 저장소와 스냅샷을 유지하고, 이후 소유 스레드에서 회수하는 것이다.
콜백은 한 워커만 쓰는 시험용 전역 포인터를 통해 연결했다. 제품 서비스의 작업별 저장소·큐·wake 설계는 별도다.

진입 장벽을 인위적으로 사용했으므로 이 결과에서 취소 지연·콜백 간격·입력 지연을 계산하지 않는다.
실제 premature-free 주입·ASan·race detector·C 내부 malloc 실패·제품 닫기/종료·IME·공유 뷰 검증은 아니다.
실제 서비스가 구현되면 같은 수명 조건을 해당 API로 재검증해야 한다.
