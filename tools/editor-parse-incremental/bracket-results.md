## 측정 결과

각 행·경로는 3프로세스의 60편집을 합친 중앙값/최대다. 정확성 구간은 섞지 않았다.
시간은 메인 서비스 제출 시작부터 완료를 가져오기까지이며 파싱·요약·접힘·괄호를 포함한다.

| 입력 | 전체 준비 중앙/최대 ms | 증분 준비 중앙/최대 ms |
|---|---:|---:|
| 한 줄 함수 3,000개 | 9.30 / 10.40 | 5.92 / 6.58 |
| 한 줄 함수 50,000개 | 172.97 / 191.60 | 116.16 / 130.82 |
| 여러 줄 함수 3,000개 | 9.50 / 10.78 | 6.15 / 6.91 |
| 여러 줄 함수 50,000개 | 175.08 / 197.59 | 121.23 / 135.47 |

성능 24프로세스·480편집과 정확성 8프로세스·160편집이 모두 성공했다. 성능 구간에서도
모든 전체 경로는 rebuilds=1/partials=0, 증분 경로는 rebuilds=0/partials=1이었다.
정확성 구간은 매 편집의 트리 전체 노드와 별도 전체 수집한 잎 배열을 대조했다.
서비스 제출 중앙값은 약 0.019~0.052ms였으며 큰 배열 복사는 워커에서 수행한다.
50,000개 문서는 증분화 후에도 완료 중앙값이 100ms를 넘는다. 화면 지연 문제가 모두
해결됐다고 해석하지 않는다. 배열 복사/위치 보정·색/짝/탐색의 선형 비용도 남는다.

첫 실행 `incremental-bracket-measure-1`은 private 분기 앵커 중복으로 빌드 전 중단했다.
두 번째 실행은 앵커의 들여쓰기를 포함해 위치를 특정한 새 전체 묶음이며, 첫 실행을
성능 자료에 포함하지 않았다. 테스트 최초 컴파일 오류와 수정 로그도 별도 보존한다.

측정 이후 제품 변경은 worker 수명 설명 주석뿐이다. 범위 상한 회귀와 빌드의 기대 테스트
개수는 추가됐으며 측정한 제품 로직과 최종 제품 로직을 구분해 영수증으로 대조한다.

## 검증 근거

worker의 20가지 편집 대조는 이름 변경, 앞/뒤 삽입, 중간 괄호 삽입/삭제, 여는/닫는 괄호
삭제, 주석으로 전환/복원, 문자열로 전환/복원, 한글 NFD·이모지·CRLF, 동일 본문,
CSS 함수 문맥 양방향, JSON 중첩, HTML 규칙, Markdown과 여러 위치의 변경을 포함한다.
매번 이전 원본과 새 결과를 독립 전체 수집에 대조하고 불필요한 전체 재수집 0을 단언한다.

별도 수명/실패 검사는 다음을 확인한다.

- 50편집에서 이전 main 참조를 즉시 반환해도 안전하고, 이전 native 결과는 매 완료 뒤 퇴역한다.
- 다른 서비스의 기준은 native만 복사하며 원본 서비스 종료 뒤에도 안전하다.
- 부분 범위 상한을 넘으면 전체 수집으로 복구하고, 동일 본문은 부분/전체 재수집 없이 재사용한다.
- 부분 수집 도중 취소는 목록을 무효화하고 전체 수집으로 복구한다.
- 복사와 부분 갱신의 모든 Zig 할당 실패는 원본을 보존하고 메모리를 회수한다.
- 기존 worker의 대기 교체·실행 취소·종료·본문 복사 OOM·문서/문법/언어 불일치도 새 코드로 검사한다.

제품 색/짝/탐색·공유 뷰·Undo/Redo·연속 프레임·실제 Apple main queue의 집중 검사는
검증 로그가 소유한다. C allocator 실패 전수 검증이나 실제 OS IME·픽셀 검증으로 확대하지 않는다.
