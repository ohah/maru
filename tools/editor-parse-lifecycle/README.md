# 파싱 결과의 수명 모델

이 도구는 제안한 비동기 파싱 수명을 실행 가능한 상태 모델로 검토한다.
**제품 서비스·C 파서·OS 스레드·allocator가 아니다.** 앞선 실제 Provider 인계 실험과 구분한다.
수락 정책과 참조 반환의 논리 반례를 찾기 위한 것이며 제품 전환 승인을 대신하지 않는다.

```sh
python3 -m unittest discover -s tools/editor-parse-lifecycle -p 'test_*.py' -v
python3 tools/editor-parse-lifecycle/run.py --output /tmp/new-lifecycle-model
```

`--output`은 새로운 저장소 밖 경로다. 코드 사본·SHA-256·기준 Git ID·Python 버전·실제 출력이 보존된다.
표준 라이브러리만 사용한다. 테스트는 도구 전용 opt-in 명령으로 실행한다.

## 모델의 경계

한 문서에 실행 하나·최신 대기 하나를 둔다. 완료와 메인 전달은 별도 사건이므로 늦은 결과 전달을
재현한다. 입력 identity는 owner·slot·generation·revision·grammar·serial을 모두 요구한다.
번호는 모델에서 재사용을 거절한다. 실제 정수 폭·고갈 정책·원자성·락은 구현하지 않는다.

본문 판 갱신은 작업 준비 성공과 분리한다. 준비 실패는 큐가 생기지 않은 사건으로만 모델링하며
실제 OOM 주입은 아니다. 취소는 실행 작업을 즉시 해제하지 않는다. 완료 뒤 스냅샷을 메인에서 반환하고,
트리는 소비 뷰가 모두 반환된 뒤 별도 퇴역 단계에서 회수한다. 트리 없는 실패 완료도 구분한다.
전체 문서 닫기와 뷰 하나의 반환은 별도 연산이다.

## 확인 결과

테스트 메서드 9개가 통과했다. 단일 워커 제약에 맞는 사건 순서 9개 × 닫기 시점 8개를 조합한
72경로에서 사건마다 불변식을 검사하고, 마지막 drain에서 모든 스냅샷이 한 번, 생성된 트리가 한 번
회수됐는지 확인했다. 닫기 시점은 사건 사이 여섯 곳·모든 사건 뒤·닫지 않음이다.
슬롯 재사용·정상 수락·대기 교체·실패 완료·중복 전달·중복 퇴역은 별도 대조한다.

문서 generation 누락·요청 serial 누락·준비 실패 시 옛 판 유지·닫기 즉시 실행 스냅샷 해제·
독자가 있는 트리 해제를 각각 활성화하면 정상 대조군과 달리 assertion이 실패한다.
이것은 모델에 주입한 다섯 결함의 탐지이며 실제 제품 결함 다섯 건을 발견했다는 뜻이 아니다.

초기 테스트 수집기의 lambda 기본 인자와 사건 수 예상값을 수정했으며 이 오류를 의미적 결함 탐지로 세지 않았다.
