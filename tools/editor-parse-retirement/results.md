## 판단

원본 참조를 메인에서 먼저 놓고 독립 Provider의 마지막 참조를 워커에서 해제할 수 있었다.
파싱뿐 아니라 마지막 해제도 메인에서 분리할 수 있는 API 경계의 근거다.
해제 작업 자체가 빨라졌다는 결과가 아니며, join을 포함하는 실험이므로 실제 UI 지연 개선을 증명하지 않는다.

제품은 공유 뷰·summary·cursor가 별도 트리 참조를 가질 수 있다. 세대별 보유 참조와 반환 확인 없이
이 순서를 그대로 적용하면 마지막 해제가 메인에 남을 수 있다. 메인에서 트리를 편집하면 별도 노드도 생기므로
단순 복사 하나로 모든 해제를 보호한다고 가정하지 않는다. 큰 해제를 처리하는 동안 단일 워커의 다른 파싱이
늦어질 수 있다. 우선순위·메모리 상한·추가 스레드는 아직 결정하지 않았다.

## 확인 범위와 실패 주입

원본 종료 뒤 복사본의 root 종류·끝 byte, 실제 실행 thread ID, 해제 완료 표시를 확인했다.
전체 트리 비교나 제품 revision 수락·취소·닫기·종료·OOM·IME 검증은 이 실험에 포함하지 않는다.
트리 좌표 변조, 잘못된 예상 좌표, 다른 Provider, 메인 실행, 해제 누락을 각각 주입해 assertion으로 거절했다.
독립 verifier는 바이너리·fixture·제품 사본·계측 패치·원시 300행·집계를 대조했다.
집계·행·표본 누락·바이너리 및 fixture identity 손상도 별도 사본에서 거절했다.

초기 parse-retirement-1의 다른 Provider 주입은 빈 문서의 null tree를 가정 없이 읽어 비정상 종료했다.
null tree 가드와 비어 있지 않은 다른 Provider 대조군으로 수정했다. 초기 실행은 assertion 검증이나 성능 표본으로
채택하지 않았다. 최종 다섯 오류는 모두 실제 assertion 실패를 확인했다.
