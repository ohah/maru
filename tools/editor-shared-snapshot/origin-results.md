# 유효한 계보가 있는 공유 분할의 첫 입력

원본에서 삽입·Undo 후 본문이 원문과 같고 입력·복사 계보가 유효한 상태를 만든다.
이 준비 시간은 따로 기록하고, 분할 명령·두 뷰 준비·첫 입력을 모두 측정한다.
한 번도 증명을 확보하지 않은 cold open의 결과가 아니며 실제 HID·GPU present·RSS도 측정하지 않는다.
`flat-50000.zig`는 50,000개 함수·200,000개 LF인 고정 입력이다.

## 표본과 대조

성능 30개 프로세스/600편집과 별도 정확성 10개/200편집을 실행했다. 조건별 성능 표본은
사본마다 3회이며 첫 입력도 포함한다. 전후 순서를 교대했고, 모든 입력의 부모/자식 시간과
전체 접힘 결과가 일치했다. 분할 준비 중 native 파싱 계측시간은 두 사본 모두 0ns였다.

첫 입력의 C 범위 계산은 전 2회·후 1회, 재사용은 전 0회·후 1회였다.
이후 19개 입력은 두 사본 모두 계산 1회·재사용 1회였다. 원본의 증명 부재·잘못된 parser·
오래된 계보·pending·선택적 할당 실패와 독립 소유는 별도 제품 검사로 대조한다.

아래 준비+첫 입력은 각 실행에서 직접 합한 값의 분포다. 별도 구간의 중앙값을 더하지 않는다.
단위는 ms이며 p95는 표본 3개의 최댓값이다. 작은 차이를 보편적 개선·퇴보로 확정하지 않는다.

## 자료 보존과 재검증

원시 자료는 저장소 밖 `/Users/yoonhb/.cache/maru-agent-artifacts/split-origin-measure-3`에 있다.
실행파일은 `.zig-cache` 밖에 보관하고 각 실행 전후 해시를 대조했다. 저장소 밖 경로는
GitHub 공개 artifact가 아니다. 실행 순서·입력·소스·빌드·바이너리 해시와 전체 로그를 보존한다.
40개 로그를 다시 읽어 검증했고, 첫 입력의 계보/프레임 누락·잘못된 첫 호출 수·원본 준비
증명 부재·잘못된 준비 구간 파싱 계측값의 다섯 손상을 거절했다. 정상 전후 대조도 통과했다.

앞선 `split-origin-measure-2`도 따로 보존한다. 그 실행 뒤 캐시 경로의 바이너리가 없어졌고
같은 소스를 재빌드한 실행파일의 해시가 달라 현재 바이너리로 이전 표본을 재검증할 수 없었다.
따라서 이전 로그를 새 실행파일의 표본으로 취급하지 않고, 새 바이너리로 전 표본을 다시 실행한
3번 자료를 이 표의 근거로 삼는다. 이전의 작은 Zig 준비+첫 입력 16.784→16.858ms 표본도
삭제하지 않았다. 캐시가 사라진 원인은 확인하지 않았다.
