# 일반 본문 색 조회의 전후 실측

이 표는 `078a8dcef`로 리베이스하기 전에 수집한 실측이다. 기준은 당시 실제 메인
`711591ffa`이며 수정본은 측정 당시 작업 트리의 소스 해시로 고정했다.
리베이스에서 본문 색 조회·화면 예산 코드가 그대로임을 대조했지만, 새 main의 검색 IME 변경을
포함한 전체 시간은 이 표로 측정하지 않았다. 리베이스 후 동작·시각 검증은 구현 계획에서 구분한다.
옛 자료의 시간을 빼지 않고 동일한 다섯 입력으로 두 버전을 새로 실행했다.
입력 파일의 bytes·SHA, 원본/계측 소스·도구·실행 파일·원시 로그를 함께 보존했다.

각 입력·뷰 조합은 성능 3프로세스×20입력이다. 별도 정확성 1프로세스×20입력을 더해
두 버전 합계 80프로세스, 성능 1,200입력과 정확성 400입력을 확인했다.
두 버전을 같은 입력 옆에 배치하고 반복별 순서를 바꿨다. 프로세스마다 첫 입력도 보존했다.
정확성 실행은 매 입력·각 실제 뷰의 표시 색을 남은 원문 전체 조회와 값으로 대조한다.
이 대조는 측정 구간 밖에서 수행하며 성능 실행의 중간 입력에는 넣지 않는다.
성능 실행도 마지막 표시 색을 별도로 대조한다. 같은 문법 알고리즘의 범위 대조이며
외부 문법/에디터의 독립 색상 정답과 같다는 뜻은 아니다.

## 색 구간과 첫 입력

색 시간은 `syntaxColors`의 포함 시간이며 공유 2뷰에서는 두 호출의 합이다.
첫 입력 p50은 프로세스별 첫 입력 3개의 중앙값이다.

| 입력·뷰 | 색 p50 전 | 색 p50 후 | 첫 입력 p50 전 | 첫 입력 p50 후 |
|---|---:|---:|---:|---:|
| Zig 15,000 · 단일 뷰 | 0.396 | 0.059 | 10.682 | 10.241 |
| Zig 15,000 · 공유 2뷰 | 0.794 | 0.125 | 13.817 | 13.357 |
| Zig 3,000 · 단일 뷰 | 0.394 | 0.058 | 2.631 | 2.338 |
| Zig 3,000 · 공유 2뷰 | 0.786 | 0.117 | 3.281 | 2.598 |
| Zig 50,000 · 단일 뷰 | 0.398 | 0.062 | 33.535 | 31.449 |
| Zig 50,000 · 공유 2뷰 | 0.807 | 0.130 | 45.390 | 45.709 |
| 실제 build.zig · 단일 뷰 | 1.516 | 0.168 | 8.404 | 7.132 |
| 실제 build.zig · 공유 2뷰 | 2.968 | 0.321 | 10.071 | 7.201 |
| 실제 Swift 호스트 · 단일 뷰 | 1.726 | 0.744 | 8.619 | 7.444 |
| 실제 Swift 호스트 · 공유 2뷰 | 3.444 | 1.433 | 11.876 | 9.830 |

중앙값은 이 표본에서 감소했지만 모든 입력·꼬리에서 개선됐다는 뜻은 아니다.
Zig 50,000 공유의 첫 입력 중앙값은 45.390→45.709ms였고, Zig 15,000 공유의
전체 최대값은 14.079→14.085ms였다. 다른 작업 부하·CPU 주파수는 통제하지 않았다.
각 원시 입력의 시간·호출 수와 모든 구간의 p50/p95/최대·첫 입력을 별도 계산으로 대조했다.
큰 화면은 이전에 빠지던 색을 더 계산하므로 이 작은 화면의 비용 감소로 일반화하지 않는다.
GUI/HID·실제 present·사용자의 물리 입력 지연·RSS 개선을 측정한 결과가 아니다.

## 근거와 재생

자료 루트는 저장소 밖 `visible-color-window-paired-1`이다. `result.json`,
`repository-source.json`, 두 버전의 `all-source.json`, `original-product/`,
`setup-1.json`, `binaries.json`, `archived-test`, 입력·원시 로그와 도구 사본을 남겼다.
`independent-readback.json`은 원시 기록에서 모든 구간 통계·첫 입력·호출 수를 다시 계산했다.
측정 스크립트와 정확성 hook은 부모 디렉터리의 `measure-visible-color-window-pair.py`와
`visible-color-window-measure-oracle.zig.inc`다. 기존 `tools/editor-provider-measure/`의
사본 준비·계측·판정기를 사용하며 임시 사본에 표시 색 대조만 추가했다.

[구현·검증 계획](../../docs/plans/editor-visible-color-window.md)은 제품 범위와 시각 검증을 구분한다.
